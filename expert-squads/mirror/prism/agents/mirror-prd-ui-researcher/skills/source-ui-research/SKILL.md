# Source UI research

- Read `references/ui-audit-contract.md` before observation and use its evidence and output structure.
- Run once for the Task. Start from the canonical system-project contract and its exact `subsystem_closure`, plus every applicable delivery-plan entry, including complete surface sets, closure reasons, exact member routes, material journeys, and existing evidence anchors. Do not rediscover Task-wide route scope.
- Observe the real member routes, viewport, theme, desktop behavior, and required interaction states in one browser-owned evidence pass.
- Observe hierarchy, capability grouping, data density, component families, states, motion, focus, accessibility, performance, and design-system consistency as product facts.
- Execute every material journey across all associated subpages and record navigation, shared data/state continuity, feedback, deep-link and return behavior, recovery, keyboard/focus path, and outcome.
- Record exact product asset candidates with route/region, source URL or inline reference, trigger state, media type, reuse relationship, rights evidence, and acquisition limitation. Do not materialize candidate product bytes.
- Capture real Browser screenshots for every closure-critical member route and material state. Put the exact returned `/attachment/...` URL in the matching evidence-index pointer; the Host publishes those observed screenshot bytes as immutable FrontendResearchBrief Artifact resources after the Turn.
- Bind every finding to a screenshot, diagnostic, or extracted value with confidence and limitations.
- Treat screenshots, regions, layout measurements, computed styles, and geometry as observation context only. They never become Prism visual-parity or source-to-render authority.
- Document what exists; do not design, generate, or invent a replacement interface.
- Save one Task-wide evidence packet containing every assigned surface and its exact delivery-plan entries under `.mirror/prd/tmp/`.

This contract distills `prism-team/design-ui-researcher.md`.
