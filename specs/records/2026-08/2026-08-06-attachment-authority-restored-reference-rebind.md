## Live evidence and causal chain

1. The managed server at `127.0.0.1:7878` reports healthy version `0.0.32-beta` and the current Database at `%LOCALAPPDATA%/opencorvus/data/opencorvus.db`.
2. The live log records two real `POST /attachment` requests returning HTTP 500 with `AttachmentStoreAuthorityError`; the failure is after Composer byte capture, Project resolution, transport, route validation, and request-body delivery.
3. The Project store marker names Database instance `5884f316-a946-443b-b118-ceacce01eca7`, while the current Database names `465f569f-29e8-4bdd-8cad-00745b06c36b`. The explicit product-pillar schema recovery created the expected replacement Database identity.
4. `claimAuthority` already allows a markerless non-empty store when every blob SHA-256 (Secure Hash Algorithm 256-bit) digest is present in the current Database retain set, matching the architecture contract.
5. The existing-marker mismatch branch does not apply that same ownership proof: it rejects every non-empty store before consulting `collectReferencedShas`. This contradicts `02-data.md`, which permits an existing store to be claimed when every blob is referenced by the current Database.
6. Because file, image, and directory-reference writes all call `AttachmentStore.write`, the one inconsistent authority branch disables all three upload forms together.

## Implementation plan

1. Extract one strict helper that accepts an empty store or proves every on-disk blob appears in the current Database's canonical retain set; otherwise throw the existing typed ownership error.
2. Invoke that helper for both markerless first claim and existing-marker identity replacement, then use the existing cross-process lease and atomic writer to publish the new authority.
3. Replace the outdated non-empty foreign rejection test with a positive recovery contract: write under the first Database, rebuild the isolated test Database, restore the canonical reference, claim under the replacement identity, and write a new attachment without changing the old bytes.
4. Run focused storage/server/Overlay non-UI contracts, OpenCorvus typecheck, documentation health, and diff checks.
5. Build an isolated source server and exercise real binary and directory-reference requests against an isolated recovered Database/store. Do not restart or refresh the operator's running client.
