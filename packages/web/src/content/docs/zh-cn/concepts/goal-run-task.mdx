所有表定义集中在 `packages/opencorvus/src/orchestrator/orchestrator.sql.ts`。

## 概念关系

```
Task (kind: "workflow" | "build")
 ├─ Run (phase: plan | execute | evaluate | deliver)
 │   ├─ PlanVersion (version 1, 2, ...)
 │   │   └─ Goal[] (深度分解的目标)
 │   └─ GoalRun[] (每次 Goal 被执行均 1 条)
 │       └─ Evaluation (verdict: accepted | rejected | inconclusive)
 └─ Acceptance (status: candidate → publishing → delivered)
SpecSnapshot (独立，被 PlanVersion 引用)
```

## 各实体速览

### Task（`orchestrator.sql.ts:113`）

| 字段 | 说明 |
|---|---|
| `kind` | `"workflow"`（完整 pipeline）或 `"build"`（仅编译/构建型任务） |
| `status` | `pending / running / done / failed / canceled` |
| `active_run_id` | 当前活跃的 Run |
| `active_plan_version_id` | 当前活跃的 PlanVersion |
| `budget` | 总预算（runs / goals / tokens 维度） |

一个 Task 可能经历多个 Run。每次 replan 产生新的 PlanVersion，旧的置 `superseded`。

### Run（`orchestrator.sql.ts:332`）

Run 是 Task 的一次完整执行尝试，phase 按 `plan → execute → evaluate → deliver` 推进。

### PlanVersion（`orchestrator.sql.ts:161`）

- `version`：递增序号
- `summary`：人类可读的本版计划摘要
- `spec_snapshot_id`：关联当时的规格快照
- 每次 replan 生成新版

### Goal（`orchestrator.sql.ts:205`）

Goal 是最小可并行、可独立验收的实现单元。

| 字段 | 说明 |
|---|---|
| `title` / `objective` | 目标名与叙述 |
| `done_definition` | 验收标准（可含可执行命令：`pnpm test`、`cargo build` 等） |
| `owned_paths[]` | 本 Goal 负责的代码路径 |
| `depends_on[]` | 前置 Goal（拓扑排序依据） |
| `exports[]` / `imports[]` | Goal 间数据契约 |

### GoalRun（`orchestrator.sql.ts:359`）

| 字段 | 说明 |
|---|---|
| `status` | `queued → planning → running → evaluating → completed / failed` |
| `workspace_dir` | Git worktree 路径（每个 Goal 独立） |
| `base_ref` / `merge_ref` | 分支起点 / 合并点 |

同一 Goal 可能因重试产生多个 GoalRun。

### Evaluation（`orchestrator.sql.ts:467`）

| 字段 | 说明 |
|---|---|
| `verdict` | `accepted / rejected / inconclusive` |
| `checks[]` | build/test/lint/spec_check 等各检查的结果 |

`inconclusive` 语义为"无法判决"——不是通过也不是失败，触发 replan 而非 retry。

### Acceptance（`orchestrator.sql.ts:423`）

- `candidate`：评估通过，等待交付
- `publishing`：正在合并/推送
- `delivered`：已交付

### SpecSnapshot（`orchestrator.sql.ts:36`）

由 Spec Agent 产出：

| 字段 | 说明 |
|---|---|
| `summary` | 一句话规格 |
| `content` | 完整规格（Markdown） |
| `scope` | 涉及的文件/模块范围 |
| `evidence[]` | 产出规格所依据的代码证据链 |

## GoalContract 运行时契约

`GoalContract`（`src/pipeline/types.ts:60`）是 Pipeline 的唯一入参，一经创建**不可变**：

```typescript
interface GoalContract {
  goal: Goal
  planNode: PlanStep
  run: Run
  task: Task
  plan: PlanVersion
  allGoals: Goal[]  // 用于跨 Goal 依赖查询
}
```

它保证执行某个 Goal 时拿到的是快照，不会被并发修改污染。

## 状态持久化

所有状态存 SQLite（默认 `~/.opencorvus/opencorvus.db`），支持跨进程/跨会话恢复。Server 重启后，overlay 只恢复任务上下文，编排器必须等下一条真实用户消息才继续。
