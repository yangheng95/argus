The benchmark harness provides **end-to-end quality regression**. It simulates a real request from creation to acceptance and emits `qualityVerdict` (accepted / rejected / blocked) as the pass signal. Only `accepted` is a passing verdict.

## Main script

`packages/opencorvus/script/benchmark/overlay-web-benchmark.ts`

## Minimal run

```bash
cd packages/opencorvus

DASHSCOPE_API_KEY=sk-... \
ALIBABA_CODING_PLAN_API_KEY=sk-sp-... \
bun run script/benchmark/overlay-web-benchmark.ts \
  "--request-file=/path/to/prd.txt" \
  "--acceptance-verify-cmd=bun test" \
  "--idle-timeout-ms=2700000"
```

**Note**: flags support both `--name=value` and `--name value`; quote paths that contain spaces.
The benchmark task brief is explicit input: provide either `--request-file` or `--request-attachment`.
The benchmark requires either `--acceptance-verify-cmd` or `--reference-images`; without one, startup fails before task creation. When using `--reference-images`, also provide `--threshold`, `--worst-threshold`, `--browser-launch-timeout-ms`, `--navigation-timeout-ms`, and `--settle-ms`.

## Key flags

| flag                                        | purpose                                                                  |
| ------------------------------------------- | ------------------------------------------------------------------------ |
| `--request-file=PATH`                       | task description file (PRD)                                              |
| `--request-attachment=PATH`                 | attach a request file instead of reading task text from `--request-file` |
| `--reference-images=PATHS`                  | comma-separated visual reference images                                  |
| `--acceptance-verify-cmd=CMD`               | explicit local acceptance verification command                           |
| `--threshold=NUMBER`                        | required SSIM threshold when `--reference-images` drives verification     |
| `--worst-threshold=NUMBER`                  | required worst-window threshold for reference-image verification          |
| `--browser-launch-timeout-ms=NUMBER`        | required browser launch timeout for reference-image verification          |
| `--navigation-timeout-ms=NUMBER`            | required page navigation inactivity timeout for reference-image verification |
| `--settle-ms=NUMBER`                        | required post-load settle delay for reference-image verification          |
| `--executor=opencorvus\|codex\|claude-code` | executor: OpenCorvus / Codex / Claude Code                               |
| `--title=TITLE`                             | task title                                                               |
| `--report=PATH`                             | output JSON report                                                       |
| `--max-runs=N`                              | maximum runs                                                             |
| `--max-fix-runs=N`                          | maximum repair runs                                                      |
| `--max-executor-groups=N`                   | maximum parallel executor groups                                         |
| `--idle-timeout-ms=MS`                      | benchmark **inactivity timeout**                                         |
| `--resume-task-id=ID`                       | resume an existing benchmark task                                        |
| `--resume-home-dir=PATH`                    | OpenCorvus home directory from the original run                          |
| `--resume-message=TEXT`                     | message injected when resuming                                           |
| `--figma-url=URL`                           | Figma URL for tasks that use Figma input                                 |
| `--no-keep`                                 | delete tmp directory on finish                                           |
| `--stop-after-architect`                    | stop after architect output                                              |

## Env injection upfront

`Env.state()` snapshots `process.env` on instance creation; late-loaded `.env` values are missed. That's why benchmark commands inject env explicitly.

## Pass criteria

Report JSON:

```json
{
  "qualityVerdict": "accepted",
  "localVerify": { "exitCode": 0 },
  "required_check_pass_rate": 1.0
}
```

Source: `packages/opencorvus/script/benchmark/quality-checks.ts`.

## Timeout semantics

All timeouts are **inactivity timeouts**. As long as stdout/stderr/SSE is flowing, the stall timer resets. Long build/test runs are fine; truly hung tasks surface quickly. **Do not** read them as wall-clock timeouts.

## Baseline reference

Historical baseline:

- glm-5 (2026-03-09): 90% avg, 5/5 pass, 174-254s per task
- E1:254s, E2:215s, E3:174s, E4:173s, E5:193s

## Report structure

`--report` JSON contains:

- Task metadata (title, model, executor)
- Per-stage/tool duration for orchestrator workflow steps, goal runs, review, local verification, and quality evidence checks
- Per-goal check results
- `qualityVerdict` and `localVerify`
- Failure samples: stdout/stderr tails + artifact paths

## CI usage

```yaml
- name: Benchmark
  env:
    DASHSCOPE_API_KEY: ${{ secrets.DASHSCOPE_API_KEY }}
  run: |
    cd packages/opencorvus
    bun run script/benchmark/overlay-web-benchmark.ts \
      "--request-file=benchmarks/smoke.txt" \
      "--acceptance-verify-cmd=bun test" \
      "--report=report.json"
```

## Targeted local probes

Use the maintained scripts under `packages/opencorvus/script/benchmark/` for focused checks, for example `html-skeleton-workflow-check.ts`, `visual-diff.ts`, and `review-deliverable.ts`. `html-skeleton-workflow-check.ts` and `visual-diff.ts` require `--threshold`, `--worst-threshold`, `--browser-launch-timeout-ms`, `--navigation-timeout-ms`, and `--settle-ms`; other probes document their own flags at the top of the script.
