## Causal chain

1. **Observable:** every desktop platform currently receives the same opaque `--rail-surface`; `.sidebar` explicitly disables backdrop filtering, so the left Dock cannot express either native macOS translucency or Windows/Linux contrasting glass.
2. **Direct trigger:** the build target exists only as a JavaScript compile constant and is not exposed as a general document material fact. The only platform projection is the macOS/Tauri native-titlebar attribute.
3. **Deep cause:** platform chrome ownership was previously solved for window controls, but rail material remained theme-only. Applying Tauri/window-level vibrancy would cross the component boundary and blur the entire application, while image textures or animated filters would add resource cost without improving platform semantics.
4. **Root repair:** project the compile target once on `<html>`, define the platform material contract beside the single Dock owner, and use one static compositor layer with platform-specific tint/blur budgets plus the operating-system reduced-transparency preference.

## Outcome

- The Vite compile target is now projected once as `data-platform` on the document root. The left Dock consumes that fact directly; no user-agent parsing, host guessing, or second platform store exists.
- macOS uses one quiet theme-derived translucent layer with a 6-pixel scaled blur and 108% saturation. Windows and Linux share one contrasting blue/warm/green static gradient language with a bounded 16-pixel scaled blur and 138% saturation. The inner Dock content is transparent, so there is no duplicate material owner.
- `prefers-reduced-transparency: reduce` switches the same Dock owner to the opaque rail palette and disables both standard and WebKit backdrop filters. No image asset, canvas, timer, JavaScript animation, permanent compositing hint, or whole-window native vibrancy was added.
- Focused source tests, all Overlay unit tests, TypeScript, panel internationalization, the production Vite build, shell/theme continuity tests, and the Node-launched material browser test passed. The production build retained only its existing large-chunk warning.
- Six 1240-by-820 task-scoped screenshots under `packages/overlay/.scratch/left-dock-platform-material/` were inspected at original resolution: macOS light/dark remained quiet and crisp; Windows/Linux light/dark showed the intended blue-to-mint/warm contrast without dirty seams, clipped rows, or unreadable selected states.
- The actual production bundle was also opened in the controlled in-app browser at the current macOS compile target. The rendered 280-by-636 Dock reported `blur(6px) saturate(1.08)`, an 84%-tinted material color, the expected static highlight gradient, and a clean handoff into the opaque rounded workspace. The isolated preview server and tab were closed after inspection; the user's running Overlay was not touched.
