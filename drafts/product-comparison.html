架构对比：编码助手 vs opencorvus

讨论用 · 结构示意（非完整实现细节）
两者的结构
编码助手
Claude Code · Codex · Cursor — 单 agent
你 / User
在对话里全程驱动
↕同步对话
Agent（单个 LLM + 工具）
LLM 决策→ 调用工具→ 回填结果→ 下一轮 ↺ 循环，直到模型认为可以回复
工具：read edit bash grep …
· 一个上下文窗口，承载全部任务
· 没有外部验收；模型停下 = 任务结束
· 会话结束即遗忘，无跨会话状态
opencorvus
Orchestrator + 专职 sub-agent + 执行器 — 多 agent（两层循环）
你 / User
下达任务，只在权限 / 反馈节点介入
↓
Orchestrator（唯一决策者）
读全量状态 → 决定：调哪个 agent / 重试 / 交付 / 终止
↓按需调用
意图分析 需求 架构 设计分析 构建 完整性复核 交付
每个 sub-agent 自带 LLM + 工具，独立推理；其中「构建」在隔离工作区启动执行器 ↓
Executor（worktree 隔离 · 外部进程）
claude-code / codex / 自有内核 —— 跑的就是左边那套单 agent 循环
↓产出 diff
Delivery 验收门
确定性检查（build / test / lint / 视觉）+ LLM 复核 → 通过才算交付
↺不通过 → 回到 Orchestrator 重试 / 重规划
全程状态落 SQLite：任务 / 计划 / 执行 / 交付 / 记忆——可崩溃恢复、可审计、跨会话复用
关键关系：编码助手是 opencorvus 的内层

同一个「单 agent 循环」，
在 opencorvus 里只是一个执行器

左侧编码助手的整套对话循环，对应右侧的 Executor 一格。

opencorvus 没有取代它，而是在它外面套了一层：用 Orchestrator 决策、用专职 agent 分工、用验收门判定完成、用 SQLite 保存状态。

所以二者不是同一层的竞品——一个是工具，一个是调度工具的外壳。opencorvus 可以直接调度 Codex / Claude Code 当执行器。

opencorvus 外层 ─ 编排 / 验收 / 持久化
编码助手（单 agent 循环）= Executor 内层
外层负责「定规格 · 分目标 · 卡验收 · 保状态」，内层负责「动手写代码」
结构性差异
维度编码助手opencorvus
智能结构单 agent，单上下文窗口多 agent 分工，各自独立 LLM + 工具
控制循环一层：LLM ↔ 工具两层：外层 Orchestrator 决策 + 内层执行器循环
完成判定模型停下即结束验收门通过才算交付，不过则重试 / 重规划
状态会话内，结束即遗忘SQLite 持久化，可恢复 / 审计 / 跨会话
隔离与并行单线程对话，共享工作区多目标并行，各自独立 git worktree
