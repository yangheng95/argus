# Mirror Prism

`mirror/prism` is a self-contained fixed-profile AInvest subsystem-convergence Expert Squad. It observes any authorized reference product, derives the evidence-backed complete subsystem closure, maps the relevant capabilities into the package-owned AInvest product and design authority, then performs ordinary non-Goal planning, Product Requirements Document production, original AInvest rendered design, implementation, and independent MirrorTest acceptance in one Task.

Prism does not clone, replicate, port, restore, or perform screenshot/reference parity. The dedicated Frontend Replica Expert Squad owns that delivery. Prism always dispatches its designer with `frontend_design mode=greenfield_original`. Reference evidence informs product structure, data, behavior, accessibility, and explicit adopt/defer/reject decisions; the mapper's cited AInvest Artifact is the sole product/design authority and reference evidence never becomes visual-comparison authority.

## Workflows

- `mirror-prism-ainvest`: reference-product observation → source-system research → AInvest mapper → Planner → surface research/assets → Product Requirements Documents → original AInvest design → code → MirrorTest.

Every declared node runs once for the whole Task. Route count and subsystem membership come from acquired evidence. One supplied URL is a discovery entry, not a quota or a single-page delivery boundary. The closure contains every associated subpage, shared capability, cross-route state, navigation edge, and end-to-end journey required to make the evidenced business capability complete. A page is only an internal work unit; acceptance is always joint across the closure.

## Planning

Prism has no Requirements or Architect projected Agent and does not create RequirementSet, ContractGraph, Goal, Delivery Slice, phase Task, or workflow state. `mirror-prd-stage-planner` is an ordinary Delegated Worker. It selects the canonical reference-system contract plus mapper authority and publishes exactly one `prism/delivery-plan` Artifact containing the complete subsystem closure, all accepted surfaces/routes, shared owners, member dependencies, navigation/state assembly, execution order, safe internal parallel frontiers, and joint acceptance evidence.

Downstream workers enumerate the Task catalog, completely read the plan and declared predecessor Artifacts, and call `artifact_select` for every semantic source. Dispatch messages and visible final narration never transport Artifact bodies.

## Session continuity

A worker repair continues in its existing Session. If a live runtime owns the Session, Agent-to-Agent coordination appends the repair message and continues in place. If the prior Turn/runtime has ended, `dispatch_agent` uses `turn.kind=continuation`, `turn.authority.kind=prior_dispatch`, and the exact `turn.authority.continuation_dispatch_id` to reopen the same Session for a new Turn. A Session identity is never terminal and is not replaced for retry, replan, provider/process recovery, or downstream repair.

## Evidence and acceptance

The general researcher's terminal FrontendResearchBrief Artifact is the immutable reference-system contract. Turn-local authoring files are not downstream sources. The delivery plan classifies reference observations, competitor inspiration, and AInvest product/design authority separately and fixes the design adapter mode to `greenfield_original`. The mandatory mapper is the only publisher of the cited per-Task AInvest authority.

Product Requirements Document, design, implementation, integration, positive non-User-Interface tests, integrity review, and live visual review preserve the exact subsystem closure, every accepted surface/route identity, shared shell/data/state/navigation contract, material journey, product evidence, limitation, and reference-product functional/content boundary while enforcing the single AInvest visual identity. Visual review starts the real assembled subsystem, traverses every business-required associated subpage and material journey, and personally inspects current screenshots for each critical surface/state without User Interface automation. Missing members, placeholder destinations, disconnected navigation, state discontinuity, or a route that only works in isolation are incomplete delivery evidence.

MirrorTest classifies product defects with reproducible evidence and does not edit product source. Task completion remains an Orchestrator judgment over the complete selected workflow evidence.
