Benchmark 体系用于**端到端质量回归**。它模拟一次真实任务请求，从创建到交付全流程跑完，给出 `qualityVerdict`（accepted / rejected）作为通过判据。

## 主脚本

`packages/opencorvus/script/benchmark/overlay-web-benchmark.ts`

## 最小运行示例

```bash
cd packages/opencorvus

DASHSCOPE_API_KEY=sk-... \
ALIBABA_CODING_PLAN_API_KEY=sk-sp-... \
bun run script/benchmark/overlay-web-benchmark.ts \
  "--request-file=D:/path/to/prd.txt" \
  "--idle-timeout-ms=2700000"
```

**注意**：flag 支持 `--name=value` 和 `--name value`；路径中有空格时必须加引号。

## 关键 flag

| flag                                        | 说明                                                 |
| ------------------------------------------- | ---------------------------------------------------- |
| `--request-file=PATH`                       | 任务描述文件（PRD）                                  |
| `--request-attachment=PATH`                 | 附加请求文件，而不是从 `--request-file` 读取任务文本 |
| `--reference-images=PATHS`                  | 逗号分隔的视觉参考图                                 |
| `--acceptance-verify-cmd=CMD`               | 显式本地验收验证命令                                 |
| `--executor=opencorvus\|codex\|claude-code` | 执行器：OpenCorvus / Codex / Claude Code             |
| `--title=TITLE`                             | 任务标题                                             |
| `--report=PATH`                             | 输出报告 JSON                                        |
| `--max-runs=N`                              | 最大 Run 次数                                        |
| `--max-fix-runs=N`                          | 最大修复 Run 次数                                    |
| `--max-executor-groups=N`                   | 最大并行 executor group 数                           |
| `--idle-timeout-ms=MS`                      | benchmark **无活动超时**                             |
| `--resume-task-id=ID`                       | 续跑已有 benchmark task                              |
| `--resume-home-dir=PATH`                    | 原始运行的 OpenCorvus home 目录                      |
| `--resume-message=TEXT`                     | 续跑时注入的消息                                     |
| `--figma-url=URL`                           | 使用 Figma 输入的任务 URL                            |
| `--no-keep`                                 | 任务结束删除临时目录                                 |
| `--stop-after-architect`                    | architect 输出后停止                                 |

## Env 显式注入

Env 必须在**进程启动前**就绪。`Env.state()` 在实例创建时快照 `process.env`，`.env` 后期注入会失效。因此上例中所有 key 都通过 `VAR=val cmd` 显式传入。

## 通过判据

报告 JSON 中：

```json
{
  "qualityVerdict": "accepted",
  "localVerify": { "exitCode": 0 },
  "required_check_pass_rate": 1.0
}
```

判据源码：`packages/opencorvus/script/benchmark/quality-gates.ts`。

## 超时语义

所有超时都是**无活动超时**——只要 stdout/stderr/SSE 事件流还在流，就不算 stall。这样跑长 build/test 不会被机械切断，而真正挂住的任务会及时暴露。**不要**把超时理解为"从启动时刻起的总时长"。

## Baseline 参考

历史 baseline（供对比）：

- glm-5（2026-03-09）：avg 90%，5/5 pass，单任务 174~254s
- E1:254s, E2:215s, E3:174s, E4:173s, E5:193s

## 报告结构

`--report` 产出的 JSON 包含：

- 任务元信息（title、model、executor）
- orchestrator workflow steps、goal runs、review、本地验证与 quality gates 的耗时
- 每个 Goal 的 check 结果
- `qualityVerdict` 与 `localVerify`
- 失败样本：stderr / stdout 尾部 + 相关 artifact 路径

## 在 CI 中运行

在 GitHub Actions 里：

```yaml
- name: Benchmark
  env:
    DASHSCOPE_API_KEY: ${{ secrets.DASHSCOPE_API_KEY }}
  run: |
    cd packages/opencorvus
    bun run script/benchmark/overlay-web-benchmark.ts \
      "--request-file=benchmarks/smoke.txt" \
      "--report=report.json"
```

## 本地定向探针

更小粒度的检查使用 `packages/opencorvus/script/benchmark/` 下维护中的脚本，例如 `html-skeleton-workflow-check.ts`、`visual-diff.ts` 和 `review-deliverable.ts`。每个探针的可用参数写在脚本顶部。
