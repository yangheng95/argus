# v0.0.32beta Windows Native Matrix Package

## Recall

### 用户原始要求

- 进行矩阵打包。

### 验收指标

- 从仓库唯一版本来源确认版本，不从当前分支名推断版本。
- 严格先运行 GUI（Graphical User Interface，图形用户界面）installer matrix，再运行 CLI（Command-Line Interface，命令行界面）binary matrix，且均不使用跳过构建参数。
- 只声明当前 Windows x64 主机原生构建并经真实 checker 接受的 row；Linux 与 macOS row 必须明确 skipped。
- 独立复核产物名称、版本、PE（Portable Executable，Windows 可移植可执行文件）架构、文件大小与 SHA-256（Secure Hash Algorithm 256-bit，256 位安全散列算法）。
- 记录最终 Git 来源，将计划与验证证据提交并推送到 git-cc 的 `git-cc` remote。

### 硬约束

- `bun run package:gui-installer-matrix` 与 `bun run package:binary-matrix` 是唯一产物所有者；不手工拼装产物，不伪造非本机平台结果。
- 不使用 `--skip-build`，不创建 worktree，不 stash、reset、restore，不绕过 Git hooks。
- 不新增、修改、更新或运行 UI 自动化测试。
- 不重启、刷新、关闭或干预用户正在运行的 OpenCorvus/Overlay。
- 生成的安装包与二进制属于 ignored release output，不纳入源码提交。

| --- | --- |
| GUI installer matrix | 根 `package.json` 调用 `script/package-gui-installer-matrix.ts`；当前主机只构建并验证 `windows-x64`。 |

### 独立 Agent 反馈

- 用户未要求子 Agent、委托或并行审计；本次不启动子 Agent，主 Agent 负责执行与二次复核。

## Plan

1. 提交并推送本 Recall，使打包源成为 git-cc 上可追溯的不可变提交。
2. 使用文档规定的 8 GiB Node.js heap 运行 GUI installer matrix，不使用捷径。
3. GUI 成功后运行 portable CLI binary matrix。
4. 独立运行 release checker，检查 executable 版本与 PE machine，并计算最终产物大小和 SHA-256。
5. 再次 fetch `git-cc/v0.0.31beta`，确认打包期间远端生产输入是否变化。
6. 将结果写回本记录，运行文档健康检查、提交、推送，并确认本地与远端相等。

## Verification Ledger

- `bun run version:check` accepted the repository release family at canonical
  Semantic Versioning（SemVer，语义化版本）`0.0.32-beta`. The branch name
  remained `v0.0.31beta`, so it was not used as version evidence.
- Plan commit `2a28cb00a8` (`dsw-33987 plan v0.0.32beta Windows native matrix
  package`) passed the normal pre-push typecheck, Application Programming
  Interface（API，应用程序编程接口）route, documentation, internationalization,
  and secret-scan hooks and was pushed to `git-cc/v0.0.31beta` before packaging.
- With `NODE_OPTIONS=--max-old-space-size=8192`, the canonical
  `bun run package:gui-installer-matrix` completed in 841.6 seconds without
  shortcut flags. It built the Software Development Kit（SDK，软件开发工具包）,
  a 7,073-module production Overlay, embedded backend, optimized Rust/Tauri
  executable, Microsoft Installer（MSI，微软安装程序）, and Nullsoft Scriptable
  Install System（NSIS，Nullsoft 脚本化安装系统）bundle. The real release checker
  accepted `windows-x64`; Linux x64/ARM64 and Darwin x64/ARM64 were explicitly
  skipped because they require matching native runners.
- The first CLI matrix attempt built the ordinary Windows executable but failed
  the baseline compile because Bun's implicit download of
  `bun-windows-x64-baseline-v1.3.13` returned `ConnectionRefused`. The official
  Bun 1.3.13 Windows x64 and baseline release ZIPs were downloaded into the
  ignored `.scratch/bun-runtimes-1.3.13` tool cache and each executable reported
  version `1.3.13`. Their ZIP SHA-256 values were respectively
  `85B14F3E0584218E9B63407B3AA6B90C4835EC5C32435C1F12CB6FC13667C7C9` and
  `C68C7903C1190101590CC1B2129835F47211B3B37AE87759F2B97D6534AA3AD1`.
  The reruns used the repository-owned `OPENCORVUS_BUN_RUNTIME_DIR` input and
  did not use `--skip-build`.
- One long CLI run outlived its outer 15-minute tool window while the child
  matrix process continued its baseline archive. The process was left intact
  and observed by timed checks until it finished. A later captured full run
  exited successfully, but independent review found that the ordinary bundle's
  `bin/rg.exe` had disappeared after the packager's pre-archive smoke check;
  that artifact set was rejected rather than repaired by hand. No second
  package process or Windows Defender event proved a causal owner, so the
  transient deletion cause remains unknown rather than being mislabeled.
- The final `bun run package:binary-matrix` was chained directly to the
  independent CLI release checker. It completed in 1,233.3 seconds with exit
  code 0, explicitly packaged `windows-x64`, skipped the four non-Windows rows,
  and the immediately following checker accepted both `windows-x64` and
  `windows-x64-baseline`. Both executable `--version` probes reported
  `0.0.32-beta`.
- Independent Portable Executable（PE，Windows 可移植可执行文件）inspection
  found machine `0x8664` for the Overlay and both CLI executables. The NSIS
  bootstrap uses machine `0x014C`, and its file/product version is
  `0.0.32-beta`. MSI metadata reports template `x64;0` and product version
  `0.0.32.0`.
- Both final CLI archives contain 19,579 entries and independently contain

  `browser-mcp-node/package.json`.
