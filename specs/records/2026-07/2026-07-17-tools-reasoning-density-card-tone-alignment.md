## Evidence and cause chain

The visible colour mismatch is not a theme-token failure. The Assistant card background is `color-mix(in srgb, var(--card-stage, var(--accent)) 7%, var(--surface))`, while the expanded execution surface independently mixes `--chat-canvas` with black. These are different sources: the former carries the current Agent/Assistant stage hue and the latter only knows the page canvas, so a cyan card can contain a neutral gray panel. The repair is to name the Assistant card background once on the existing Agent row and derive the expanded execution surface from that inherited value. A first rendered pass mixed with `--surface-strong`; light mode was correct, but the dark Assistant role tint was brighter than that token, so the result could become darker. The corrected contract uses native `light-dark()` with a stronger light-theme and restrained dark-theme white mix, guaranteeing a small lightness increase while retaining the inherited card hue.

The loose vertical rhythm is cumulative rather than a single oversized value. `.chat-bubble__body-inner` contributes a 10px child gap; `.msg-work-details` adds its own gap and margin; expanded state adds padding; the body and each event add further padding; Markdown paragraphs add 5px margins. The current screenshot therefore exposes a large header-to-reasoning and disclosure-to-narrative interval even though each individual declaration appears modest. The repair must normalize the execution surface as one compact typographic stack and zero only the first/last reasoning Markdown margins at that boundary.
