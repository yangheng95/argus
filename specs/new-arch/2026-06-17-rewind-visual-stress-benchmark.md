# Rewind Visual Stress Benchmark - 2026-06-17

## Task

Make task rewind enterprise-grade by testing and then repairing the full visible
rewind path. The required surface is not only `rewindTask()` returning success.
The benchmark must prove that backend cursor state, overlay card-tree state,
conversation hydration/replay, task event streams, worktree reset semantics,
clear, reload, and resume remain consistent after repeated rewind operations.

If a real browser/server is started for this benchmark, it must bind port 7478.

Key recall conclusions:

- The 2026-04-27 rewind plan is partly stale. Current goal worktree metadata is
  sourced from `engine_artifact[kind="goal_run_attempt"].payload`, not direct
  `engine_goal.workspace_*` columns.
- The 2026-04-27 plan still contains a valid boundary: task rewind must not
  use `Snapshot.*` as a second file rollback source. `Snapshot.*` belongs to
  session-level patch history, while goal worktree lifecycle belongs to
  worktree/goal-run artifacts.
- Pre-repair `engine/rewind.ts` violated that boundary by using
  `Snapshot.revert(...)` when `resetWorktree=true`; the implementation now has
  a static regression test proving task rewind does not import `Snapshot`.
- Pre-repair overlay rewind UI pruned `cardTreeStore` optimistically in
  `Card.tsx` and `ChatBubble.tsx`; `task.rewound` prunes again on SSE. Failed
  HTTP rewind can leave the visible tree pruned without authoritative backend
  state.
- Selected-task recovery intentionally avoids full hydrate for normal
  live stream recovery because full hydrate can lose live-only deltas. Rewind
  clear/reload must therefore have an explicit authoritative rebuild path; it
  cannot be hidden behind generic selected-stream recovery.

## Input and Output

Input:

- A fixture task with one root session and a real overlay conversation tree.
- Deterministic cards at timestamps T1..T8 across user, agent, step, phase,
  tool, and error/retry/resume-looking cards.
- Fixture HTTP endpoints for `/global/tasks`, `/task/:id/board`,
  `/task/:id/conversation`, `/task/:id/events`,
  `/task/:id/rewind`, `/task/:id/rewind/clear`, and
  `/task/:id/message`.
- The benchmark server binds `127.0.0.1:7478`.

Output:

- Playwright screenshots for each visible state under
  `packages/overlay/.scratch/rewind-visual-stress/`.
- A JSON report beside the screenshots with request log, event log, DOM
  snapshots, card-tree snapshots, and assertion results.
- A failing process exit if any requirement below fails.

## Idle Timeout

The benchmark uses inactivity timeout, not total elapsed timeout. Activity
signals are:

- request log length changes
- stream event log length changes
- DOM text signature changes
- `window.cardTree.order/cards` signature changes
- screenshot target dimensions or non-white pixel stats change

Default idle timeout: 6000 ms for fixture browser states. Long-running real
opencorvus benchmark variants may raise this via an explicit environment
variable, but the timer must always reset only on observed activity.

## Case Matrix

### Case A - Initial Hydrate Baseline

1. Load overlay at `http://127.0.0.1:7478/ui/index.html`.
2. Restore workspace task from local settings.
3. Assert the conversation renders all fixture cards in chronological order.
4. Screenshot `01-baseline.png`.

Acceptance:

- No console/page/request errors.
- Card-tree order matches visible top-level card order.
- No horizontal overflow or overlapped header/rewind controls.
- Rewind buttons are visible only on rewindable cards.

### Case B - View-Only Rewind To Middle Card

1. Click a middle card's rewind button.
2. Confirm the "view only" option.
3. Assert POST `/task/:taskID/rewind` body includes cursorTime and
   `resetWorktree:false`.
4. Server emits `task.rewound` with the same cursor.
5. Assert cards after cursor disappear and earlier cards remain stable.
6. Screenshot `02-view-rewind.png`.

Acceptance:

- The UI must not prune before the server acknowledges success, or a failed
  acknowledgement must restore from the authoritative server state in the same
  benchmark step.
- `cardTreeStore.rewindCursor` equals backend cursor.
- Board/conversation hydrate endpoints return filtered state with no post-cursor
  cards.

### Case C - Clear Rewind Restores Visible Tail

1. Click or call `/task/:taskID/rewind/clear`.
2. Server emits `task.rewound` with `cursorTime:0`.
3. Assert full tail cards T1..T8 become visible again without duplicate cards.
4. Screenshot `03-clear-restored.png`.

Acceptance:

- Clear must use an authoritative conversation rebuild or equivalent replay,
  not a no-op selected stream restart that leaves pruned cards missing.
- The restored card-tree must match the initial baseline IDs and text.

### Case D - Failed Rewind Does Not Leave Stale UI

1. Configure next POST `/rewind` to return 503.
2. Attempt rewind.
3. Assert post-cursor cards remain visible, or the UI immediately rebuilds from
   `/conversation` before the assertion point.
4. Screenshot `04-failed-rewind.png`.

Acceptance:

- Failed backend rewind cannot leave `rewindCursor` set locally.
- No console-only error is accepted as recovery.

### Case E - Rewind Then Reload

1. Apply view-only rewind.
2. Reload the browser page.
3. Assert startup hydrate shows the filtered timeline and no missing/blank view.
4. Clear rewind.
5. Reload again.
6. Assert full timeline returns.
7. Screenshots `05-reload-filtered.png` and `06-reload-cleared.png`.

Acceptance:

- Persistent backend cursor is the single source after page reload.
- No old in-memory card prune state survives clear.

### Case F - Resume/New Message After Rewind

1. Apply view-only rewind.
2. Submit a new task message.
3. Assert the request goes to `/task/:taskID/message`.
4. Server clears cursor and emits a new user/assistant event after the anchor.
5. Assert the visible tree contains pre-anchor history plus the new branch, not
   the old hidden tail.
6. Screenshot `07-resume-branch.png`.

Acceptance:

- The workflow is not blocked after rewind.
- Old hidden cards do not reappear unless clear/reload explicitly restores
  them.
- New branch events render and keep SSE cursors monotonic.

### Case G - Rapid Rewind Stress

1. Rewind to T6, then T4, then T2, then clear, using real clicks.
2. Insert a stream sequence gap event between operations.
3. Assert final visible tree equals baseline after clear.
4. Screenshot `08-rapid-clear.png`.

Acceptance:

- No duplicate top-level IDs.
- No orphaned `childIDs`.
- No missing selected stream cursor advancement.
- No recovery storm or repeated open streams.

### Case H - File Reset Contract Guard

This case can run as unit/static verification until the full worktree repair is
implemented.

Acceptance:

- `packages/opencorvus/src/engine/rewind.ts` must not import `Snapshot`.
- Task rewind file reset must use the current goal-run/worktree source, not
  session patch parts.
- A reset failure must not persist `rewind_cursor_time`.

## Visual Assertions

Every screenshot is decoded and checked for:

- positive dimensions
- non-white pixel density above 0.03
- more than 24 coarse color buckets
- visible cards for the expected state
- no body horizontal overflow
- no incoherent overlap between card header controls
- no empty center conversation panel

The benchmark also writes the screenshot paths into its JSON report so review
can inspect them after the automated pass.

## Non-Accepted Pass Paths

- Direct `rewindTask()` unit tests without overlay visual evidence.
- DOM text checks without screenshots.
- A passing POST `/rewind` without SSE/render synchronization.
- Any fallback/compatibility branch that silently reloads or ignores failures.
- Generic selected-task recovery used to hide rewind clear failure without an
  explicit authoritative rebuild contract.
- Snapshot-based task rewind file reset.

## Implementation Result - 2026-06-17

Adversarial review findings were folded into the benchmark and repair:

- Failed rewind now proves the POST failed and that the visible tail remains
  authoritative.
- Rewind SSE handling no longer writes fake snapshot versions for
  `resetWorktree`; it schedules authoritative board sync.
- Rewind clear recovery dedupes with ordinary selected sequence-gap recovery so
  clear hydration cannot be aborted by a concurrent recovery.
- Resume/new task message clears the backend rewind cursor and emits a visible
  `task.rewound(cursorTime=0)` branch.
- Worktree reset prevalidates workspace action data before file side effects or
  cursor persistence, aborts affected live goal runs even when their workspace
  is already absent, and uses goal-run/worktree data instead of `Snapshot`.
- The browser benchmark fixture now preserves a protocol event replay log and
  models sequence gaps by withholding one live event while keeping it replayable.
  This prevents a false infinite recovery loop and validates the real selected
  stream recovery contract.
- The browser sidecar has an RPC inactivity timeout and Playwright action
  timeout so a broken visual test fails with evidence instead of hanging.
- Rewind OpenAPI text no longer references PatchPart replay, and the clear
  route uses a flat `task.clearRewindCursor` operationId so the generated SDK
  no longer exposes the conflicting `rewind2` namespace.
