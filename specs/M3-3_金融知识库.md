# AimeCode M3-3 · 金融知识库

> **自包含文档**：一个 AI 模型只读这一个文件，就能实现金融知识库注入。
> **前置条件**：M3-2（上下文记忆引擎，system prompt 动态拼装机制已就绪）。
> **包含**：量化陷阱规则库、金融术语规范、代码审查规则、System Prompt 动态拼装。
> **不包含**：向量检索 RAG（阶段 2+）、外部文档上传。

---

## 1. 目标与验收标准

### 1.1 里程碑目标

将金融领域专业知识以结构化规则的形式注入 LLM 上下文，提升 S02（因子调试）场景的识别准确率。

### 1.2 验收标准

| # | 验收项 | 操作 | 预期结果 |
|---|---|---|---|
| V1 | Look-ahead 识别 | 粘贴含未来信息泄露的因子代码 | Claude 指出具体泄露位置和修正方法 |
| V2 | 存活偏差识别 | 描述只用当前在市股票回测 | Claude 指出存活偏差并给出使用全历史样本的建议 |
| V3 | 代码规范检查 | 生成的代码含 `df['close'].pct_change()` 直接作为因子 | 指出缺少 shift(1) |
| V4 | 金融术语规范 | 用户问"ROE"和"净资产收益率" | 输出统一使用标准名称 |
| V5 | 规则按场景注入 | S01 场景不注入因子调试规则 | system prompt token 数更小 |
| V6 | 因子陷阱识别率 | 10 条含错误的代码 | ≥ 80% 正确识别 |

## 3. 量化陷阱规则

文件路径：`server/knowledge/rules/quant-traps.ts`

```typescript
export interface TrapRule {
  id: string
  name: string
  severity: 'critical' | 'warning' | 'info'
  description: string
  pattern: string         // 代码模式描述（给 LLM 看）
  fix: string             // 修正方法
  example: {
    bad: string
    good: string
  }
}

export const QUANT_TRAP_RULES: TrapRule[] = [
  {
    id: 'QT-001',
    name: 'Look-ahead Bias (未来信息泄露)',
    severity: 'critical',
    description: '在 t 日使用了 t 日或之后的数据来构建信号或做出交易决策',
    pattern: '因子信号使用了当日数据但未 shift(1)；或目标收益率使用了当日的收盘价',
    fix: '所有因子信号必须使用 shift(1)（即 t-1 日数据），预测目标使用 shift(-1)（t+1 日收益）',
    example: {
      bad: `signal = df['close'].rolling(20).mean()  # 使用了当日 close
ret = df['close'].pct_change()  # 当日收益
ic = signal.corr(ret)`,
      good: `signal = df['close'].shift(1).rolling(20).mean()  # t-1 日数据
ret = df['close'].pct_change().shift(-1)  # t+1 日收益
ic = signal.corr(ret)`,
    },
  },
  {
    id: 'QT-002',
    name: 'Survivorship Bias (存活偏差)',
    severity: 'critical',
    description: '回测样本仅包含当前在市的股票，排除了已退市和被 ST 的股票',
    pattern: '使用当前成分股列表做历史回测；或从当前股票池筛选后回溯',
    fix: '使用 Point-in-Time 数据，每个截面日期使用当时的成分股或全市场股票',
    example: {
      bad: `# 错误：用今天的沪深300成分股做2020年回测
current_stocks = get_index_components('000300.SH')
data = get_data(current_stocks, '2020-01-01', '2024-12-31')`,
      good: `# 正确：每月重新获取当月的成分股
for date in monthly_dates:
    stocks = get_index_components('000300.SH', date=date)
    data = get_data(stocks, date, next_date)`,
    },
  },
  {
    id: 'QT-003',
    name: 'Transaction Cost Ignorance (忽略交易成本)',
    severity: 'warning',
    description: '回测中未计算手续费、印花税、滑点',
    pattern: '直接用 pct_change 计算策略收益而未扣除交易成本',
    fix: 'A股双边交易成本约 0.3%（佣金 0.03% + 印花税 0.1% + 滑点），高频策略需要更高估算',
    example: {
      bad: `portfolio_return = position_change * stock_return`,
      good: `cost_per_trade = 0.003  # 30bp 单边
turnover = abs(position_change).sum() / 2
portfolio_return = position_change * stock_return - turnover * cost_per_trade`,
    },
  },
  {
    id: 'QT-004',
    name: 'Overfitting (过拟合)',
    severity: 'warning',
    description: '在全样本上调参后用同一样本评估，或参数过多',
    pattern: '没有 train/test split；或在样本内 Sharpe > 3 但样本外 < 0.5',
    fix: '使用时间序列交叉验证（扩展窗口法），不用随机 split',
    example: {
      bad: `# 在全部数据上优化参数
best_params = optimize(all_data)
sharpe = backtest(all_data, best_params)  # 同一数据！`,
      good: `# 扩展窗口验证
for train_end in rolling_dates:
    params = optimize(data[:train_end])
    oos_sharpe = backtest(data[train_end:train_end+6m], params)`,
    },
  },
  {
    id: 'QT-005',
    name: 'Data Snooping (数据窥探)',
    severity: 'warning',
    description: '反复在同一测试集上调整策略直到"有效"',
    pattern: '测试了 100 个因子变体，只报告最好的那个',
    fix: '使用 Bonferroni 或 FDR 校正多重检验；或预留 holdout 集',
    example: {
      bad: `# 试了50种参数组合，选最好的
results = [backtest(momentum, n=n) for n in range(5, 60)]
best = max(results, key=lambda x: x.sharpe)`,
      good: `# 有理论基础的参数选择 + holdout 验证
n = 20  # 一个月交易日，有经济学含义
is_result = backtest(train_data, momentum, n=20)
oos_result = backtest(test_data, momentum, n=20)`,
    },
  },
  {
    id: 'QT-006',
    name: 'Frequency Mismatch (频率不匹配)',
    severity: 'warning',
    description: '因子频率和持仓调整频率不匹配',
    pattern: '用日频因子但月度调仓，或用月频数据做日度回测',
    fix: '因子计算频率应与调仓频率一致',
    example: {
      bad: `# 日频因子 + 月度调仓 → 日度噪音被放大
daily_signal = df['close'].pct_change(1)
monthly_position = daily_signal.resample('M').last()`,
      good: `# 月频因子 + 月度调仓
monthly_return = df['close'].resample('M').last().pct_change(1)
monthly_signal = monthly_return.shift(1)  # 上月收益作为动量信号`,
    },
  },
]
```

## 4. 知识库管理器

文件路径：`server/knowledge/index.ts`

```typescript
import { QUANT_TRAP_RULES } from './rules/quant-traps'

type ScenarioHint = 'S01' | 'S02' | 'S03' | 'S04' | 'S05' | 'unknown'

/**
 * 根据场景类型生成注入到 system prompt 的知识片段。
 */
export function getKnowledgeInjection(scenario: ScenarioHint): string {
  switch (scenario) {
    case 'S02':
      return buildQuantTrapPrompt()
    case 'S04':
      return buildRiskPrompt()
    default:
      return ''
  }
}

function buildQuantTrapPrompt(): string {
  const rules = QUANT_TRAP_RULES.map(r =>
    `### ${r.id}: ${r.name} [${r.severity}]
${r.description}
**代码模式**: ${r.pattern}
**修正方法**: ${r.fix}
**错误示例**:
\`\`\`python
${r.example.bad}
\`\`\`
**正确示例**:
\`\`\`python
${r.example.good}
\`\`\``
  ).join('\n\n')

  return `

## 量化代码审查规则

当用户请求审查因子代码、回测代码或量化策略时，必须检查以下常见陷阱。如果发现问题，必须明确指出问题所在行号和具体修正方法。

${rules}
`
}

function buildRiskPrompt(): string {
  return `

## 压力测试规则

执行历史情景压力测试时：
1. 必须使用真实历史数据（通过 get_market_data 获取），不可编造数据
2. 最大回撤计算公式：max_drawdown = (peak - trough) / peak
3. 年化收益率使用几何平均：(1 + total_return)^(252/trading_days) - 1
4. Sharpe Ratio 使用无风险利率 2.5%（当前中国 10 年国债收益率近似值）
5. VaR 计算必须说明置信水平和时间窗口
`
}

/**
 * 简单意图推断（用于决定注入哪些知识）。
 * 不是关键词匹配——只是为了选择知识库片段。
 * LLM 自身的 tool call 决策不依赖此推断。
 */
export function inferScenario(userMessage: string): ScenarioHint {
  const lower = userMessage.toLowerCase()
  if (/ic|因子|alpha|动量|反转|look.?ahead|过拟合/.test(lower)) return 'S02'
  if (/压力测试|回撤|股灾|var|风险|回测/.test(lower)) return 'S04'
  if (/对比|比较/.test(lower)) return 'S05'
  if (/封装|函数|查询|行情|k线|走势/.test(lower)) return 'S03'
  if (/roe|财报|毛利率|营收|净利润|pe|估值/.test(lower)) return 'S01'
  return 'unknown'
}
```

## 5. System Prompt 动态拼装

```typescript
// 在 chat 路由中，构建最终 system prompt
import { BASE_SYSTEM_PROMPT } from '@/services/llm/system-prompt'
import { getKnowledgeInjection, inferScenario } from '@/knowledge'

function buildSystemPrompt(userMessage: string, entityContext: string): string {
  const scenario = inferScenario(userMessage)
  const knowledge = getKnowledgeInjection(scenario)

  return BASE_SYSTEM_PROMPT + knowledge + entityContext
}
```

## 6. 集成陷阱

| # | 问题 | 解决方案 |
|---|---|---|
| T1 | 知识注入增加 token 消耗 | 只在 S02/S04 场景注入，其他场景不注入 |
| T2 | 规则太多导致 system prompt 超长 | 量化陷阱规则控制在 6 条内（~2K tokens） |
| T3 | `inferScenario` 误判导致注入无关知识 | 误判只是多花了一点 token，不会产生错误输出 |
| T4 | 规则中的代码示例被 LLM 照搬到输出 | 规则标注为"审查规则"而非"输出模板" |
