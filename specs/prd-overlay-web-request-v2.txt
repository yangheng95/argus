为 Moment Diary 交付一个“可直接编码、无需继续澄清”的 backend-first MVP。

这个任务来自 `specs/prd.txt`，但这里已经把产品需求压缩成固定默认值和明确交付边界。不要再输出高层方案文档，不要继续追问开放问题，直接按下面的默认值实现。

## 固定默认值

- 技术栈固定为：Bun + TypeScript + Hono + SQLite。
- 只做后端 API，不做网页或移动端 UI。
- SQLite 数据库文件固定为 `data/moment-diary.db`。
- 标签在“单个用户内”按小写去重，不要求跨用户唯一。
- `/timeline` 默认分页大小固定为 `20`。
- 不实现 CORS。
- 不使用 JWT；使用更简单、可测试的 Bearer session token 方案即可。
- 数据库初始化可以在应用启动时自动建表，不要求复杂 migration 系统。
- 没有额外环境变量要求；实现应在本地直接运行和测试。

## 交付目标

实现一个最小但合格的日记后端闭环，覆盖：

1. 用户注册
2. 用户登录
3. 认证后创建日记
4. 认证后读取自己的日记
5. 认证后更新自己的日记
6. 认证后删除自己的日记
7. 时间轴查看
8. 按标签和心情筛选
9. 基础隐私保护

## 必须实现的 API

### 认证

- `POST /auth/register`
  - 输入：`email`, `password`
  - 成功返回用户基础信息

- `POST /auth/login`
  - 输入：`email`, `password`
  - 成功返回 `token`

### 日记

- `POST /diaries`
- `GET /diaries`
- `GET /diaries/:id`
- `PATCH /diaries/:id`
- `DELETE /diaries/:id`

要求：

- 以上接口都需要 Bearer token 认证，除了注册和登录。
- `content` 不能为空。
- 标签输入可以是字符串数组。
- 更新时必须刷新 `updated_at`。
- 删除日记时必须同步清理 `diary_tags` 关系。

### 时间轴

- `GET /timeline`

要求：

- 按 `created_at` 倒序。
- 支持查询参数：
  - `tag`
  - `mood`
  - `limit`
  - `offset`

## 安全与业务规则

- 密码绝不能明文存储。
- 未认证请求不能访问受保护接口。
- 用户不能读取、更新、删除其他用户的日记。
- 标签去重要稳定，不要因为大小写重复创建脏数据。
- 返回结果要稳定、可测试，不要夹带调试信息。

## 测试要求

必须有自动化测试，至少覆盖这些场景：

1. 注册成功后数据库里保存的是哈希密码，不是原始密码。
2. 登录成功后返回 token。
3. 使用 token 可以创建日记，并保存 mood 与 tags。
4. 时间轴按时间倒序。
5. `tag` 过滤有效。
6. `mood` 过滤有效。
7. 用户不能访问其他用户的日记。
8. 更新日记会刷新 `updated_at`。
9. 删除日记后内容和关联标签关系都被清理。
