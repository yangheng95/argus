## Cause chain

1. `GET /work-ledger` builds a union of Project, Mission, Chat/Work Session, and every engine Task row.
2. It excludes a Task from the top level only when the Task has complete Mission creator metadata and its owning Mission Session still exists.
3. Right-sidebar conversations can leave engine Tasks with `source: right-sidebar-conversation` and no Mission identity. The live response proves these are exactly the rows shown at top level in the screenshot.
4. `WorkLedgerRow` also declares Task as a valid top-level transport alternative, and the Overlay groups every non-Project alternative as a peer. The frontend therefore faithfully renders the backend's incorrect hierarchy.
5. CSS indentation or a frontend-only filter would leave the API, pagination, search, sorting, command palette, project counts, and other consumers on the old hierarchy. The root repair is to remove Task from the top-level candidate and transport unions while retaining `WorkLedgerMissionRow.tasks` as the sole visible Task projection.

## Single-source design

| Owner                              | Disposition                                                                                                                                                                                          |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `WorkLedgerRow` / `WorkLedgerList` | Top-level union becomes Project, Mission, or Chat/Work. `WorkLedgerTaskRow` remains the Mission-child contract only.                                                                                 |
| `topRowCandidates()`               | Delete the engine Task `UNION ALL` branch and its candidate resolver. Search continues to match Mission child titles/IDs through the Mission branch.                                                 |
| `WorkLedger.tsx`                   | Model group items as Mission or Chat/Work only; remove dead top-level Task sorting, queue drag/reorder, and rendering branches. Keep `WorkLedgerTaskChildRow` and Task actions for Mission children. |
| Runtime index / selection          | Continue indexing `Mission.tasks` by Task ID so selected Task detail, title status, and child actions keep their canonical identity.                                                                 |
| Command Palette / Memory           | Flatten Mission child Tasks when a Task lookup surface is required; never expect a top-level Task row.                                                                                               |
| Archive                            | Archive remains a maintenance surface over its existing endpoint while the active Work Ledger hierarchy is repaired. Any broader Task archival lifecycle change is outside this screenshot defect.   |
| Direct Task APIs                   | Preserve lifecycle, integration, and deep-link access. Work Ledger navigation placement is not Task persistence authority.                                                                           |
| UI tests                           | Delete the touched Work Ledger source/DOM assertion tests without running or replacing them. Real UI acceptance uses the running application and manually reviewed screenshots only.                 |
