## Evidence and root causes

- `tree-writer-part-orderkey.test.ts` exposed a hydrate/live divergence: hydration sorts persisted parts by backend `part`-domain `orderKey`, while `upsertPart` appended newly arriving live parts. A reasoning part arriving after a later tool part therefore remained in arrival order even though reasoning is retained as non-visible runtime evidence. The live writer must insert within the owning message by `orderKey` and update every shifted `partIndex`; hiding reasoning is a renderer concern and must not mutate protocol chronology.
- `card-tree-reachability.test.ts` encoded the old append-only implementation text. Its immutable-array requirement remains valid, but the contract now requires immutable chronological insertion. The live regression also updates a shifted part after insertion to prove `partIndex` remains aligned.
- `conversation-agent-rail-records.test.ts` exposed the multi-message segment case: flattened segment boundaries carry `messageID` but intentionally have no part-domain `orderKey`. Chronological insertion must skip the boundary itself and constrain a late part to its owning message segment, stopping before the next boundary rather than comparing protocol parts across messages.
- `tree-writer-perf.test.ts` still required a reasoning-only executor card in the visible top-level order. The performance contract is unchanged—5,000 deltas must update retained raw evidence without rebuilding the order per token—but the reasoning-only card must remain outside the user-facing order.
- `task-init-git-retry.test.ts` and `tool-call-generation-stream.test.ts` passed while emitting `MissingI18nKeyError` because their isolated processes never installed the real locale dictionaries. The keys exist in both catalogs; both tests now use the shared `installRealOverlayI18n` fixture so real service paths are exercised without false error diagnostics.

1. `assertBoardInvariants` validates task creation time and resolved-interaction response ordering, but never validates `board.task.orderKey`. The test is current: downstream task chronology requires a task-domain key, and both task hydration paths enter through `setBoardData`.
2. The payload market deliberately replaced a boolean `installed` view with the authoritative nullable `installationScope` in commit `5b15b1549`; its TypeScript type, HTTP schema, route mapping, and overlay all use that single contract. One older package-manager assertion still reads the retired property and therefore receives `undefined`. Restoring `installed` would create a duplicate state source, so the test must assert `installationScope === "global"`.
3. The cleanup regression runs five separate Bun processes because each scenario installs process-global `mock.module` and spies. Measured alone, all assertions pass in about 6.4 seconds, but the enclosing test inherits Bun's 5-second default. The process exits normally and leaves no dangling process. This is a test-duration declaration defect, not a production cleanup hang; give only this process-isolation test a bounded 15-second timeout rather than weakening assertions or changing cleanup behavior.
4. The full Overlay runner exposed a stale Command Palette source assertion that requires inline `closeProject()`. The current empty-workspace control-plane record and commit `d16968cde` intentionally centralized that lifecycle in `openGlobalChatLauncher`, whose implementation conditionally closes the active project before opening global Chat. Production, Work Ledger, and Titlebar already use that owner. Restore the regression to the single owner instead of duplicating lifecycle steps in the component.

The next full-run failure identifies `.workspace-main` root declarations in both `workspace.css` and `conversation.css`. `workspace.css` is the documented canonical owner; the later conversation rule only introduced the Agent Rail width custom property. Move that property into the canonical rule. Keep the rail-dependent descendant selector in `conversation.css`, where the feature remains owned, without creating another root declaration.
6. A later failure exposes contradictory Project-hover regressions: the navigation primitive and project-delete tests require sidebar hover ownership to be absent, while the density test requires the duplicate. The DOM proves `.project-group-head.oc-navigation-row` contains both the main Project button and action controls, so primitive `:hover`/`:focus-within` already paints the full head. The sidebar selector additionally highlights the head when unrelated Project body descendants are hovered. Delete the duplicate and align the density regression with the primitive single source.
7. The Provider layout regression still expects every discovery request to call the project-scoped helper directly. The current empty-workspace Provider design deliberately captures `""` as global scope and `null` only as an uninitialized form, then selects `global/providers/discover-models` or the project-scoped route. Update the source regression to require both explicit branches and the one computed request path.
8. Once the task-order boundary is active, three runtime-directory success fixtures fail because their simulated board responses omit the now-required task key. They are not negative corruption tests; stamp every successful board task response with the shared task-domain fixture helper. Direct store setup that intentionally bypasses server hydration remains outside this boundary.

Production intentionally delegates New Chat and Quick Chat to `openGlobalChatLauncher`, while retaining direct `closeProject` only for the distinct Close Project command. Align the test with these separate owners.
10. The hierarchy suite still expects a reasoning-only executor message to enter the visible card order. That directly contradicts the delivered reasoning-display retirement. Keep applying and flushing the raw reasoning delta and retain its internal card-tree node for protocol ownership, but assert it never enters display order without another visible part.
