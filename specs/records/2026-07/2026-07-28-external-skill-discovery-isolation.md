## Causal chain

1. **Observable:** Provider catalog, live-model refresh, and Provider list all
   return HTTP 500 for a project whose directory is carried in the query.
2. **Direct trigger:** two automatically discovered files under
   `~/.agents/skills/` declare the exact same `context-restore` identity, and
   `Skill.registerStrict` throws `SkillInvalidError`.
3. **Deep cause:** automatic third-party compatibility discovery shares the
   fatal registration policy of explicit OpenCorvus/configured sources.
   Project bootstrap also validates Chat capabilities by enumerating the
   complete installed Skill catalog even when Chat assigns no Skills, so the
   unrelated Provider handler is never reached.
4. **Why the path looked guilty:** the common project bootstrap prefixes all
   downstream errors with the project-scoped request URL. The `%2F` sequences
   are ordinary URL encoding and are decoded before `Filesystem.resolve`; the
   exception payload points to the duplicate Skill identities instead.

## Call-site disposition

| Owner / consumer                                             | Disposition                                                                                                                                                                                            |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `skill.ts` built-in registration                             | Keep strict and canonical.                                                                                                                                                                             |
| Automatic `.claude/.agents/.codex` discovery                 | Parse each candidate independently. Warn and skip invalid candidates. Quarantine every automatic definition of a duplicated name. Keep warnings in the same instance state as the canonical catalog.   |
| `.opencorvus`, configured path, and configured URL discovery | Keep strict. If the same name was only auto-discovered, replace that automatic candidate and record why; duplicate explicit definitions remain fatal.                                                  |
| `Skill.all/get/dirs` consumers                               | Keep their existing catalog contracts. Add a read-only `Skill.warnings()` projection for regression evidence and diagnostics; do not create another catalog or API response shape.                     |
| `ChatCapability.assertConfig`                                | If no Chat Skill references are configured, validate MCP references without enumerating installed Skills. When references exist, retain exact installed-reference validation.                          |
| Project middleware and Provider routes                       | Keep unchanged. Tests prove the reported encoded directory reaches Provider after bootstrap and that no Provider-specific bypass is introduced.                                                        |
| Skill route tests                                            | Replace the obsolete expectation that an automatic/external collision prevents bootstrap. Prove the explicit `.opencorvus` definition is authoritative and the automatic source is warned and ignored. |
| Mission Skill catalog                                        | Keep its strict identity collision behavior unchanged; it is an explicit orchestration surface, not automatic compatibility discovery.                                                                 |
