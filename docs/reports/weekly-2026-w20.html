01总体情况

本周 OpenCorvus 的主要变化集中在三条线：算法与编排边界收紧、Overlay 操作面继续成型、执行器命名完成从历史包袱到当前品牌的迁移。核心链路仍围绕任务事实推进：需求进入 REQ 条目，Architect 生成至少两个 Goal 和接口契约，Build 执行，Integrity 与 Delivery 复核，用户后续消息继续进入同一任务上下文。

从当前仓库状态看，项目仍处于开源准备和早期增长阶段。核心代码、前端和通道适配已具备可展示形态，但对外材料、性能基线、长任务稳定性和多人操作边界仍需继续收口。

核心结果

  • 跨 Goal 契约链路更清晰：Contract IR、Linker、Acceptance scorer 和 Integrity 审计的责任边界被进一步固定。
  • Overlay 从任务浏览向操作面推进：Operator Gateway Console 和 conversation rail 让控制消息、任务状态、证据查看集中到同一前端体验。
  • 执行器历史命名减少：当前内置执行器代码路径已经是 executor/opencorvus.ts，对外材料只保留当前实现命名。
  • 对外材料回到事实口径：OpenCorvus 自身路径使用 1,507 commit 表述，不把 fork 前上游历史计入自身工作量。

业务结果

  • OpenCorvus 可以用“代码交付编排系统”而不是“又一个编码 Agent”对外解释，差异点集中在任务事实、Goal、契约、审计和交付判决。
  • 本周完成的执行器命名迁移减少了 fork 历史带来的误读，降低对外材料中出现过期代码名的概率。
  • Operator Gateway Console 让多通道控制面有了统一前端入口，为 Slack、HTTP 和后续通道统一操作规则提供基础。
  • 白皮书与周报使用可复核数字，避免把上游 12k+ 历史误写成 OpenCorvus 自身投入。
