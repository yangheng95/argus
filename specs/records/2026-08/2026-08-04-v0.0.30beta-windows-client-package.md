# v0.0.30beta Windows Client Package Plan

> **For agentic workers:** Execute this packaging plan inline from the current Windows checkout. Do not delegate, create a worktree, or substitute another packaging path.

**Goal:** Build and independently verify a new native Windows x64 OpenCorvus desktop-client package from the current `0.0.30-beta` delivery source.

**Architecture:** The repository-owned GUI installer matrix is the only package owner. It builds the Software Development Kit (SDK), production Overlay, embedded backend, Rust/Tauri executable, Microsoft Installer (MSI), and Nullsoft Scriptable Install System (NSIS) installer, then stages the accepted Windows row under `packages/overlay/dist-artifacts/windows-x64/`.

**Tech Stack:** Bun 1.3.13, TypeScript, Vite, Rust, Tauri 2, Windows x64.

## Global Constraints

- Use `packages/opencorvus/package.json` and `bun run version:check` as the version source; do not infer a version from the branch name.
- Run `bun run package:gui-installer-matrix` without `--skip-build`.
- Build only the host-supported Windows x64 row and report Linux and macOS rows as skipped.
- Do not add, modify, update, or run User Interface (UI) automated tests.
- Do not restart, refresh, close, or otherwise interfere with a running OpenCorvus or Overlay process.
- Do not create a worktree, stash, reset, restore, bypass Git hooks, or push to `origin` as a substitute for `legacy-remote`.
- Generated executables and installers are ignored release outputs and must not be committed.
- Commit subjects must begin with `dsw-33987`.

## Execution Ledger

### Published package-plan baseline

- Commit `6f9fab3d31` (`dsw-33987 plan v0.0.30beta Windows client package`) was pushed to `legacy-remote/work-lcx-v0.0.30beta` through the normal pre-push hooks.
- The hooks accepted full typecheck, API route inventory, documentation generation, Overlay internationalization, and secret scanning.

### First matrix attempt: missing documented Node heap

- `bun run package:gui-installer-matrix` built the SDK in 25.24 seconds, then the production Vite subprocess exhausted Node's default 2,348,810,240-byte heap after about 209 seconds.
- The access path was traced from the matrix to `packages/overlay/script/build.ts`, then to the `build:vite` package script and its Node-hosted Vite process. The original shell had an empty `NODE_OPTIONS` value.
- Repository packaging documentation already prescribes `NODE_OPTIONS=--max-old-space-size=8192` for this exact failure. With that value, a child Node probe reported an 8,791,261,184-byte heap limit. No source workaround or shortcut flag was introduced.

### Second matrix attempt: generated contract drift and occupied staging source

- With the documented heap, Vite transformed 7,062 modules in 69.59 seconds; the embedded backend completed in 102.22 seconds; the Tauri executable completed in 320.46 seconds; and MSI plus NSIS bundling completed in 50.98 seconds.
- Staging then failed with the Windows access-denied error `EACCES` while removing the canonical `packages/overlay/dist-artifacts/windows-x64` directory. Process inspection proved Process Identifier (PID) 22788 had been launched from that exact old directory by Windows Explorer at 18:32:08, twelve seconds before the first matrix process started. The client therefore owns a live executable lock; filesystem permissions are valid.
- The SDK build also regenerated `packages/sdk/js/src/gen/types.gen.ts` from the current API source. The positive contract now includes terminal coordination acknowledgement, exact terminal Task event payloads, and Task ingress provenance. A second generation produced the same SHA-256 hash `76F85E9C69580F9781B91658B9B49F0C195F911F537A54B9BFF085BDA2E6E656`, and SDK typecheck passed.
- The generated contract must be committed and pushed before the final full matrix rerun so the package source remains immutable and self-consistent.

### Final matrix build and independent verification

- With the documented `NODE_OPTIONS=--max-old-space-size=8192`, the canonical `bun run package:gui-installer-matrix` completed in 564.1 seconds without shortcut flags.
