## Implementation boundaries

1. Add one shared Skill under `expert-squads/mirror/mirror-prd/skills/mirror-prism-cluster/` and project it only to the Mirror PRD scheduler. Its full content is loaded only when the user invokes `@skill`; ordinary bounded Mirror PRD work continues to use `mirror-prd-workflow`.
2. Keep all five scheduler prompts stage-local. They must not name a mandatory next profile or embed the cluster route. The shared Skill owns exact predecessor evidence, completion evidence, next `select_expert_squad` call, and continuation-wake semantics.
3. Keep handoff truth in existing project artifacts plus visible terminal worker/Orchestrator messages. Do not create a second persisted step/status ledger.
4. Distill source templates and invariant-bearing references into the cluster Skill or the responsible stage package. Do not copy absolute paths, credentials, provider fallbacks, retry wrappers, cron/watchdog logic, cached state, or obsolete executor diagnostics.
5. Reuse the existing Task/Mission project archive. Do not add a second ZIP tool, and do not report remote Kanban delivery without the absent official dispatcher.
6. Tests must execute real Registry/Manager/Resolver projection of the shared Skill, verify inactive isolation and package-local loading, prove the five exact selector identities, and reject next-squad hard routes in stage prompts.
