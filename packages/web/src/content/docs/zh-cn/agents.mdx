OpenCorvus 的编排围绕 **agent** 构建。单个任务可派生多个 agent——主规划者、执行者，以及为并行 goal 派遣的一次性 sub-agent。

源码：`packages/opencorvus/src/agent/`、`packages/opencorvus/src/orchestrator/`。

## Primary agents

OpenCorvus 内置若干 primary agent：

| Agent | 角色 |
|---|---|
| `task` | 顶层协调者，驱动 spec → goals → plan → run → eval |
| `requirements` | 从用户请求提取可测试 spec（含验收标准） |
| `planner` | 把 spec 分解为独立 goal |
| `executor` | 实现 goal 的主力 |
| `evaluator` | 跑 build/test/lint/startup/artifact 检查 |

每个 agent 的模型可独立通过 `assistant.<name>.model` 配置（见 [config](/docs/zh-cn/config/)）——常见用强/慢模型规划、用快/便宜模型执行。

## Sub-agents

任务有多个并行 goal 时，planner 通过 **`dispatch_goal`** 工具派遣 sub-agent，每个 sub-agent 在独立的 Goal worktree（git 工作目录）里跑，结果由 orchestrator fast-forward 合并回主分支。

evaluator 拒绝某个 goal 时，orchestrator 可调 **`retry_goal`** 用上次失败上下文重启一次新尝试——同一 goal，新 session。

每个 sub-agent 一个 session：orchestrator 不会在已有 sub-agent session 上"包一层 next session"。

## 自定义 Agent

可在 config 内联或 `~/.config/opencorvus/agents/`、`.opencorvus/agents/` markdown 文件中定义：

```jsonc
{
  "agent": {
    "code-reviewer": {
      "description": "审查代码最佳实践与潜在问题",
      "model": "anthropic/claude-sonnet-4-6",
      "prompt": "你是代码评审者。关注安全、性能、可维护性。",
      "tools": { "write": false, "edit": false }
    }
  }
}
```

自定义 agent 继承 OpenCorvus 的工具集、权限与 channel 接入。

## 默认 Agent

`default_agent` 指定无显式选择时使用的 agent，必须是 primary agent。

## 预算

Agent run 受 `assistant.<name>` 预算限制：
- `max_steps` — 每次 run 的轮次上限
- `max_runs` — orchestrator 层重试次数
- `max_goal_retries` — 单个 sub-goal 重试次数

这些是硬上限，防止循环失控。详见 [config](/docs/zh-cn/config/)。
