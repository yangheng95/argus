## Root cause

The application deliberately combines an AppKit overlay titlebar with a compact 36-logical-pixel HTML top row. With no explicit `trafficLightPosition`, AppKit chooses its normal titlebar placement, which is not derived from the application's compact row. The supplied Retina screenshot shows the 14-logical-pixel traffic-light group approximately two logical pixels above the menu/navigation center. Moving HTML content would align one platform by breaking the already canonical row and every non-macOS host; CSS also cannot move native AppKit views.

Tauri passes `trafficLightPosition` as a logical position into TAO/Wry. Their macOS implementation uses `x` as the close-button origin, but `y` is not a top coordinate: Wry retains AppKit's button origin inside its native container and sets that container's height to `button height + y`. The first isolated Retina screenshot with `y=11` measured the traffic-light center nine logical pixels above the canonical 36px Web-row center. Increasing the native-container inset by those measured nine pixels gives `y=20`; `x=10` preserves the measured horizontal close origin and the established 78px Web-content inset.

The retired `{x:14,y:12}` override is not restored: both coordinates differed from the current measured titlebar and content-inset contract.

The menu mismatch is a separate ownership error in the same chrome layer. `main.rs` unconditionally calls `window.remove_menu()`, explicitly discarding Tauri's application menu on macOS. `App.tsx` then mounts the Kobalte `TitlebarMenubar` inside the Web titlebar on every host. Its trigger font is a hard-coded 12px, which explains the follow-up typography observation, but increasing that font would preserve the wrong macOS owner. The root repair is to restore the app-wide Tauri menu on macOS and make the Web menubar non-native-host-only.

Application actions remain single-source: macOS custom native items emit a stable action identifier to the mounted frontend action owner; Windows/Linux/browser triggers invoke that same action map directly. AppKit predefined items own standard About, Undo/Redo, Cut/Copy/Paste/Select All, Services, Hide/Show, Minimize, Full Screen, and window-front behavior.
