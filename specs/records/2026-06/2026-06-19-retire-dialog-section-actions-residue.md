# Retire Dialog Section Actions Residue

Date: 2026-06-19

CSS means Cascading Style Sheets. DOM means Document Object Model.

## Problem

`dialog.css` still carries an old section-detail dialog selector cluster and a
`.session-actions .oc-button` rule. The current dialog runtime uses Solid host
components and the shared Kobalte-backed Dialog primitive; no production
component or service emits `.section-dialog-head`, `.section-dialog-meta`,
`.section-dialog-body`, or `.session-actions`.

The `.session-actions` block is especially clear: its own comment says it has
zero renderer references and was only preserved pending explicit approval. The
current goal explicitly authorizes unattended cleanup of high-confidence dead
UI code, so keeping it now creates stale dialog contracts.

## Recall

| Source                                         | Relevant constraint                                                                               |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `2026-06-09-overlay-ui-tech-debt-consensus.md` | Dialog semantics should be owned by the mature Dialog primitive, not feature-local dialog shells. |
| `dialog-service-single-source.test.ts`         | App, session, goal, and config dialogs are store-backed Solid hosts rather than raw DOM mutation. |
| `dead-dialog-cleanup.test.ts`                  | Retired dialog-only selectors should be absence-guarded once no runtime owner remains.            |
| `dialog-primitive.test.ts`                     | Feature components render the shared Dialog primitive and do not own native dialog wiring.        |

## Fix

- Remove `.section-dialog-head`, `.section-dialog-meta`,
  `.section-dialog-body`, and `.session-actions .oc-button` from
  `dialog.css`.
- Extend dialog cleanup tests to reject these retired selectors in production
  CSS/source.
- Add a browser visual check for the live Session dialog body so the cleanup is
  tied to the current dialog surface instead of only static text.

## Acceptance

- Production source has no `.section-dialog-*` or `.session-actions` owners.
- `dialog.css` still keeps `.session-dialog-body` and `.session-msg*`.
- Focused dialog cleanup tests pass.
- Real browser screenshot of the live Session dialog body is reviewed.
