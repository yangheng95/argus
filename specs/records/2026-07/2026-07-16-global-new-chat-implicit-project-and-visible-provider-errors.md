## Evidence and causal chains

The live session contains the persisted user message `你好` and a completed assistant message with no parts. Its real error is HTTP 401 from Provider `hexin/gpt-5.5`: LiteLLM received the configured `nova…late` credential but requires a virtual key beginning with `sk-`. The frontend shows only one card because the backend conversation filter rejects part-less assistant errors and tree-writer also hides part-less message cards, including cards with terminal error metadata.

Menu-bar New Chat calls `selectTask("")`, which clears the selected task/session but deliberately does not clear `settingsStore.directory`. The launcher therefore reads `nova-project` from the retained project context and creates the Chat there.

Observable no reply → Provider rejects authentication → assistant error persists without text parts → hydrate and card visibility discard the real error surface. Observable wrong directory → menu action clears only conversation selection → retained project directory remains active → project-bound Chat creation receives the prompt in `nova-project`.
