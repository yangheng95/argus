### Acceptance criteria

1. Fetch `myhexin/v0.0.11beta`, preserve the existing staged work, merge the remote branch, and bind packaging to one recorded source commit.
2. Run the repository-owned `bun run package:gui-installer-matrix` without `--skip-build` for native Windows x64.
3. Run the same matrix owner in Docker Linux x64 and Linux ARM64 containers built from `packages/overlay/docker/Dockerfile`; do not hand-assemble Tauri bundles or describe cross-compilation as native verification.
4. Produce and validate the Windows raw executable, MSI (Microsoft Installer), and NSIS (Nullsoft Scriptable Install System) installer.
5. Produce and validate each Linux row's raw executable, DEB (Debian package), RPM (Red Hat Package Manager package), and AppImage installer.
6. Record exact artifact paths, byte sizes, SHA-256 digests, architecture evidence, version evidence, and the canonical release-validator result for every completed row.
7. Run the focused GUI matrix and release-workflow contract tests, version alignment, document health, historical-link health, and final diff review.
8. Commit the packaging record with the required `dsw-33987` prefix and push the completed branch to git-cc remote `myhexin`.

### Hard constraints

- No fallback, compatibility path, manual installer construction, `--skip-build`, or false native-platform claim.
- Windows host files are the edit and Git source of truth. Host/WSL (Windows Subsystem for Linux) synchronization uses only `script/sync-host-wsl.ps1`, first dry-run and then one reviewed apply.
- Linux build outputs are created inside Docker from synchronized source. Build artifacts are not synchronized back as source; they are copied out explicitly as requested deliverables and validated against the release contract.
- Do not create a new Git worktree and do not reset, restore, or discard concurrent changes.
- Do not restart, close, refresh, or otherwise interfere with a running OpenCorvus/Overlay process. Isolated packaging processes are allowed to finish naturally.
- A timeout is inactivity-based. Long packaging is monitored through emitted build output and artifact activity, not total elapsed time.
- Generated installers remain ignored delivery artifacts and are not committed to Git.

## Verification record

- Windows x64 completed from commit `2a6a2263ef`: the canonical matrix generated and validated the raw GUI executable, MSI, and NSIS installer. Exact digests are recorded after all matrix rows finish.
- The mandatory host/WSL dry-run did not reach conflict classification within the 120-second outer command limit. Its partial report proved the Windows host was clean while the pre-existing WSL checkout had a large changed-file set. No apply or preference flag was used. Linux Docker therefore reads the Windows source-of-truth workspace directly through `/mnt/c`; it does not copy files into or mutate the WSL checkout.
- Pre-build Dockerfile review found that the repository Linux Tauri image omitted `xdg-utils`, which provides the `xdg-open` binary required by the AppImage bundler, and omitted the build-time `ripgrep` dependency present on every native workflow runner. The image now declares both packages and a focused contract test locks the complete Docker toolchain.
- The first x64 image build proved `deb.debian.org` could resolve and transfer but was operationally unusable on this network: a fixed 1.7 MB package did not finish in 20 seconds, while the byte-identical Aliyun and TUNA Debian mirror paths completed at about 6.0 MB/s and 5.1 MB/s. The Dockerfile now exposes official-default `DEBIAN_MIRROR` and `DEBIAN_SECURITY_MIRROR` build arguments; this run supplies the measured Aliyun mirror paths without changing package names, versions, or the default Dockerfile source.
- After the Debian layer completed, the previous `curl https://bun.sh/install` step made no network progress because `bun.sh` resolved to blocked Cloudflare addresses. That path also installed an unpinned current Bun instead of the repository's declared runtime. The Dockerfile now copies Bun from the official multi-architecture `oven/bun` image, with its default `BUN_VERSION` contract-tested against root `packageManager`, and exposes an official-default `NPM_REGISTRY` argument for the Tauri CLI and later repository dependency installation.
- The first fixed-Bun image build also exposed that the removed installer script had implicitly created the global Bun binary path. The Dockerfile now explicitly retains `/root/.bun/bin` on `PATH`, and the contract test proves the preinstalled Tauri CLI remains executable instead of merely present on disk.
- Executing the installed `tauri` binary then exposed the CI/Docker environment mismatch: its package launcher requires `node`, which hosted CI runners provide but the Docker image did not. The native Docker dependency layer now includes Node.js and the same toolchain contract test locks that requirement; no wrapper or shebang rewrite is used.
