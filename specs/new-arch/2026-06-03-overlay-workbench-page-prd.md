## 0. 缩写与术语定义
- GLOSSARY-001 PRD: Product Requirements Document，产品需求文档，用于定义目标、范围、用户体验、接口、验收和发布要求。
- GLOSSARY-002 UI: User Interface，用户界面，指用户可见的布局、控件、文案和视觉反馈。
- GLOSSARY-003 UX: User Experience，用户体验，指用户完成任务的路径、效率、可理解性和错误恢复体验。
- GLOSSARY-004 API: Application Programming Interface，应用程序接口，指 overlay 前端调用 opencorvus server 的 HTTP 或 host transport 合约。
- GLOSSARY-005 HTTP: HyperText Transfer Protocol，超文本传输协议，本页通过它访问 server route。
- GLOSSARY-006 SSE: Server-Sent Events，服务器发送事件，用于任务列表、会话消息和进度的流式更新。
- GLOSSARY-007 LLM: Large Language Model，大语言模型，OpenCorvus 中负责理解、规划、构建、审查和对话的智能执行主体。
- GLOSSARY-008 MCP: Model Context Protocol，模型上下文协议，用于连接浏览器、文件、工具等外部能力。
- GLOSSARY-009 DB: Database，数据库，本项目中主要指 engine 运行期 SQLite 数据库。
- GLOSSARY-010 SQLite: SQLite database engine，轻量嵌入式数据库，存放 task、session、artifact 等运行期记录。
- GLOSSARY-011 VCS: Version Control System，版本控制系统，本页主要展示 Git 仓库状态、分支、提交和文件变化。
- GLOSSARY-012 Git: 分布式版本控制系统，OpenCorvus 通过它管理 worktree、branch、commit、diff 和 push。
- GLOSSARY-013 QA: Quality Assurance，质量保障，包含单元测试、集成测试、视觉验证和回归检查。
- GLOSSARY-014 Tauri: 桌面应用运行时，用于 packaged overlay 的窗口、侧车进程和 host transport。
- GLOSSARY-015 WebView: 嵌入式网页视图，Tauri 桌面应用中承载 overlay HTML/CSS/JS 的容器。
- GLOSSARY-016 Solid: Solid.js，overlay 前端使用的响应式 UI 框架。
- GLOSSARY-017 Kobalte: Kobalte Core，Solid 生态的成熟无样式交互 primitive 库，用于 tabs、popover 等语义控件。
- GLOSSARY-018 CodeMirror: CodeMirror 6，成熟代码编辑器组件，用于文件编辑器而不是手写 textarea 编辑体验。
- GLOSSARY-019 Virtua: virtua/solid，虚拟列表库，用于长会话、日志和文件树的大列表渲染。
- GLOSSARY-020 Worktree: Git 工作树，用于每个目标或任务隔离执行文件改动。
- GLOSSARY-021 Artifact: engine_artifact，append-only 运行期产物记录，是 run、goal_run_attempt、delivery、verification evidence 等的单一来源。
- GLOSSARY-022 Mission: OpenCorvus 长运行目标和外部 channel 的控制页面模式，和 Panel 共用 overlay shell。
- GLOSSARY-023 Panel: 默认工作台页面模式，包含任务列表、对话、composer、右侧 Explorer/Files/Inspector。
- GLOSSARY-024 Composer: 消息输入区，负责发送用户自然语言、附件和 web search 参数。
- GLOSSARY-025 Inspector: 右侧检查面板，展示 Requirements、Architect、Goals、Evaluation、Trace 等任务结构化信息。
- GLOSSARY-026 Explorer: 右侧文件浏览器，使用 project-scoped file API 懒加载目录并打开文件编辑器。
- GLOSSARY-027 Files: 右侧文件变化面板，展示 delivery 投影出的 changedFiles、diffs、commitRef 和 diff stats。
- GLOSSARY-028 Diagnostics: 诊断信息，指 API error、runtime error、log、health、debug blob 和 notification 等可定位问题的数据。
- GLOSSARY-029 Fallback: 备用兼容路径，本 PRD 禁止将 fallback 作为产品方案，错误必须显式暴露并修根因。

## 1. 文档目标
- DOC-GOAL-001 定义 Overlay 主工作台页面的完整产品边界，覆盖默认 Panel mode 和 Mission mode。
- DOC-GOAL-002 把页面现有实现中的隐性行为转换为可验证的产品需求。
- DOC-GOAL-003 为后续 UI、接口、错误可见性、性能、测试和发布提供单一需求来源。
- DOC-GOAL-004 避免把页面写成营销页，页面第一屏必须是可用的工作台。
- DOC-GOAL-005 明确禁止 fallback、兼容双路、状态机绕行和隐藏消息分叉作为产品解法。
- DOC-GOAL-006 让工程实现围绕真实 data source 展开，而不是围绕截图或临时 mock 展开。
- DOC-GOAL-007 确保任务执行、文件编辑、diff 检查、日志诊断和 Mission 控制都可被用户独立完成。
- DOC-GOAL-008 把用户可见状态、系统状态、错误状态和审查证据放在同一页面产品模型里。
- DOC-GOAL-009 给 QA 提供足够细的验收清单，避免只检查页面能打开。
- DOC-GOAL-010 给设计提供足够细的信息架构，避免装饰性重做。

## 2. 页面范围
- SCOPE-001 页面包含 titlebar、workspace command dock、left task ledger、central conversation、composer、workspace diff、file editor、right panel、dialogs、notifications、logs 和 Mission mount。
- SCOPE-002 页面不包含外部文档站、CLI TUI、server-only API 文档页、GitHub action 页面和纯 benchmark 页面。
- SCOPE-003 默认 mode 是 Panel，body[data-page-mode='panel'] 下显示工作台三栏。
- SCOPE-004 Mission mode 与 Panel mode 并列挂载，不卸载 Panel，以保留选中任务和对话状态。
- SCOPE-005 右侧 panel tab 的默认值是 Explorer。
- SCOPE-006 Files tab 是 delivery file projection，不是本地文件浏览器。
- SCOPE-007 Inspector tab 是任务结构化状态，不是通用设置中心。
- SCOPE-008 File editor 是 conversation sidecar，不是 right panel 内部 tab。
- SCOPE-009 Workspace panel 是 diff/workspace 底部区域，不是持久文件编辑器。
- SCOPE-010 Log viewer 是 dialog surface，不应占用三栏常驻空间。
- SCOPE-011 Notification center 必须独立挂载，并在异步启动之前可用。
- SCOPE-012 Connection badge 和 connection banner 是诊断入口，不是装饰状态。
- SCOPE-013 Window controls 仅对桌面 WebView 有意义，但 Web 环境也必须保持布局稳定。
- SCOPE-014 Recent directory dropdown 位于 panel 外部，以逃逸 stacking context 和 overflow clip。
- SCOPE-015 Brand guide 是短 hover/focus 帮助，不得替代实际工作台功能。

## 4. 用户画像
- PERSONA-001 Operator: 日常使用 OpenCorvus 完成开发任务的人，需要快速创建任务、监控进度、审查结果并继续追问。
- PERSONA-002 Maintainer: 维护 OpenCorvus 自身的人，需要查看 debug blob、logs、runtime diagnostics 和 route/source 证据。
- PERSONA-003 Reviewer: 对交付物做质量审查的人，需要看到需求、计划、目标、文件变化、diff、证据和失败原因。
- PERSONA-004 Mission Owner: 运行长期 Mission 或 channel automation 的人，需要查看 Mission 列表、channel runtime 和 Mission conversation。
- PERSONA-005 Frontend Engineer: 调整 overlay UI 的工程师，需要清楚布局、组件责任、响应式和成熟 primitive 约束。
- PERSONA-006 Backend Engineer: 调整 server routes、engine artifact、file API 的工程师，需要清楚页面消费哪些 route。
- PERSONA-007 QA Engineer: 负责回归的人，需要明确每个 state、route、error 和 visual acceptance。
- PERSONA-008 Support Engineer: 排查用户环境问题的人，需要复制 task debug info、logs、health 和 project-scoped probes。

## 5. 用户核心目标

- USER-GOAL-005 在交付完成后查看 changed files、diff、commit reference、evaluation 和 follow-up suggestion。
- USER-GOAL-006 打开项目文件，搜索文件，编辑文本文件，并通过 project-scoped API 保存。
- USER-GOAL-007 从 right inspector 检查需求、架构、目标、trace、review 和 delivery evidence。
- USER-GOAL-008 从 titlebar 进入 settings、providers、models、tools、view、diagnostics 和 log viewer。
- USER-GOAL-009 在 Mission mode 中查看 Mission records、启动或恢复 Mission、查看 channel runtime。
- USER-GOAL-010 在桌面 overlay 中完成窗口控制、编辑器启动、terminal 启动和 coding CLI 启动。

## 8. 全局产品原则
- PRINCIPLE-001 用户输入必须进入真实会话或真实 task route，不走隐藏分叉。
- PRINCIPLE-002 页面展示的任务状态必须来自 server 或 store single source。
- PRINCIPLE-003 错误必须显式呈现，不用空状态替代错误。
- PRINCIPLE-004 长列表必须虚拟化或分页，不能让 DOM 随历史无限增长。
- PRINCIPLE-005 Project-scoped route 必须携带 directory context。
- PRINCIPLE-006 Control-plane route 只能表达 global health/config/dispose/tasks 等全局语义。
- PRINCIPLE-007 文件读写必须经过 path canonicalization 和 project-scoped file API。
- PRINCIPLE-008 所有 destructive action 必须有明确确认或两段式 armed confirm。
- PRINCIPLE-009 UI 控件语义优先使用成熟 primitive 或现有组件。
- PRINCIPLE-010 页面不靠解释性大段文字教用户；控件、状态和布局本身应承担可理解性。
- PRINCIPLE-011 任务执行中用户仍可发送 operator note 或追加消息。
- PRINCIPLE-012 Composer stop 只停止当前 send request，不远程 cancel task。
- PRINCIPLE-013 Task cancel 是 task row 或 task action 的显式操作。
- PRINCIPLE-014 Mission 和 Panel 的状态保留必须来自同一 page mode store。
- PRINCIPLE-015 每个用户可见状态都必须能映射到一个 testable source。

## 9. 页面模式需求
- PAGE-MODE-001 Panel mode 是默认模式，显示 Recent Chats、Conversation、Right Panel。
- PAGE-MODE-002 Mission mode 通过 sidebar Mission button 或 pageMode store 切换。
- PAGE-MODE-003 切换到 Mission mode 时，Panel DOM 保留但视觉隐藏。
- PAGE-MODE-004 从 Mission mode 返回 Panel 时，之前的 active task、conversation scroll、right tab、workspace target 应尽量保留。
- PAGE-MODE-005 Mission mode 不应触发 Panel task selection 重置。
- PAGE-MODE-006 Mission mode 资源请求应仅在 active mode 且必要 directory 已存在时发起。
- PAGE-MODE-007 Panel mode 资源请求不应因为 Mission component 常驻挂载而被 Mission 行为污染。
- PAGE-MODE-008 body[data-page-mode] 是 CSS 可见性单一来源。
- PAGE-MODE-009 Page mode 切换不应创建第二套 router。
- PAGE-MODE-010 Page mode 切换不应引入 history fallback 或 URL hash 兼容路径。

- STARTUP-014 Startup 必须恢复 zoom、opacity、theme 和 pane layout。
- STARTUP-015 Startup 必须启动必要 sync timers，并在 teardown 时停止。

## 12. API contract requirements
- API-001 GET /global/health is control-plane health and not task DB proof.
- API-002 GET /global/tasks is the task ledger source.
- API-003 POST /global/db/reset requires explicit confirmation.
- API-004 GET /task/events is the global task-list SSE source.
- API-005 POST /task creates a task.
- API-006 GET /task/:taskID/board is selected task board source.
- API-007 GET /task/:taskID/progress is selected task progress source.
- API-008 GET /task/:taskID/conversation is selected task conversation source.
- API-009 GET /task/:taskID/conversation/history pages older history.
- API-010 GET /task/:taskID/conversation/events replays conversation events.
- API-011 POST /task/:taskID/message sends operator message to existing task.
- API-012 POST /task/:taskID/cancel cancels task explicitly.
- API-013 POST /task/:taskID/retry retries task.
- API-014 POST /task/:taskID/replan replans task.
- API-015 POST /task/:taskID/rewind rewinds from message/card anchor.
- API-016 POST /task/:taskID/followup returns finish-edge follow-up suggestion.
- API-017 DELETE /task/:taskID deletes task.
- API-018 PATCH /task/:taskID/title renames task.
- API-019 POST /task-queue/reorder reorders queued tasks.
- API-020 POST /task/:taskID/start-now starts queued task immediately.
- API-021 GET /file lists Explorer directory content.
- API-022 GET /find/file searches Explorer files.
- API-023 GET /file/content reads file editor content.
- API-024 PATCH /file/content saves file editor content.
- API-025 GET /mission lists Mission records.
- API-026 POST /mission/wake starts or resumes Mission.
- API-027 GET /gateway/stats returns Mission stats.
- API-028 GET /channel lists channels.
- API-029 GET /channel/runtime returns channel runtime status.
- API-030 POST /channel/runtime/restart restarts channel runtime.
- API-031 GET /log/tail returns log viewer tail content.

## 13. State ownership requirements
- STATE-001 pageMode store is the single source for Panel/Mission visibility.
- STATE-002 boardStore is the source for active task, task list, and board snapshot.
- STATE-003 cardTreeStore is the source for conversation cards.
- STATE-004 messageStore.chatRequest is the source for composer busy/stopping.
- STATE-005 settingsStore is the source for directory, theme, zoom, opacity, and pane widths.

- JOURNEY-007 Change workspace: user selects recent directory, project-scoped resources refresh, task list changes, Explorer resets, and old project data is not shown as current.
- JOURNEY-008 Respond to pending interaction: user sees pending interaction card/dialog, replies or rejects, board refreshes, and task resumes from server state.
- JOURNEY-009 Use titlebar settings: user opens provider/model/tool/channel configuration, sees load errors, saves through real APIs, and returns to workbench without losing task selection.
- JOURNEY-010 Use desktop launchers: user opens editor, terminal, or coding CLI from command dock, route uses selected directory, and unsupported profile errors are visible.
