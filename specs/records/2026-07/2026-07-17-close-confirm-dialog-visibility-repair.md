## Evidence and causal chain

1. Observable symptom: the close prompt shows a text field and a select field labeled `Input`; the first field receives the blue focus ring.
2. Direct trigger: `nativeConfirm` correctly opens `showAppDialog` with both `input` and `select` false, but the two always-mounted field roots do not receive the expected `hidden` class in the rendered application.
3. Root cause: `AppDialogHost` passes dynamic `classList` through the custom `TextField.Root` boundary. `TextField.Root` does not explicitly consume and reapply `classList`; it leaves it in a spread and then applies a separate canonical `class`. Solid's DOM `classList` directive semantics are not preserved by that generic component spread, so the primitive loses caller visibility classes.
4. Why the prior path did not catch it: source-shape tests assert primitive usage and store contracts, while current browser helpers infer visibility from `classList.contains("hidden")`; there is no dedicated confirmation-only browser assertion or close-dialog screenshot.

## Call-site disposition

| Surface                             | Decision                                                                                                                                                                                                |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TextField.Root`                    | Explicitly accept and apply caller `classList` together with the canonical `oc-text-field` class. This repairs the abstraction boundary for every owner without a close-dialog-specific selector.       |
| `AppDialogHost` confirm mode        | Keep the existing single store-backed path. The input and select roots remain mounted but must compute `display: none`; Kobalte retains its safe initial focus on Cancel for this destructive decision. |
| `AppDialogHost` prompt/select modes | Preserve the current input/select rendering and focus behavior; cover them alongside confirm mode so the fix cannot invert visibility.                                                                  |
| `provider-auth-panel.test.ts`       | Retain its workflow coverage; update only if the canonical visibility contract changes.                                                                                                                 |
| Window close lifecycle              | Preserve `onCloseRequested` prevention, localized copy, `nativeConfirm`, and canonical `quitOverlay` cleanup. No second close-dialog owner is added.                                                    |

## Codex review feedback

The first real-browser run disproved the plan's assumption that Quit should receive initial focus. After `AppDialogHost` queues its focus request, the canonical Kobalte modal applies its accessible focus management and selects the first safe footer action, Cancel. Because closing OpenCorvus is destructive, retaining Cancel as the effective initial focus is safer and avoids a feature override of the primitive. The acceptance criterion and browser assertion were revised explicitly; the failed run still proved that both unrelated fields now compute to `display: none`.
