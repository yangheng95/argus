OpenCorvus Agent Team Infrastructure

面向规模化智能交付的 Agent Team 架构画布

这张图从 CEO 视角表达 OpenCorvus 的核心资产：一个由唯一调度脊柱、可扩展 Agent 家族、Skill / MCP / Memory 能力织网、专家团与证据化交付闭环组成的智能作业平台。它不是单个自动化脚本，而是一套可持续扩张的组织级 Agent 基建。

阅读方式

从左到右看业务目标如何进入系统，从中心看 Agent Team 如何被统一调度和增强，从右侧看交付如何沉淀为证据、记忆和可审计资产。底部是架构单一来源，不是第二套流程。

1 唯一任务级调度者：Orchestrator 负责决策，避免多调度源分叉。
Role AgentRoleContract 统一描述 Agent 家族、工具面、技能挂载与协作边界。
Skill 通过 mounted_agents 精确挂载领域能力，能力可复用、可治理。
MCP MCP（Model Context Protocol，模型上下文协议）接入外部工具、资源和提示词。
A2A A2A（Agent-to-Agent，Agent 间协作）保留 durable request / response / action。
Trace Decision Log、engine_artifact、Trace、Bus、SSE 形成证据闭环。

战略运营视图

主图把 OpenCorvus 看作一个 Agent Team Operating System：上层承接目标，中层组织智能作业，下层沉淀记忆、证据和扩展能力。

运营模型：从目标到可审计交付

下面把主图拆成 CEO 能快速判断的经营含义：谁做决策、能力如何扩张、风险如何被看见。

目标进入
用户、Mission、工作区和任务请求进入同一 ChannelIngress；系统不把同一目标拆成不可见的双路消息。
统一调度
EngineService 唤起 Task Control Loop，Orchestrator 根据上下文、workflow hint 和证据做一次可见决策。
Agent 家族执行
Build、Research、Design、Visual QA、Integrity、Fact Check、Workload、Custom 等角色由 AgentRoleContract 描述职责和工具面。
能力增强
Skill 通过 mounted_agents 挂载到目标 Agent；MCP 接入外部工具和资源；专家团通过 PromptProfile 与 select_expert_squad 进入。
证据沉淀
Decision Log、engine_artifact、Trace、Bus、SSE 与 overlay projection 把过程变成可复盘的组织记忆。
Agent 家族 不是单一机器人，而是按职责拆分的智能作业团队；每个角色都有明确的工具、上下文和协作边界。
专家团 Frontend Replica、Frontend Innovate、Backend、Algorithm、Automation Debug 等作为 prompt profile 扩展，不改变底层调度事实。
Skill 把行业流程、检查清单、工具使用方式沉淀成可挂载能力，适合做组织知识复用和部门级标准化。
MCP 把外部系统作为工具、资源、prompt 接入，形成企业工具目录和数据接入层。
Workflow direct / pipeline 是声明式作业提示，不是固定状态机；Orchestrator 仍根据真实上下文做决策。
Memory DB（Database，数据库）、decision log 和 artifact 将经验变成可追踪资产，支撑复盘、训练和治理。

使用前景：从项目助手到组织级智能作业平台

规模化路径不靠复制流程，而靠扩展角色、技能、MCP 接入和证据运营能力。

现

当前可落地：任务级智能交付

围绕一个 Mission 组织多个 Agent 完成实现、调研、设计、验证和复核。

  • Orchestrator 可见调度
  • AgentRoleContract 统一角色事实
  • SkillTool 和 MCP 扩展能力
  • 可截图、可测试、可审计的交付证据
扩

下一阶段：领域能力复用

把高频行业场景沉淀成 skill packs、专家团模板和 MCP 工具目录。

  • 前端复刻、创新设计、自动化调试专家团
  • 企业工具和数据系统通过 MCP 接入
  • 组织级 Memory 支撑经验复用
  • Workflow hint 保持灵活，不固化为流程门
治

长期价值：智能作业治理层

每次 Agent 协作都留下可观察证据，形成管理者能理解的交付运营视图。

  • 从单任务效率提升到团队能力资产
  • 从“模型回答”升级为“证据化作业链”
  • 从工具集成升级为可审计智能组织
  • 从项目支持扩展到跨部门场景复制

架构单一来源锚点

这些锚点说明主图不是概念包装，而是对当前 OpenCorvus 架构事实的高层抽象。

AgentRoleContract 角色、工具面、skillMountable、workflow tool、A2A redispatch binding 的单一事实来源。
AgentToolPool 工具可见性、Orchestrator private tools、worker 请求 Orchestrator 决策能力的边界。
Skill Mount Matrix Skill 的 mounted_agents、canonical SkillTool、overlay mount projection 和技能读取路径。
MCP Boundary MCP 是协议扩展轴；它不同于 plugin，也不同于 executor，避免概念混用。
PromptProfile 专家团是 prompt profile 与可见 skill loading，不是 host 端关键词路由。
WorkflowRegistry direct / pipeline 是声明式 hint；调度仍由 Orchestrator 基于上下文判断。
A2A Protocol request / response / action 形成 durable coordination；子 Agent 提供证据，不替代任务级调度。
Evidence Plane Decision Log、engine_artifact、Trace、Bus、SSE 和 overlay projection 共同构成交付证据层。
