## Causal chain and design decision

1. Visible names are emitted by two existing title renderers: top-level and nested message agents use `ChatBubbleIdentity`, while structured nested Agent cards use `CardHeader`. Changing identity strings in the store would conflate presentation with canonical identity.
2. The correct uppercase boundary is therefore CSS presentation scoped to Agent-name selectors. Tool titles and message content remain untouched.
3. `CardHeaderChrome` already owns LLM metadata plus four control actions, but `ChatBubble` appends reply and copy beside it, while error copy sits as another sibling. The crowding is caused by split visual ownership, not missing data.
4. The existing Kobalte-backed `DropdownMenu` and Lucide-backed `more-horizontal` icon already define the project's accessible aggregate-action language. `CardHeaderChrome` should own one overflow trigger and menu, accepting the two Chat-specific callbacks as capabilities so it remains the only renderer.
5. Metadata remains a separate trigger because it is informational, frequently scanned, and already consolidates model, context, usage, and cost. All command actions move into the overflow menu with labels and icons; no command or state source is duplicated.
