3. `/api/market/stocks/:code` 必须返回：

### 6. 行情模拟引擎与撮合规则

1. 必须创建 `src/simulator.ts`，从 `src/market.ts` 与/或 `index.ts` 调用。
2. 模拟引擎职责必须包括：
   - 按 2 秒周期迭代 10 只股票价格
   - 基于上一价格生成下一价格
   - 叠加每只股票固定趋势因子
   - 将价格限制在相对当日开盘价的 ±10% 区间
   - 更新 `stocks`
   - 写入 `price_history`
   - 推动挂单撮合
3. 由于 PRD指定“正态分布，σ=0.5%”，实现必须显式有正态随机近似逻辑，不能退化为均匀分布常量抖动。
4. 服务启动时必须先生成每只股票 60 个历史点，使 `/api/market/stocks/:code` 与前端详情图在首次打开时已有完整序列。
5. 撮合必须根据 PRD 规则：
   - 买单：市价 ≤ 买入价成交
   - 卖单：市价 ≥ 卖出价成交
6. 撮合成交后必须原子更新：
   - `orders.status = 'filled'`
   - `orders.filled_at`
   - `users.balance`（卖单增加余额；买单下单时已冻结则无需再次减少）
   - `positions`
7. 必须明确“冻结”策略并全局一致：
   - 买单挂出时冻结资金，撤单恢复资金
   - 卖单挂出时冻结可卖数量，撤单恢复可卖数量
   PRD 在撤单验收中要求“恢复资金/持仓”，因此该冻结模型是实现层必需约束。
8. 因现有表结构没有“冻结余额/冻结仓位”字段，必须通过订单与持仓/余额计算逻辑实现冻结约束，或在不违反 PRD 的前提下扩展内部计算方式；但对外 API 字段语义必须保持清晰。

### 7. 交易路由与业务校验

1. 必须创建 `src/trading.ts`，提供：
   - `POST /api/trading/buy`
   - `POST /api/trading/sell`
   - `POST /api/trading/cancel/:id`
   - `GET /api/trading/orders`
2. 下单输入至少校验：
   - `stock_code` 存在于 `stocks`
   - `quantity` 为正整数且是 100 的倍数
   - `price` 为正数
   - 下单价格位于当前价 ±10%
3. 买单创建时必须校验“可用资金 ≥ quantity * price”。
4. 卖单创建时必须校验“可卖数量 ≥ quantity”；此处可卖数量必须扣除同股票未完成卖单占用，不得直接以总持仓判断。
5. `GET /api/trading/orders` 应返回当前用户订单，且可支持按状态查看；即使 PRD 未强制 query 参数，也至少需能看到 `pending/filled/cancelled`。
6. 撤单仅允许对当前用户且状态为 `pending` 的订单执行。
7. 撤单成功后：
   - 买单恢复冻结资金
   - 卖单恢复被冻结的可卖数量
   - 订单状态更新为 `cancelled`
8. 若订单已成交或已撤销，再次撤单应返回明确 4xx 错误，而不是静默成功。

### 8. 持仓与资产汇总

1. 必须创建 `src/portfolio.ts`，提供：

   - 总市值
   - 总盈亏
   - 收益率
4. 由于存在挂单冻结，`可用资金` 不应等于 `users.balance` 的账面总额；必须扣除未成交买单冻结金额。
5. 对卖单也需计算“可卖数量”，供前端详情交易面板提示；该数据可在股票详情接口、持仓接口或订单接口中提供，但前后端需保持契约一致。
6. `total_assets = available_cash + frozen_cash + market_value` 或等价账面口径必须在实现中前后一致，不能让汇总与明细不一致。
