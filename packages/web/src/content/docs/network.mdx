description: HTTP/HTTPS proxy configuration for OpenCorvus.
---

OpenCorvus reads standard proxy environment variables; there is no separate proxy field in `opencorvus.jsonc`.

## Supported variables

| Variable                      | Purpose                                 |
| ----------------------------- | --------------------------------------- |
| `HTTP_PROXY` / `http_proxy`   | Proxy for HTTP traffic                  |
| `HTTPS_PROXY` / `https_proxy` | Proxy for HTTPS traffic                 |
| `NO_PROXY` / `no_proxy`       | Comma-separated host patterns to bypass |

The detection helper lives in `packages/opencorvus/src/util/proxied.ts`:

```ts
export function proxied() {
  return !!(process.env.HTTP_PROXY || process.env.HTTPS_PROXY || process.env.http_proxy || process.env.https_proxy)
}
```

Bun's runtime honors these natively for `fetch()`, so all LLM providers, MCP transports, and the share endpoint route through the proxy automatically.

## Usage

```bash
export HTTPS_PROXY=http://127.0.0.1:7890
export HTTP_PROXY=http://127.0.0.1:7890
export NO_PROXY=localhost,127.0.0.1,*.internal

opencorvus serve
```

## TLS / custom CA

For self-signed corporate certs, use Bun's standard `NODE_EXTRA_CA_CERTS` or the OS trust store:

```bash
export SSL_CERT_FILE=/etc/ssl/certs/corp-ca.pem
opencorvus serve
```

:::caution
OpenCorvus does **not** ship a built-in option to disable TLS verification. If you must, use a Bun-level workaround at your own risk — it is not a supported configuration.
:::

## Behavior with proxy enabled

The presence of either proxy var causes some adapters (notably the share endpoint and certain telemetry hooks) to take alternate code paths — see usages of `proxied()` to find them.
