=============

### 1.2 运行方式

```bash
# 全部测试
bun test

# 仅单元测试

# 仅集成测试
bun test tests/integration/

# 仅指标测试
bun test tests/unit/indicators/

# 单个文件
bun test tests/unit/indicators/macd.test.ts
```

### 1.3 测试原则

1. **单元测试是纯函数测试**：不启动服务器、不访问数据库、不依赖网络。
   直接 import 计算函数，传入数据，断言输出。
2. **集成测试启动真实服务**：在 `beforeAll` 中启动 Hono server + SQLite（内存数据库），
   在 `afterAll` 中关闭。每个 test file 独立数据库实例，互不干扰。
3. **数值断言使用容差**：浮点计算的断言使用 `toBeCloseTo(expected, 4)`
   （小数点后 4 位精度，即误差 < 0.00005）。
4. **不 mock 任何内部模块**：直接测试真实代码路径。
5. **每个 test case 独立**：不依赖其他 test case 的执行顺序或副作用。

### 2.2 手算基准值

以下是基于 OHLCV_10 数据集的手算基准值，作为 expected 值写入测试用例。

#### MA5 (close 的 5 周期简单移动平均)

```
bar 1~4: null (数据不足)
bar 5:  (10.20 + 10.40 + 10.30 + 10.10 + 10.35) / 5 = 10.27
bar 6:  (10.40 + 10.30 + 10.10 + 10.35 + 10.60) / 5 = 10.35
bar 7:  (10.30 + 10.10 + 10.35 + 10.60 + 10.50) / 5 = 10.37
bar 8:  (10.10 + 10.35 + 10.60 + 10.50 + 10.15) / 5 = 10.34
bar 9:  (10.35 + 10.60 + 10.50 + 10.15 + 10.25) / 5 = 10.37
bar 10: (10.60 + 10.50 + 10.15 + 10.25 + 10.55) / 5 = 10.41
```

expected: `[null, null, null, null, 10.27, 10.35, 10.37, 10.34, 10.37, 10.41]`

#### MA10

```
bar 1~9: null
bar 10: (10.20+10.40+10.30+10.10+10.35+10.60+10.50+10.15+10.25+10.55)/10 = 10.34
```

expected: `[null, null, null, null, null, null, null, null, null, 10.34]`

#### EMA5 (k = 2/(5+1) = 1/3)

```
bar 1~4: null (用 SMA 启动)
bar 5:  SMA5 = 10.27 (首值)
bar 6:  10.60 × (1/3) + 10.27 × (2/3) = 3.5333 + 6.8467 = 10.38
bar 7:  10.50 × (1/3) + 10.38 × (2/3) = 3.5000 + 6.9200 = 10.42
bar 8:  10.15 × (1/3) + 10.42 × (2/3) = 3.3833 + 6.9467 = 10.33
bar 9:  10.25 × (1/3) + 10.33 × (2/3) = 3.4167 + 6.8867 = 10.30
bar 10: 10.55 × (1/3) + 10.30 × (2/3) = 3.5167 + 6.8667 = 10.3833
```

expected: `[null, null, null, null, 10.27, 10.38, 10.42, 10.33, 10.30, 10.3833]`

（精度到 4 位小数，断言 toBeCloseTo(x, 2)）

#### BOLL (N=5, K=2)

基于 MA5 和标准差：

```
bar 5: MA=10.27
  偏差: [10.20-10.27, 10.40-10.27, 10.30-10.27, 10.10-10.27, 10.35-10.27]
       = [-0.07, 0.13, 0.03, -0.17, 0.08]
  方差: (0.0049+0.0169+0.0009+0.0289+0.0064)/5 = 0.0580/5 = 0.0116
  σ = sqrt(0.0116) = 0.1077
  上轨 = 10.27 + 2×0.1077 = 10.4854
  下轨 = 10.27 - 2×0.1077 = 10.0546
```

bar 5 expected: `{ mid: 10.27, upper: 10.4854, lower: 10.0546 }`

（后续 bar 同理，测试中验证 bar 5~10 的 6 组值）

describe("撮合引擎")
  describe("买单撮合")
    test("市价 ≤ 买入价时立即成交")
      setup: 买单 price=10.50，当前市价跌到 10.40
      expected: 订单状态 → filled, filled_at 有值

    test("市价 > 买入价时不成交")
      setup: 买单 price=10.50，当前市价 10.60
      expected: 订单保持 pending

    test("市价 = 买入价时成交（边界）")
      setup: 买单 price=10.50，市价=10.50
      expected: filled

  describe("卖单撮合")
    test("市价 ≥ 卖出价时立即成交")
      setup: 卖单 price=10.50，市价涨到 10.60
      expected: filled

    test("市价 < 卖出价时不成交")
      setup: 卖单 price=10.50，市价 10.40
      expected: pending

    test("市价 = 卖出价时成交（边界）")
      expected: filled

  describe("撮合后资金更新")
    test("买单成交：解除冻结资金，扣减余额 = 成交价 × 数量（非冻结价 × 数量）")
      setup: 以 10.50 挂买单 100 股，冻结 1050
             以 10.40 成交
      expected:
        frozen_balance -= 1050（全额解冻）
        balance 不再额外扣减（挂单时已扣）
        如果成交价 < 挂单价，差额返还可用余额

    test("卖单成交：余额增加 = 成交价 × 数量")
      setup: 以 10.50 卖出 100 股
      expected: balance += 10.50 × 100 = 1050

  describe("撮合后持仓更新")
    test("买单成交：持仓数量增加，可卖数量增加")
      setup: 买入 100 股成交
      expected:
        position.quantity += 100
        position.available_quantity += 100

    test("卖单成交：冻结的可卖数量释放，持仓总量减少")
      setup: 持有 500 股，挂卖 200 股（available 降到 300），成交
      expected:
        position.quantity = 300
        position.available_quantity = 300（冻结已在挂单时扣减）

  describe("撮合后成本价更新")
    test("首次买入：成本价 = 成交价")
      setup: 空仓，买入 100 股 @ 10.50
      expected: cost_basis = 10.50

    test("加仓：成本价 = 加权平均")
      setup: 持有 100 股 @ 10.50，再买 200 股 @ 10.80
      expected: cost_basis = (10.50×100 + 10.80×200) / 300 = 10.70

    test("卖出不改变成本价")
      setup: 持有 300 股 @ 10.70，卖出 100 股
      expected: cost_basis 仍为 10.70

    test("清仓后重新买入，成本价为新买入价")
      setup: 全部卖出 → 再买入 100 股 @ 11.00
      expected: cost_basis = 11.00

  describe("批量撮合")
    test("同一价格变动触发多个挂单同时成交")
      setup: 3 个不同用户的买单都满足条件
      expected: 3 个都成交，各自资金/持仓独立更新

    test("同一用户的多个挂单同时成交")
      setup: 用户有 2 个不同价格的买单，市价同时满足
      expected: 2 个都成交

  describe("已成交/已撤销订单不参与撮合")
    test("filled 订单不再被触发")
    test("cancelled 订单不再被触发")

## 九、验收标准

1. `bun test` 全部通过（0 failures）
2. 单元测试执行时间 < 5 秒（纯计算，不含 IO）
3. 集成测试执行时间 < 30 秒
4. 浮点精度断言一致使用 `toBeCloseTo(x, 2)`（小数点后 2 位，即误差 < 0.005），
   仅在手算验证值精确到 4 位时使用 `toBeCloseTo(x, 4)`
5. 不存在 `test.skip` 或 `test.todo`
6. 每个 test case 独立可运行（不依赖其他 case 的顺序或副作用）
7. 集成测试使用内存 SQLite，不写入磁盘文件
8. 不 mock 内部模块，直接测试真实代码路径
