## Causal chain

1. The visible badge is truthful: it is projected from the database row that is still `pending`, and the Mission badge aggregates the child Task count.
2. `InteractionDialogHost` keeps one persistent Kobalte `Dialog` root while only the nested `InteractionCard` is keyed by interaction identity.
3. The host's `onClose` callback reads the reactive `current()` at callback time. When the first resolution refresh changes `current()` from interaction A to B while the same Dialog root is retained, a close request owned by A's retiring surface can observe B and add B to `dismissed`.
4. `pickDialogInteraction` then excludes B while B remains canonically pending. The popup disappears, but the Work Ledger correctly continues to display one pending badge; hiding or clearing that badge would only mask the unresolved interaction.
5. The root repair is to key the complete Dialog lifecycle by interaction identity and close over that exact identity. The retired Dialog can then affect only A, while B receives a fresh Kobalte root and fresh card state.

The exact stale-close timing remains a browser-lifecycle hypothesis until reproduced on the real page. The identity mismatch itself is proven statically: the root is unkeyed and `onClose` dereferences mutable `current()` rather than the rendered interaction.
