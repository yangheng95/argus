## Root cause

The public SDK has several legality functions but no one package-level contract. `renderExpertSquadPackageFiles()` directly calls one manifest dispatch validator and then a private file-layout validator. This means callers cannot validate a complete in-memory definition through one named API, required README/selector/prompt entrypoints are not rejected until the later Registry pass, and the same workflow legality is implemented separately in SDK and Registry. The creation call graph is already narrow, but its validation ownership is fragmented.

## Implementation

| Surface                | Change                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| SDK validation suite   | Add `validateExpertSquadPackageDefinition()`. It validates manifest workflow topology and dispatch semantics, generated-manifest ownership, canonical/collision-free file layout, and required README/selector/prompt entrypoint existence, UTF-8 text type, non-blank content, and canonical owner path. Return the original definition after success; do not write files or maintain state.                                                                                                                                                                |
| Dispatch topology      | Keep `validateExpertSquadManifestDispatchTopology()` as the single shared semantic primitive. It rejects non-canonical workflow/node identities, unsorted or duplicate dependencies, unknown workflow agents/dependencies, self-dependencies, cycles, reserved worker identities, and invalid Goal/Integrity lineage. Do not hand-copy manifest metadata, configuration, version, runtime-template, or resource schemas into the SDK; Registry remains their only validator.                                                                      |
| SDK render/write hook  | `renderExpertSquadPackageFiles()` calls the package validator and renders only its validated entries. `writeExpertSquadPackage()` remains the sole materializer and reaches the validator only through render, so there is one execution path and validation happens before destination creation.                                                                                                                                                                                                                                                            |
| Registry single source | Import the SDK dispatch-topology function and remove the duplicate workflow graph/Goal/Integrity implementation from `ExpertSquadRegistry`; retain Registry-only strict schema, version, configuration, runtime-template, tool, Skill, MCP, orphan-resource, and installed-folder checks.                                                                                                                                                                                                                                                                      |
| Creation callers       | Keep portable template generation and Multica import on `writeExpertSquadPackage`; add call-graph regression assertions. Update the portable authoring Skill and public English/Chinese docs to name the package validator and state that every new package must use the writer.                                                                                                                                                                                                                                                                             |
| Tests                  | Add SDK unit tests for each validation family and for no-directory creation after failure; keep round-trip suites for Mirror, Research Studio, Review & Debug, portable template, and Multica; add architecture residue checks that prevent direct package writers or duplicate Registry workflow rules.                                                                                                                                                                                                                                                     |
