# v0.0.29beta Windows Native Matrix Package

## Recall

### 用户原始要求

- 对当前 OpenCorvus 交付线进行矩阵打包。

### 验收指标

- 从仓库唯一版本来源确认版本，不从分支名猜测版本。
- 严格先运行 GUI（Graphical User Interface，图形用户界面）installer matrix，再运行 CLI（Command-Line Interface，命令行界面）binary matrix。
- 只声明当前 Windows x64 主机原生构建并由真实 checker 接受的 row；Linux 与 macOS row 必须明确 skipped。
- 独立复核产物名称、版本、PE（Portable Executable，Windows 可移植可执行文件）架构、文件大小和 SHA-256（Secure Hash Algorithm 256-bit，256 位安全散列算法）。
- 记录最终 Git 来源并将验证证据提交、推送到 git-cc 的 `myhexin` remote。

### 硬约束

- `bun run package:gui-installer-matrix` 与 `bun run package:binary-matrix` 是唯一产物所有者，不手工拼装、复制或伪造非本机平台产物。
- 不使用 `--skip-build`，不创建 worktree，不 stash、reset、restore，不绕过 Git hooks。
- 不新增、修改、更新或运行 UI 自动化测试。
- 不重启、刷新、关闭或干预用户正在运行的 OpenCorvus/Overlay。
- 生成的安装包与二进制是 ignored release output，不纳入源码提交。

### 全仓 grep 结果

| 契约 | 唯一所有者 / 处理 |
| --- | --- |
| GUI installer matrix | 根 `package.json` 调用 `script/package-gui-installer-matrix.ts`；当前主机只可构建并验证 `windows-x64`。 |
| Portable CLI matrix | 根 `package.json` 调用 `script/package-binary-matrix.ts`，并由 `script/package-native-binary.ts` 构建、执行、归档当前原生 row。 |
| Release asset validation | 两个 matrix owner 均调用 `script/check-release-assets.ts`；交付后再次独立运行同一 checker 验证最终目录。 |
| 非本机平台 | Linux x64/ARM64 与 Darwin x64/ARM64 只能由匹配的原生 runner 验证，本次必须报告 skipped。 |

### 独立 Agent 反馈

- 用户未要求子 Agent、委托或并行审计；本次不启动子 Agent，主 Agent 负责执行与二次复核。

## Plan

1. 提交并推送本 Recall，使打包源成为 git-cc 上可追溯的不可变提交。
2. 从该提交运行 GUI installer matrix，不使用跳过构建的捷径。
3. GUI 成功后运行 portable CLI binary matrix。
4. 独立执行 release checker，检查 executable 版本与 PE machine，计算所有最终产物大小和 SHA-256。
5. 再次 fetch `myhexin/v0.0.29beta`；若远端新增生产输入则先合并并重打，若只新增记录则如实记录来源边界。
6. 将结果写回本记录，运行文档健康检查、提交、推送，并确认本地与远端相等。
