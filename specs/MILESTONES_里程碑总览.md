## 一、产品定义

### 1.1 愿景

让金融从业者用自然语言发起"数据查询 + 代码编写"的复合任务，在同一个对话流中得到可执行的结果，无需在任何外部工具之间切换。

### 1.2 北极星指标（HTCR）

**混合任务闭环率**：用户发出包含金融数据意图的编程请求，工具在不追问、不切换工具的情况下，一次性完成数据获取 + 代码生成 + 结果呈现的比率。

测量方法：
- 测试集：S01-S05 各 20 条标注指令（共 100 条），不公开给研发
- 判定规则：≤3 轮完成 + 工具调用参数正确 + 输出含结构化内容 + 无占位符
- 数据源超时不计入分母

目标：M0.5 ≥ 55% → M1 ≥ 70%

辅助指标：工具调用成功率 ≥ 95%、代码复制率 ≥ 60%、会话均轮次 ≤ 3、7 日留存 ≥ 40%、意图识别准确率 ≥ 90%

### 1.3 用户角色

| 角色 | 特征 | 核心痛点 | 对应场景 |
|---|---|---|---|
| **A：量化研究员** | 每天写 Python，熟悉 pandas/numpy/backtrader，理解 IC/因子暴露/Sharpe | 数据获取与代码编写分离，缺乏领域专用错误提示 | S02 S03 S04 |
| **B：基本面分析师** | 财务建模为核心，Python 能力参差不齐 | 拉数据、清洗、建模三件事重复耗时 | S01 S05 |
| **C：风控工程师** | VaR、压力测试、风险归因，需快速引用历史行情 | 风控代码可复用性差，历史情景数据拉取繁琐 | S03 S04 |
| D：投研实习生 | 使用门槛更低 | — | — |
| E：基金经理助理 | 不写代码，需快速获取分析结果 | — | — |

**非目标用户**：纯软件工程师（非金融）、个人散户、通用 ML/AI 数据科学家。

### 1.4 核心场景

| 场景 | 用户输入 | 期望行为 | 覆盖模块 |
|---|---|---|---|
| **S01** 财报可视化 | "帮我用过去三年茅台的季报数据算一下 ROE 趋势，并画出来" | 自动调用财报工具 → 生成 Plotly 代码（数据内联）→ 渲染图表 + 趋势解读 | M01 M02 M05 M03 M07 |

### 1.5 能力边界（不做什么）

以下 6 条红线适用于全部里程碑，任何里程碑 PRD 不得违反：

1. **不提供投资建议**：不出现"建议买入/卖出/持有"。市场分析类输出必须附 disclaimer。
2. **不执行交易指令**：不接入交易所或经纪商 API，无委托下单功能。
3. **不自主修改生产代码**：所有代码修改由用户手动执行或复制，工具不操作用户代码仓库。
4. **不存储用户金融数据**：数据仅在会话生命周期内流转，不持久化到产品数据库。
5. **不支持非金融领域通用编程**：Web 开发、通用 ML、DevOps 不在服务范围。
6. **不做实时交易监控**：不提供 tick 级推送、实时 PnL 监控（第一阶段）。

### 1.6 设计原则

| 编号 | 原则 | 正例 | 反例 |
|---|---|---|---|
| P1 | **意图优先于模式切换** | 用户说"画茅台 ROE 趋势"，自动完成数据 + 代码 + 渲染 | 用户必须先点"数据模式"查数据，再切"代码模式" |
| P2 | **工具调用透明化** | 财报数据旁显示"来源：tushare · 截至 2024Q3" | 数据直接出现，不知来源 |
| P3 | **输出即可用** | 代码已内联实际数据，直接复制能跑 | 代码中大量 `YOUR_TICKER`、`TODO` |
| P4 | **金融错误优于代码错误** | KeyError → "可能是列名大小写不一致" | 仅输出 "KeyError at line 12" |
| P5 | **最小必要上下文** | "最新一期"自动对应最近财报期，不追问 | 先问"哪个财报期？"再问"股票代码？" |

### 1.7 词汇表

| 术语 | 定义 |
|---|---|
| 会话（Session） | 用户打开对话到关闭的生命周期，独立上下文 |
| 轮次（Turn） | 一条用户消息 + 一条完整回复 |
| 意图（Intent） | 代码意图 / 数据意图 / 混合意图 |
| 工具调用（Tool Call） | 向外部数据源发起的查询请求 |
| 代码生成（Code Generation） | 输出代码文本，不含执行 |
| 代码执行（Code Execution） | 在沙箱中运行代码并返回结果 |
| 任务（Task） | 用户一个完整分析需求，可能跨多轮 |
| 混合意图（Hybrid Intent） | 单条输入同时包含数据查询和代码编写需求 |
| 财报期（Reporting Period） | 如 2024Q3 / FY2024 |
| 标的（Instrument） | 可被查询和分析的金融对象 |
| 技术指标（Technical Indicator） | 基于价量计算的衍生数据（MA/MACD/RSI 等） |
| 沙箱（Sandbox） | 隔离的代码执行环境，无网络无文件系统 |
| 数据源（Data Source） | 提供金融数据的外部系统（tushare/akshare/Wind） |
| 渲染（Render） | 将数据转化为图表/表格/富文本展示的过程 |

## 三、使用方式

将对应的里程碑 PRD 文件**完整输入**给 AI 模型。每个 PRD 是自包含的：

1. 该阶段的目标与验收标准
2. 完整的文件创建顺序
3. 每个文件的完整代码（内联，非引用）
4. 集成陷阱
5. 验证检查点

一个 PRD 文件 = 一次完整的实现输入。模型不需要读其他文件。

```
specs/
├── MILESTONES_里程碑总览.md    ← 本文件（产品上下文 + 索引）
├── M0-1_基础层.md              ← 第 1 步
├── M0-2_UI层.md                ← 第 2 步
├── M05_Real接入.md             ← 第 3 步
├── M1_完整产品.md              ← 第 4 步
└── M2_商业化.md                ← 第 5 步
```
