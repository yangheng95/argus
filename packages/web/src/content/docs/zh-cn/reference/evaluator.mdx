per-goal build attempt 产出 verification evidence，pipeline 的最终复核是 `integrity` workflow tool。

## 当前复核流程

1. **Build evidence**：direct build 或 per-goal build 写入 run / goal-run artifacts、changed files、reports 和可选 verification evidence。
2. **Acceptance / evaluation artifacts**：`engine_artifact.kind="acceptance"` 与 `engine_artifact.kind="verification-evidence"` 保存 acceptance 与 check evidence，供 replay 使用。
3. **Integrity review**：integrity agent 读取用户请求、requirements、architect contract graph、goal outputs、diffs、runtime/visual evidence、历史 attempts 与 acceptance evidence。
4. **Orchestrator decision**：integrity 返回 pass 或 non-pass 证据。orchestrator 决定完成、modify goals、重新 build、回到 architect、询问用户或 fail task。

## Evaluation Row 形态

`EvaluationRow` 从 `engine_artifact.kind="verification-evidence"` 重建：

```typescript
type EvaluationRow = {
  scope: "goal_run" | "acceptance"
  status: "pending" | "passed" | "failed" | "inconclusive"
  verdict: "accepted" | "rejected" | "inconclusive"
  checks: EngineEvaluationCheck[] | null
}
```

checks 是给 operator 与后续 review 使用的审计证据。

## Integrity Verdict 语义

| Integrity outcome | Orchestrator 含义 |
|---|---|
| pass | 集成系统满足本任务；orchestrator 可以完成任务。 |
| non-pass 且有 blocking findings | orchestrator 必须基于证据把修复路由到 build、`modify_goal`、`architect` 或用户问题。 |
| thrown / artifact missing | orchestrator 会收到可见失败证据并决定恢复；UI 不应静默显示空卡片。 |

## 配置说明

Agent 模型与 step 预算分别配置在 `agent.integrity.*` 与 `assistant.integrity.*`。视觉验收阈值位于 engine config 的 `assistant.acceptance_visual`。
