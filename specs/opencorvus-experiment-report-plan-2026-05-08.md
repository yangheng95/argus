## 4. 指标体系

### 4.1 代码规模与结构

真实计算：

- 源码总行数：排除 `node_modules`、`dist`、构建缓存、锁文件、图片、数据库。
- 业务源码行数：统计 `src`、`web/src`、`index.ts`、`tests` 等。
- 平均代码行数：按同一类项目集合计算均值、中位数、最大值、最小值。
- 文件数、目录深度、模块数量。
- 测试行数与测试占比。

### 4.2 可运行性

建议 0-20 分：

| 项 | 分值 |
| --- | --- |
| 依赖安装成功 | 4 |
| 构建成功 | 4 |
| 服务可启动 | 4 |
| 首页可访问且非白屏 | 4 |
| 无明显 console error | 4 |

### 4.3 需求覆盖率

从 PRD 抽取验收项，按证据打分：

- 2 分：真实实现并经运行/代码证据确认。
- 1 分：有 UI 或代码痕迹，但链路不完整。
- 0 分：未实现或无法确认。

AI Chat 与股票交易分别建立独立清单，避免跨产品混算。

## 5. 股票交易 baseline 对比方案

对比对象：

- baseline：`demos\baseline-opus-4-7`
- OpenCorvus：`demos\PRD2Code-股票交易`

对比维度：

1. 代码规模：总行数、前后端行数、测试行数、文件数。
2. 启动质量：安装、构建、启动、端口可访问、白屏/错误。
3. 后端完整度：Hono 路由、SQLite schema、认证、订单、持仓、行情、SSE、风控。
4. 前端完整度：行情首页、个股详情、交易面板、持仓、记录、热力图、新闻、响应式。
5. 测试：PRD 20 条 API 测试覆盖情况与实际通过情况。
6. UI/UX：Apple 风格 token、毛玻璃、涨跌色、图表、动画、交易信息密度。
7. 交易闭环：注册 -> 登录 -> 查看行情 -> 下单 -> 撤单/成交 -> 持仓 -> 记录。
8. 风控与数据一致性：资金冻结、可卖数量、价格限制、用户隔离。

最终输出一张详细矩阵表，并配至少 2-4 张关键截图说明差异。

## 8. 执行检查点

1. 完成需求/prompt 证据表后，先复核是否遗漏项目。
2. 完成代码统计后，抽样核对排除规则是否误算 `node_modules` / `dist`。
3. 完成项目启动后，复核端口表和截图是否一一对应。
4. 完成指标计算后，复核每个分数是否有证据。
5. 完成 PPTX 后，导出 PNG 逐页检查文字溢出、遮挡、截图清晰度。
6. 二次 review：检查报告结论是否被单个工具错误带偏，是否真实回答“项目生成能力”。

## 9. 风险与处理原则

- 项目未全部就绪：报告如实标注“未就绪/无法启动/缺少 prompt 证据”，不补造结果。
- 依赖或启动失败：先确认是否是项目契约问题、环境问题或端口问题，并把证据写入报告。
- 视觉相关结论：必须来自真实浏览器截图。
- 指标不能只给主观评价：每个评分项必须能回溯到代码、测试、运行截图或 PRD 验收项。
- 不修改生成项目源码来提高评分；本报告评估的是当前生成结果。
