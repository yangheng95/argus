## Causal analysis

The backend-to-overlay message projection already preserves the exact owning `goalID`, and the TaskBoard snapshot already preserves the corresponding `orderIndex` and `retryCount`. The missing correlation is purely at the title renderer: `ChatBubbleIdentity` currently renders avatar, agent identity, status, time, and duration, while `CardHeader` renders the structured-card title without consuming Goal ownership. Deriving a label from the title or session ID would create a second identity source; the correct repair is to join the existing `CardNode.goalID` to `boardStore.board.goals` at one shared presentation component.

## Implementation plan

1. Extend the existing Goal-label utility with a board-goal projection helper that preserves the same index/retry defaults already used by `TaskProgressBar`, and cover found, missing, and non-array cases.
2. Add one shared conversation Goal badge component backed by the TaskBoard store and the existing `Badge` primitive. It renders nothing when the card has no matching Goal.
3. Mount that shared badge after the title in both `ChatBubbleIdentity` and `CardHeader` for agent cards only. Let the existing small neutral Badge primitive own its geometry instead of adding a parallel one-off style.
4. Add source contracts for both render paths, the single shared owner, primitive usage, placement order, and non-Goal behavior. Extend the existing real agent-card fixture with goal-owned and unowned cards, then add a focused browser test that measures and screenshots the title region.
5. Run focused tests, Overlay typecheck/build, the Node-launched browser fixture, spec/document health, `git diff --check`, and a second ownership/diff review. Stage only this task's files, commit, and push the current branch to `myhexin`.
