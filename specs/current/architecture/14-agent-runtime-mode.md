Agent runtime mode is a data/runtime boundary. Current code does not implement
separate `SessionAgent` and `PipelineAgent` class families; it uses agent
metadata, prompts, session runtime, and orchestrator dispatch tools.

## Current Modes

| Mode                     | Runtime owner                                                  | Examples                                                                                                                                                                 |
| ------------------------ | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Interactive/session role | `runAgentSession` plus session loop/LLM runtime                | `coding`, `general`, `explore`, `build` when started as a direct coding session                                                                                          |
| Workflow specialist      | Orchestrator dispatch tool creates a scoped session and prompt | `requirements`, `architect`, `frontend-design`, `frontend-research`, `goal-workload-analyst`, `visual-qa`, `integrity`, `fact-check`, `deep-research`, `intent-analysis` |
| Orchestrator root        | `orchestrator/agent.ts` and `createOrchestratorTools`          | Task control loop, workflow dispatch, interactions, goal/task control                                                                                                    |
| Utility/system role      | Specialized session/runtime helpers                            | `compaction`, `title`, `summary`, `mission`, `control`                                                                                                                   |

The mode controls context construction, prompt source, tool surface, and
session ownership. It is not a frontend-only label.

## Context Strategy

- Root/orchestrator context comes from task state, decision log, workflow
  projection, and operator messages.
- Specialist context is scoped by task, stage, decision-log records, and
  stage-specific evidence.
- Direct session context comes from conversation history, selected directory,
  permissions, tools, and model configuration.
- Compaction/title/summary contexts are generated by their dedicated runtime
  entrypoints.

Any new mode must document its context source and tests. Do not infer runtime
mode from display text alone.

## Budget And Tool Policy

- `Agent.Info` and config own per-agent defaults such as model/prompt/tool
  settings.
- `AgentToolPool` and agent metadata decide visible tools for ordinary agents.
- Orchestrator tools create workflow-specific sessions and may add session
  permission rules for that child session.
- Long-running checks must use the inactivity-timeout process helper when they
  spawn external commands.

## Current Non-Goals

- No separate class hierarchy is the runtime source of truth.
- No hidden mailbox protocol is current.
- No compatibility layer maps retired planner/evaluator roles into active
  roles.
- No non-streaming LLM path is documented as valid for current agent runtime.
