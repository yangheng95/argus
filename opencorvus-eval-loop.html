验收层 · Per-Goal Autonomous Judge
🔍 EvaluatorAgent · per-goal.ts
自主评估，无预定义检查项 · 读代码 → 推断检查 → 执行 → 产出裁决
评估执行序列 · max_steps=30 · timeout=5min
1
读取源码 — 逐文件检查 changedFiles，理解实现意图与数据流
2
验证 owned_paths — 检测是否修改了 Goal 边界外的文件，违规即 REJECT
3
推断检查策略 — 根据代码类型自动选择验证手段：
React/Vue → build 检查  ·  后端服务 → 接口测试  ·  库代码 → 单元测试
4
run_command 执行检查 — 运行 build / test / lint / verify_cmd
5
done_definition 对照 — 逐条核查 Goal 的完成定义，收集具体 evidence（文件路径 + 行号 + 断言结果）
6
Goal Judge (judge.txt) — 严格基于证据评分，拒绝"测试通过"等模糊表述
7
输出结构化裁决 — EvalVerdict: verdict + confidence + evidence[] + failureClass + replan_guidance

🧭 ReplanGuidance · 优化反馈
🔍
root_cause
技术层面真实原因
e.g. "WebSocket 消息序列化未处理 bigint 类型"
💥
what_failed
具体失败的交付部分
e.g. "实时行情 WebSocket 推送断连"
🎯
suggested_strategy
下次尝试的不同方向
e.g. "改用 JSON.stringify replacer 显式转换"
🚧
avoid_approaches
已尝试且失败的方案列表
Build Agent 必须跳过这些路径
ReplanGuidance 流转链路
EvaluatorAgent
↓ replan_guidance
PlannerAgent
↓ new GoalContract (avoid_approaches 注入)
Build Agent
↓ 新 worktree + 新策略
EvaluatorAgent (再次验收)
⚖ Judge · 核心评判规则
1️⃣
仅凭证据判断
禁止采纳 Agent 自我评估
2️⃣
保守原则
存疑时判为未达成
3️⃣
调查后再判
证据模糊时必须用工具读取源码
4️⃣
具体 nextStep
必须给出精确文件路径 + 行号 + 修改内容
5️⃣
Deadlock 检测
重复错误 / 无效循环 → 立即 REJECT
GOOD evidence:
"read_file src/ws.ts:42 — bigint 转换
缺少 replacer，导致 JSON 序列化失败"

BAD evidence (拒绝):
"Tests pass" · "代码看起来正确"
"功能应该可以工作"
