---
title: Plugins（插件）
description: 用 TypeScript 编写插件，hook 进 OpenCorvus 的工具、LLM 请求与评估流水线。
---

Plugin 是 OpenCorvus 的深层扩展机制。与 Skill（通过 `skill` 工具显式加载 Markdown 工作流）不同，Plugin 是 TypeScript/JavaScript 代码，可在运行时 hook 进核心事件链——注册工具、修改 LLM 请求参数、拦截权限检查、订阅评估结果，甚至完整替换评估分析流程。

源码：`packages/opencorvus/src/plugin/index.ts`、`packages/plugin/src/index.ts`（接口）

## 1. Plugin vs Skill

| 维度 | Skill | Plugin |
|---|---|---|
| 实现 | Markdown + YAML | TypeScript/JavaScript 模块 |
| 加载 | agent 调用 `skill` 工具加载 | 服务启动时，全局常驻 |
| 能力 | 给 agent 提供可加载工作流 | hook LLM 请求 / 注册工具 / 拦截事件 / 扩展评估 |
| 门槛 | 零代码 | 实现 `Plugin` 函数接口 |

## 2. 默认插件

### `opencode-anthropic-auth`（npm）

启动时自动安装加载（`src/plugin/index.ts:18`）：

```typescript
const BUILTIN = ["opencode-anthropic-auth@0.0.13"]
```

为 Anthropic 模型提供 OAuth 认证流程。无 npm 环境（CI / 开发）必须禁用（见第 6 节）。

### GitLab Auth（内部）

`@gitlab/opencode-gitlab-auth` 编译时静态导入，无需 npm（`src/plugin/index.ts:12-23`）。

## 3. 加载流程

`Plugin.state()`（`src/plugin/index.ts:25-102`）：

1. 加载 `INTERNAL_PLUGINS`（GitLab Auth）
2. 若未设 `OPENCORVUS_DISABLE_DEFAULT_PLUGINS`，前置 `BUILTIN`
3. 合并 config 的 `plugin` 数组，逐项：
   - `file://` 前缀 → 直接 `import()`
   - 否则 → `BunProc.install(pkg, version)` 后 `import()`
4. 对每个导出的 Plugin 函数，调用 `fn(ctx)` 得到 `Hooks` 对象推入全局 hooks

```typescript
// packages/plugin/src/index.ts:35
export type Plugin = (input: PluginInput) => Promise<Hooks>
```

## 4. 编写自己的 Plugin

```bash
bun add @opencorvus-ai/plugin
```

```typescript
// my-plugin.ts
import { Plugin, tool } from "@opencorvus-ai/plugin"

export const MyPlugin: Plugin = async (ctx) => {
  return {
    tool: {
      my_tool: tool({
        description: "说明这个工具做什么",
        args: { query: tool.schema.string() },
        async execute(args) { return `结果：${args.query}` },
      }),
    },

    "chat.params": async (_input, output) => { output.temperature = 0.3 },

    "permission.ask": async (request, output) => {
      if (request.permission === "bash" && request.patterns[0]?.startsWith("echo")) {
        output.status = "allow"
      }
    },

    "evaluation.checks": async (_input, output) => {
      output.checks.push({
        name: "my-check",
        mode: "soft",
        run: async () => ({ status: "passed", evidence: "ok" }),
      })
    },

    "acceptance.ready": async (input, output) => {
      output.actions.push({ name: "notify", status: "ok", summary: "通知已发" })
    },
  }
}
```

## 5. 全部 Hooks

完整列表见 `packages/plugin/src/index.ts:148-337`。常用：

| Hook | 时机 |
|---|---|
| `event` | 任意 Bus 事件发布 |
| `config` | 配置加载后 |
| `tool` | 静态注册额外工具 |
| `auth` | provider 认证扩展 |
| `chat.message` | 收到新消息 |
| `chat.params` | LLM 请求参数构建后、发送前 |
| `chat.headers` | LLM HTTP 头构建后 |
| `permission.ask` | 权限询问（可覆盖 ask→allow/deny） |
| `shell.env` | shell 命令前注入 env |
| `tool.execute.before` | 工具执行前（可改 args） |
| `tool.execute.after` | 工具执行后（可改输出） |
| `tool.definition` | 工具定义发给 LLM 前 |
| `evaluation.checks` | 评估阶段注入自定义检查 |
| `evaluation.result` | 评估完成后（通知 / 写外部） |
| `evaluation.analysis` | 完整替换默认 LLM 评估分析 |
| `acceptance.ready` | 交付持久化后（部署钩子） |
| `experimental.chat.system.transform` | system prompt 构建后 |

## 6. 在 config 中声明

```jsonc
{
  "plugin": [
    "my-npm-plugin@1.0.0",
    "file:///path/to/my-plugin.ts"
  ]
}
```

或把插件文件放在 `.opencorvus/plugin/` 目录（`*.ts` / `*.js`），自动发现（`src/config/config.ts:467-479`）。

## 7. 禁用默认插件

```bash
OPENCORVUS_DISABLE_DEFAULT_PLUGINS=1 opencorvus serve
```

跳过 `opencode-anthropic-auth` 的 npm 安装与加载（`src/plugin/index.ts:52-54`）。内部插件不受影响。

必须禁用的场景：CI / 无网络 / 使用 DashScope 等替代认证 / 运行 benchmark 避免 `bun install` 阻塞。

## 8. Plugin vs Provider vs Executor

Plugin 不直接替换 Provider 或 Executor，但可通过：
- `auth` hook — 为特定 Provider 实现自定义认证
- `chat.headers` / `chat.params` — 请求前修改参数
- `evaluation.analysis` — 完整接管评估
- `acceptance.ready` — 交付后触发部署

Executor 选择（OpenCorvus / Codex / Claude Code）由 Orchestrator 控制，Plugin 不干预。
