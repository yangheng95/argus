2. `GET /api/market/stocks` 的返回必须为数组，每项至少包含：
   - `code`
   - `name`
   - `openPrice`
   - `currentPrice`
   - `change`
   - `changePercent`
   - `highPrice`
   - `lowPrice`
   - `volume`
   - `updatedAt`

3. `GET /api/market/stocks/:code` 的返回必须是对象，至少包含：
   - 股票基础字段；
   - `history` 数组，长度最多 60，按时间升序；
   - `history` 每项至少包含 `price`、`volume`、`createdAt`

4. `GET /api/market/sse` 必须使用标准 `text/event-stream` 响应，并满足：
   - 连接建立后立即推送一次当前全量快照，避免首页白屏等待 2 秒；

   - 至少包含 `stocks` 与 `serverTime`。

5. SSE 连接不应要求认证。PRD 未将行情接口标记为认证必需；首页应支持未登录查看行情，登录后再交易。

### 5. 行情模拟引擎与撮合

1. 必须新增 `src/simulator.ts`，作为独立模块管理定时价格推进，不应把随机价格逻辑散落在 `index.ts` 或 `src/market.ts`。

2. 模拟引擎必须实现：
   - 基于上一价格的随机波动；
   - 叠加 `stocks.trend`；
   - 基于 `open_price` 的 ±10% 涨跌停钳制；
   - `high_price` / `low_price` / `current_price` / `updated_at` / `volume` 更新；
   - `price_history` 增量写入并只在接口层截取最近 60 个点，不要求数据库物理裁剪。

3. 正态分布实现不需要引入额外依赖；可在 `src/simulator.ts` 中用 Box–Muller 生成近似正态随机数。该决定源于当前仓库无依赖、PRD 未要求统计学库，且应保持 Bun 项目轻量。

4. 撮合逻辑必须在每次价格更新后的同一 tick 内执行，且至少满足：
   - 待成交买单：若 `current_price <= order.price` 则成交；
   - 待成交卖单：若 `current_price >= order.price` 则成交；
   - 成交后更新 `orders.status = 'filled'` 与 `filled_at`；
   - 买单成交后增加/创建 `positions`，并按加权平均法更新 `cost_basis`；
   - 卖单成交后增加 `users.balance`，并减少持仓；若数量归零，可保留 0 仓记录或删除，但接口层不得返回负数或脏数据。

5. 必须定义“成交价”规则并全项目一致。PRD 仅定义触发条件，未明示最终成交价格。为保证可验证性，本规格要求：
   - 成交价使用“当前市场价 `stocks.current_price`”，不是挂单限价；
   - 买单成交时实际成本可能低于挂单预扣金额，差额必须立即返还到 `users.balance`；
   - 卖单成交时收入按市场价计算，因卖单下单时仅冻结股票数量，不冻结现金，因此不存在差额返还问题。

### 6. 交易模块

1. 必须新增 `src/trading.ts`，实现：
   - `POST /api/trading/buy`
   - `POST /api/trading/sell`
   - `POST /api/trading/cancel/:id`
   - `GET /api/trading/orders`

2. 交易接口必须全部要求认证，并复用 `src/auth.ts` 的 Bearer 中间件。

3. 买卖请求体统一为：
   - `{ "stockCode": string, "quantity": number, "price": number }`

4. 交易校验规则必须在路由层显式返回 4xx JSON 错误，并覆盖：
   - `stockCode` 存在；
   - `quantity` 为正整数且是 100 的倍数；
   - `price` 为正数；
   - 挂单价格位于当前价 ±10% 区间；
   - 买入时 `users.balance >= quantity * price`；
   - 卖出时用户在 `positions` 中对该股票的可卖数量足够。

5. 下单成功后的状态必须是：
   - 一律先创建 `orders.status = 'pending'`；
   - 然后可选择立即尝试一次按当前价撮合；
   - 若当前价已满足条件，可在同一请求中直接成交为 `filled`；
   - 若未成交，则保持 `pending`。
   这样既不违背“每次价格变动自动撮合”，又能使交易行为在静态行情下更直观。

6. `GET /api/trading/orders` 必须只返回当前认证用户订单，支持至少按 `created_at DESC` 排序。每项至少包含：
   - `id`
   - `stockCode`
   - `stockName`
   - `direction`
   - `quantity`
   - `price`
   - `status`
   - `filledAt`
   - `createdAt`

7. `POST /api/trading/cancel/:id` 必须只允许撤销当前用户自己的 `pending` 订单：
   - 买单撤单：恢复预扣金额到 `users.balance`
   - 卖单撤单：恢复冻结数量到 `positions.quantity`
   - 已成交或已撤销订单再次撤销应返回 409 或 400，项目内需统一

### 8. 历史与资产曲线

   - `GET /api/history/trades` 应以 `orders` 为源；
   - 返回字段至少包括 `id`、`stockCode`、`stockName`、`direction`、`quantity`、`price`、`amount`、`filledAt`；

3. `GET /api/history/trades` 必须支持：
   - `?stock=` 代码筛选
   - `?limit=` 分页大小
   - `?offset=` 偏移量
   - 默认按 `filled_at DESC`

4. `GET /api/history/daily` 必须返回最近 30 个点；若真实天数不足，应返回已存在快照，不要求伪造 30 天历史。

## Constraints

1. 当前仓库不存在任何业务代码，只有以下已探索到的真实文件：
   - `package.json`
   - `tsconfig.json`
   - `opencorvus.json`
   - `prd-stock-trading-sim.txt`
   因此所有业务文件均为新增，不存在可复用实现。

2. 根级 `package.json` 当前没有依赖与 scripts，说明实现必须同时补齐依赖管理与运行命令，而不是假定工程已初始化。

3. 根级 `tsconfig.json` 当前仅设置：
   - `"target": "ES2022"`
   - `"module": "Preserve"`
   - `"moduleResolution": "Bundler"`
   - `"strict": true"`
   - `"skipLibCheck": true"`
   这意味着新增代码必须天然兼容 ESM/Bundler 解析风格，避免 CommonJS 写法。

4. `src/` 当前为空，不能声称“修改现有模块”；实现必须从零定义导出边界与复用模式。为保证后续维护，建议各后端模块统一导出 Hono 路由对象与服务函数，而不是彼此直接操作 HTTP 上下文。

5. PRD 固定要求 `index.ts` 同时服务 API 与前端静态资源，因此不能把前后端拆成两个独立进程作为最终运行形态。

6. PRD 固定要求无 README、文档等无关产物，因此实现范围应严格限制在可运行代码、配置、测试与必要静态文件，不新增说明文档。

7. 由于 PRD 给出的 `orders` 表没有实际成交价字段，而历史接口需要准确成交记录，这是当前 PRD 与实现之间最明显的数据建模缺口；必须通过最小 schema 扩展解决。

8. 由于 PRD 没有“冻结资金/冻结持仓”表或字段，而测试又要求撤单恢复，必须采用“直接扣减余额/持仓 + 订单 pending 代表冻结”的实现模型，或等价地新增冻结字段。考虑最小改动，本规格要求前者。

<assumptions>
- Q: 是否允许在 PRD 给出的 DDL 之外增加最小字段？
  A: 假定允许最小扩展，因为 `orders` 若无实际成交价字段，`GET /api/history/trades` 无法准确返回成交价格与金额；建议新增 `filled_price REAL`。

- Q: 挂单提交后是否可在当前价已满足时立即成交？
  A: 假定允许，因为 PRD 仅要求价格变动自动撮合，并未禁止下单时按当前价立即匹配；该行为能提升 MVP 可用性且不破坏后续 tick 撮合。

- Q: 行情接口是否要求登录？
  A: 假定不要求登录，因为 PRD 未将其列为受保护资源，且首页行情浏览应支持匿名访问。

- Q: 每日资产曲线在短生命周期 MVP 中如何产生足够数据？
  A: 假定允许通过注册、成交与查询时惰性写入/更新 `daily_snapshots`，而非依赖真实日终调度。
</assumptions>

<risks>
- 当前仓库没有任何现成代码，连 `web/` 都不存在，实际工作量是完整全栈搭建，不是局部修改；若下游执行代理低估为“填空”，会导致漏掉构建与静态资源集成。
