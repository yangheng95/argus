Tank Battle — 经典坦克大战 Web 版 PRD

1. 产品概述

产品名称：Tank Battle
类型：2D 俯视角射击游戏（经典坦克大战复刻）
技术栈：纯前端，HTML5 Canvas + TypeScript，零外部依赖
运行环境：现代浏览器（Chrome/Firefox/Safari/Edge）
构建工具：Bun + esbuild（或直接 bun build）
目标：实现一个可玩的、包含完整游戏循环的经典坦克大战单机版，融入 Roguelike 升级系统和夜战模式等创意元素

2. 核心玩法

玩家操控一辆坦克，在由砖墙、钢墙、河流、草丛构成的战场上消灭所有敌方坦克，同时保护己方基地（鹰徽）。

胜利条件：消灭当前关卡所有敌方坦克。
失败条件：玩家生命耗尽，或基地（鹰徽）被摧毁。

2.1 Roguelike 升级系统
- 每关通关后进入升级选择界面，随机展示 3 个强化，玩家选 1 个
- 强化列表（每次从中随机抽 3 个不重复的）：
  - 双弹：同时可发射 2 颗子弹
  - 穿甲弹：子弹可摧毁钢墙
  - 弹射弹：子弹碰到钢墙/地图边界反弹 1 次
  - 加速：移动速度 +50%
  - 快射：射击冷却减半
  - 护盾：每关额外获得 1 次免死
  - 地雷：按 M 键在当前位置放置地雷（最多存在 3 个），敌人经过时爆炸
  - 侦查：草丛不再遮挡视野
- 升级效果可叠加（如选两次加速 = +100%）
- 游戏结束时所有升级重置

2.2 夜战模式
- 关卡 2 和之后的偶数关卡为夜战
- 夜战规则：
  - 屏幕整体变暗（Canvas 覆盖半透明黑色层）
  - 玩家坦克周围有圆形可见区域（半径 3 格，用径向渐变实现）
  - 射击时闪光效果：可见区域瞬间扩大到 6 格，持续 200ms
  - 爆炸也会产生闪光
  - 敌方坦克在可见区域外不渲染（但仍正常移动和射击）
  - 子弹的飞行轨迹始终可见（发光效果）

2.3 特殊地形（新增）
- 炸药桶 BARREL (7)：子弹击中后 3×3 范围爆炸，摧毁范围内砖墙、伤害坦克
- 传送门 PORTAL (8)：成对出现，坦克进入一个从另一个出来，冷却 3 秒

3. 游戏对象

3.1 地图（BattleField）
- 尺寸：13×13 格（每格 48×48 像素），画布 624×624
- 地图数据用二维数组表示，每个格子是一个 Tile 类型
- Tile 类型：
  - EMPTY (0)：空地，可通行可射击
  - BRICK (1)：砖墙，可被子弹摧毁，不可通行
  - STEEL (2)：钢墙，普通子弹无法摧毁，不可通行
  - WATER (3)：河流，不可通行，子弹可飞越
  - TREES (4)：草丛，可通行，遮挡坦克（坦克在草丛下不可见）
  - ICE (5)：冰面，可通行但坦克会滑行（惯性移动）
  - BASE (6)：基地（鹰徽），被摧毁则游戏失败

3.2 玩家坦克（PlayerTank）
- 初始位置：地图底部中央偏左
- 移动速度：每帧 2 像素
- 属性：
  - lives：初始 3 条命
  - direction：上下左右四方向
  - bulletCooldown：射击冷却 500ms
  - invincible：重生后 3 秒无敌
- 操作：
  - 方向键（↑↓←→）或 WASD 移动
  - 空格键射击
- 碰撞：不能穿过砖墙、钢墙、河流、地图边界、其他坦克
- 死亡：被敌方子弹命中后爆炸，消耗一条命，在初始位置重生
- 重生保护：重生后 3 秒内闪烁且无敌

3.3 敌方坦克（EnemyTank）
- 每关总共 20 辆敌方坦克
- 同时在场最多 4 辆
- 出生点：地图顶部左、中、右三个位置轮流出生
- 类型（4种）：
  - Basic：速度慢，1 发子弹消灭，白色
  - Fast：速度快，1 发子弹消灭，浅蓝色
  - Power：速度中等，1 发子弹消灭，但子弹可摧毁钢墙，紫色
  - Armor：速度慢，需要 4 发子弹消灭（每次被击中变色），绿色→黄色→橙色→红色
- AI 行为：
  - 每隔 1-3 秒随机改变方向
  - 前方有障碍物时立即转向
  - 以一定概率（30%）朝玩家方向移动
  - 持续射击（冷却 1 秒）

3.4 子弹（Bullet）
- 速度：每帧 4 像素
- 同一坦克同时只能存在 1 颗子弹（子弹消失后才能再次射击）
- 碰撞规则：
  - 击中砖墙：摧毁砖墙，子弹消失
  - 击中钢墙：子弹消失（Power 型敌坦克的子弹可摧毁钢墙）
  - 击中河流：子弹飞越，不受影响
  - 击中地图边界：子弹消失
  - 击中敌方坦克（玩家子弹）：坦克受伤或被消灭
  - 击中玩家坦克（敌方子弹）：玩家死亡（无敌状态除外）
  - 击中基地：基地被摧毁，游戏失败
  - 两颗子弹相撞：同时消失

3.5 爆炸效果（Explosion）
- 坦克被摧毁时播放爆炸动画（3 帧，每帧 100ms）
- 子弹击中墙壁时播放小爆炸（2 帧）

4. 游戏状态机

4.1 状态：
- MENU：主菜单（显示 "TANK BATTLE" 标题 + "Press ENTER to Start"）
- PLAYING：游戏进行中
- PAUSED：暂停（按 P 键切换，显示 "PAUSED" 文字）
- GAME_OVER：游戏结束（显示 "GAME OVER" 上升动画 + 最终统计 + 已获得的升级列表）
- STAGE_CLEAR：关卡通过（显示关卡统计：击杀数、得分）
- UPGRADE_SELECT：升级选择（展示 3 个随机强化卡片，玩家点击或按 1/2/3 选择）
- STAGE_INTRO：关卡开始前（显示 "STAGE X" + 夜战关卡显示月亮图标 + 2 秒）

4.2 状态转换：
- MENU → STAGE_INTRO（按 Enter）
- STAGE_INTRO → PLAYING（2 秒后自动）
- PLAYING → PAUSED（按 P）
- PAUSED → PLAYING（按 P）
- PLAYING → GAME_OVER（生命耗尽或基地被摧毁）
- PLAYING → STAGE_CLEAR（所有敌方坦克被消灭）
- STAGE_CLEAR → UPGRADE_SELECT（1.5 秒后）
- UPGRADE_SELECT → STAGE_INTRO（玩家选择后进入下一关）
- GAME_OVER → MENU（5 秒后自动或按 Enter）

5. 关卡系统

- 至少实现 5 个关卡，每关地图布局不同
- 关卡 1（日间）：砖墙为主，简单布局，入门教学
- 关卡 2（夜战）：加入钢墙和河流，视野受限
- 关卡 3（日间）：炸药桶关，大量桶与砖墙混合，连锁爆炸
- 关卡 4（夜战）：传送门迷宫，草丛密布
- 关卡 5（日间 Boss）：开阔地形，Boss 坦克（2×2 格，8 发子弹，散射攻击）
- 每关敌方坦克配置：
  - 关卡 1：Basic×10, Fast×6, Power×2, Armor×2
  - 关卡 2：Basic×6, Fast×6, Power×4, Armor×4
  - 关卡 3：Basic×4, Fast×8, Power×4, Armor×4（快速坦克引爆桶）
  - 关卡 4：Basic×4, Fast×4, Power×6, Armor×6
  - 关卡 5：Basic×6, Fast×6, Power×4, Armor×2, Boss×1
- 通关后循环（难度递增：敌人速度 +10%，AI 朝玩家概率 +10%）
- 偶数关卡为夜战模式

6. 计分系统

- Basic 坦克：100 分
- Fast 坦克：200 分
- Power 坦克：300 分
- Armor 坦克：400 分
- 分数在 HUD 右侧面板显示
- 关卡结束时显示击杀统计

7. HUD 界面

7.1 游戏区域左侧（624×624 画布）
7.2 右侧信息面板（150 像素宽）：
- 剩余敌方坦克数量（用小坦克图标表示）
- 当前关卡号
- 玩家剩余生命
- 当前得分

- 经典 FC/NES 像素风
- 所有图形用 Canvas API 绘制（fillRect/strokeRect），不使用外部图片

  - 背景：纯黑 #000000
  - 砖墙：#B85C38（砖红色）
  - 钢墙：#C0C0C0（银灰色）
  - 河流：#4A86C8（蓝色，可加波纹动画）
  - 草丛：#2E8B57（深绿色）
  - 冰面：#ADD8E6（浅蓝色）
  - 玩家坦克：#FFD700（金黄色）
  - 敌方坦克：按类型着色（见 3.3）
  - 子弹：#FFFFFF（白色）
  - 基地鹰徽：#FFD700（金色）边框 + 内部图案
  - 炸药桶：#D2691E（棕色）+ 红色危险标识

  - 闪光效果：白色径向渐变，200ms 衰减
  - 升级卡片：金色边框 #FFD700，悬浮发光效果

10.2 游戏主循环
```
function gameLoop(timestamp) {
  const deltaTime = timestamp - lastTime
  lastTime = timestamp

  update(deltaTime)   // 更新所有游戏对象
  render()            // 绘制所有游戏对象

  requestAnimationFrame(gameLoop)
}
```

10.3 碰撞检测

- 子弹与地形碰撞
- 子弹与坦克碰撞
- 坦克与坦克碰撞
- 子弹与子弹碰撞

11. 性能要求

- 60 FPS 稳定运行

12. 测试策略

测试优先级：端到端测试 > 单元测试。先确保整体可玩，再验证局部逻辑。

12.1 端到端测试（E2E）— 最高优先级

所有 E2E 测试通过模拟键盘输入驱动 Game 实例，验证真实的状态转换和游戏行为。
使用 Bun test runner，Game 类需支持 headless 模式（不依赖真实 Canvas，用 mock context）。

E2E-01 完整游戏流程：
  - 启动 → MENU 状态 → 模拟 Enter → STAGE_INTRO → 2s 后 PLAYING
  - 模拟玩家移动和射击 → 消灭所有敌人 → STAGE_CLEAR → UPGRADE_SELECT
  - 选择升级 → STAGE_INTRO（下一关）→ 验证升级效果生效
  - 断言：状态转换正确，分数累计，关卡递增

E2E-02 游戏结束流程：
  - 进入 PLAYING → 玩家被击杀 3 次 → GAME_OVER
  - 断言：生命递减正确，GAME_OVER 状态触发，升级重置

E2E-03 基地被毁流程：
  - 进入 PLAYING → 敌方子弹命中基地 → GAME_OVER
  - 断言：基地状态变化，游戏立即结束

E2E-04 夜战模式：
  - 进入关卡 2（夜战）→ 验证夜战标志为 true
  - 模拟射击 → 验证闪光事件触发
  - 断言：夜战关卡正确识别

E2E-05 升级系统端到端：
  - 通关 → 进入 UPGRADE_SELECT → 验证展示 3 个不重复选项
  - 选择"双弹" → 下一关验证玩家 maxBullets === 2
  - 选择"加速" → 验证玩家速度增加

E2E-06 暂停恢复：
  - PLAYING → 按 P → PAUSED → 再按 P → PLAYING
  - 断言：暂停期间游戏时间不推进

E2E-07 炸药桶连锁爆炸：
  - 放置相邻桶的地图 → 子弹击中一个桶 → 验证连锁引爆
  - 断言：爆炸范围内砖墙被摧毁，附近坦克受伤

E2E-08 传送门：
  - 坦克进入传送门 A → 出现在传送门 B
  - 断言：坐标正确，冷却期间无法再次传送

12.2 单元测试 — 第二优先级

UNIT-01 碰撞检测：AABB 碰撞、坦克与地形、子弹与墙壁、子弹与子弹
UNIT-02 坦克属性：移动速度、射击冷却、无敌状态计时
UNIT-03 地图解析：Tile 类型解析、可通行性判断
UNIT-04 敌方 AI：方向切换频率、朝玩家概率、障碍物回避
UNIT-05 升级效果计算：各升级数值叠加、重置逻辑
UNIT-06 炸药桶爆炸范围：3×3 区域计算、连锁检测
UNIT-07 传送门配对：配对查找、冷却计时
UNIT-08 Boss 坦克：多血条、散射子弹生成

12.3 验收标准

P0（必须通过 — E2E 覆盖）：
- E2E-01 完整游戏流程通过
- E2E-02 游戏结束流程通过
- E2E-03 基地被毁流程通过
- 游戏可在浏览器中正常渲染和操作
- 5 个关卡可以循环

P1（应该通过）：
- E2E-04 至 E2E-08 全部通过
- 4 种敌方坦克类型 + Boss 行为正确
- 夜战视觉效果正常（视野限制 + 射击闪光）
- 升级卡片 UI 正常展示和选择
- 连杀提示（"Double Kill!" 等）
- HUD 正确显示分数、生命、关卡、已获得升级图标

P2（加分项）：

- 屏幕震动效果（Boss 攻击、炸药桶爆炸时）

13. 交付物

- src/ 目录下所有源码文件
- tests/ 目录下 E2E 和单元测试
- 一个 index.html 入口文件（可以直接在浏览器打开或通过 bun serve 运行）

- 执行 `bun build src/main.ts --outdir=dist --minify` 可以成功打包
- 执行 `bun test` 通过所有 E2E 和单元测试
