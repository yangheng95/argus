# MirrorWatch

Mirror Watch is an OpenCorvus project package for the author's complete AInvest expert/persona survey, deterministic 3-2-1 aggregation, and rendered decision-report protocol.

Vocabulary: E2E means End-to-End; HTML means HyperText Markup Language; ID means Identifier; JSON means JavaScript Object Notation; SVG means Scalable Vector Graphics; URL means Uniform Resource Locator.

## Fact and Turn Contract

Every projected agent extends the platform Agent-fact and Turn protocol. Domain tools record durable research, survey, aggregation, and report facts without becoming submit/finalizer calls; a normal stream end is only a physical Turn observation; and the visible final assistant message is natural narration of work, limitations, and blockers rather than durable evidence transport. File changes, command exits, process facts, and browser captures remain Host observations rather than Agent self-reports.

Execution attempts and dispatch lineage are immutable physical evidence identities. Exact Delivery Slice revision IDs are optional work and evidence subjects, never lifecycle or scheduling owners. The Orchestrator judges visible final messages, domain artifacts, tool traces, and Host observations and owns Task lifecycle decisions. Every completion appends one typed `task_completion_decision` artifact that names the exact Orchestrator message/tool part, typed EvidenceLocators, every intentionally delivered Artifact locator, every accepted current Delivery Slice revision ID, and the exact selected workflow ID (`null` only for a direct Task). The selected workflow is inseparably bound to the active package revision: scope, project identity, namespace, manifest ID, version, and package digest. Empty deliverable or accepted-revision lists are truthful only when that Task produced no Artifact deliverables or has no Delivery Slices. Reopen preserves earlier decisions, and the current Task projection joins only the artifact whose timestamp equals the terminal Task timestamp. The artifact does not copy the narrative summary or materialize an acceptance aggregate. This package does not infer an active/current Run or persist workflow step state.

## Expert contract

Mirror Watch exposes one manifest-owned `research-survey-report` workflow: complete AInvest research, survey, and report delivery. It is not a generic competitor-research or Prism source-observation package.

The complete AInvest workflow is complete only when all of the following are true:

1. Research uses current, visible source-page evidence and produces exactly ten stable feature identities, F01 through F10.
2. Recommendations, the inline SVG Gantt, the agent survey, and the human survey preserve the same feature codes, titles, timing, action, differentiation, and source trace.
3. Each expert session loads one explicitly assigned package perspective, records a qualitative three-pick opinion with citations, derivation, confidence, rejected alternatives, and an honest authorship boundary, then publishes it only through `mirror-watch/shared/publish-expert-survey`; that producer-boundary validator emits the structured schema-v1 expert Artifact consumed downstream.
4. The persona-cohort session owns the exact nonempty Task-selected identity and vote-path collection; each planned identity must be a unique member of the full authority, and each individual vote preserves its authority identity and segmentation fields byte-for-value while returning exactly three independently grounded canonical feature codes.
5. One package-local parser validates the full persona file, and `mirror-watch/shared/personas` publishes it as the sole `mirror-watch/persona-authority` Catalog Artifact. One vote must exist for every planned cohort identity; no duplicate, unplanned, or out-of-authority vote is accepted. An explicit subset is never enlarged to all authority personas.
6. Only persona votes contribute to quantitative scores. Expert votes remain visible qualitative corroboration.
7. The research, expert, and persona producers publish immutable typed domain Artifacts before report dispatch. `mirror-watch/shared/aggregate-report` is the only aggregation and report-rendering implementation: it consumes only those exact selected typed payloads, returns all independently detectable snapshot violations together, proves their cross-Artifact lineage, applies deterministic 3-2-1 weights, byte-verifies exact retries, atomically reuses the canonical exact-input publication, and returns only a compact receipt.
8. Missing, malformed, inconsistent, duplicated, unplanned, or out-of-authority data is an error. No record is normalized, inferred, truncated, skipped, substituted, or silently defaulted.

The package supports any nonempty explicit Task-selected cohort. The current authority contains 105 personas, but the report is complete for the exact declared Task scope and must state its actual cohort count rather than imply all 105 or any larger production survey.

The `## Canonical project paths` section in `mirror-watch-delivery-contract` is the single path source for every worker and report. Package prompts must use that map directly and never ask the user to invent a missing report path.

## Agent communication

The existing OpenCorvus Orchestrator owns task decomposition and dispatch. Mirror Watch does not ship a workflow engine, state machine, runner, or MCP (Model Context Protocol) server.

The planning owners persist the report Delivery Slice contract and assembly ownership. Research, both expert perspectives, the exact Task-selected persona cohort, and report production are mandatory once-per-Task workflow nodes. Persona rows and vote files remain individually validated data rather than scheduler work units.

## Source migration boundary

The source project's research, survey, and aggregation semantics are preserved. Its seed/demo copying, Python and shell dispatchers, OpenCode/Claude alternatives, inferred segmentation, malformed-ID normalization, truncated picks, invalid-file skipping, and empty-report generation are deliberately absent.

The source skills were imported from the reviewed Mirror Watch source repository as complete directory snapshots. Every `SKILL.md`, reference, script, template, and binary asset is part of the content-addressed package Skill closure and materializes only when the exact active grant is loaded. The six Denis/Oleg research files and their honesty boundaries remain visible. Neither perspective may be represented as the named expert's direct opinion.

Manifest refs select and project resources; the Skill tool loads the exact visible name from each `SKILL.md` definition. They are separate protocol fields and are never aliases for one another. Package tool IDs retain their manifest refs.

The iFind package tool preserves the source channel and response contract. Its statically imported `assets/ifind.json` closure is the only endpoint, header, provider-identity, and request-policy source; callers pass only `query`, `channels`, and `size`, independent of project or global installation location. The model never receives configuration contents. The declared tool result projects the exact provider `summary` as `results[].evidence` with its same-result URL; it excludes unrequested raw bodies and provider extras instead of truncating a persisted response. Research for the concrete AInvest financial-product question begins with a finite evidence plan without a package-prescribed query order. All 16 source Skill identities are present. Their presence preserves the full expert-squad capability package; it does not override a concrete Task instruction that requires iFind-only evidence collection. The `s3-share` copy requires explicit environment configuration and contains no embedded credential, while signed sample URLs and source fallback instructions are removed under the repository's security and no-fallback contract.

The package-owned configuration asset is one strict JSON object with exactly these top-level fields: `endpoint`, `headers`, `request`, `evidence_field`, `max_result_count`, `max_evidence_characters`, `max_tool_output_bytes`, `inactivity_timeout_ms`, and `max_response_bytes`. `endpoint` is one HTTPS URL without embedded credentials, query, or fragment. `headers` must contain unique HTTP field names under case-insensitive comparison and valid nonempty field values; their canonical `Headers` representation is the exact representation sent by fetch. `request` accepts arbitrary JSON property names with nonempty string, finite number, or boolean values and must declare `output: "block"`, `need_content: false`, and `dl: 1999`. The four call-owned fields `query`, `channels`, `size`, and `qid` cannot be configured because that would create a second source for the tool invocation. All remaining configuration entries and the four call entries are combined through one own-property construction. The complete request is serialized once, parsed once to verify its own-property shape, and the same serialized bytes are the fetch body. Keys such as `__proto__`, `constructor`, and `prototype` are ordinary own JSON properties, not rejected names or prototype mutations. The public provider bounds are fixed: `max_result_count` must equal `10`, `max_evidence_characters` must equal `2000`, and `max_tool_output_bytes` must equal `49152`. Every project input/output path uses the same exact portable canonical forward-slash project-relative contract; whitespace, backslashes, absolute paths, normalization drift, Windows alternate-data-stream syntax, reserved device segments, portable-forbidden/control characters, trailing segment dots/spaces, project escape, and symbolic-link or junction traversal are rejected rather than normalized. There is no caller path, package default, environment lookup, or alternate configuration source.

iFind failures expose only the local validation or transport stage and, for an HTTP failure, the numeric HTTP status. Transport exception messages, HTTP status text/body, stream exceptions, parser details, provider status values, invalid result values, and configured private values are not interpolated into diagnostics. Successful output structurally contains only the declared request identity and validated provider result schema; the client never copies endpoint, header, or configured request-policy fields into it. Valid title, URL, publish date and evidence are trusted provider content and are not inspected for configuration substrings, keywords or token patterns. A deployment that does not trust its provider must establish that boundary outside this client; this package does not claim to detect malicious provider reflection. Successful output is complete compact one-line JSON and must fit the fixed 49,152-byte UTF-8 package limit before the host tool wrapper receives it. Header and body inactivity use the configured interval as a true timeout since the last activity, caller abort settles before fetch creation when already aborted, and late fetch/body operations remain observed even when upstream code ignores its abort signal.

## Artifact protocol

The model-facing file protocol uses `artifact_snapshot` to publish current-Task project files and return one exact content-addressed `resource_set` locator. `artifact_publish` accepts the complete evidence value only as strict JSON text in `payload_json`; object keys must be unique, and `resource_set` is required (`null` when there are no files, otherwise the exact locator returned by `artifact_snapshot`). The Host verifies and expands the immutable manifest inside its trusted boundary, then publishes the structured value through the same canonical service used by typed and package tools. Mirror Watch expert surveys are an explicit typed-domain exception: `mirror-watch/shared/publish-expert-survey` resolves and validates the three-resource set at the producing Agent boundary and is the sole publisher of `mirror-watch/expert-survey` schema version 1.

Mirror Watch has one V1 protocol. Its expert-survey Artifact has exactly one shared payload, `{vote, resource_roles}`; producer-specific field variants are not separate versions and have no compatibility reader. Task Artifact schema version 2 and OpenTest result schema version 2 are unrelated protocols.

Task schedulers and projected workers inherit `artifact_search`, `artifact_read`, and `artifact_select` as platform tools. Projected workers additionally inherit `artifact_snapshot` and `artifact_publish`; schedulers do not. A worker without a typed domain-output producer uses `artifact_publish` for canonical JSON `expert_output` type `<active-squad-id>/...`; the publication declares publication-specific `source_artifact_locators` from complete reads earlier in the same physical Turn, and the Host derives Task, Session, Agent, active-Squad, projection, and complete-read observations. Typed domain-output and package tools remain their domain's sole publishers and are never duplicated. Every consumer completely reads each candidate it inspects, then calls `artifact_select` for every Artifact that semantically supports its typed output; complete but unselected reads remain observations and zero selections are valid. Research, survey, aggregation, report, and source evidence does not travel through Agent messages or adapter results: each consumer enumerates the same-Task catalog and reads exact Task-scoped bytes or immutable disk resources. A user-pinned locator cannot be replaced by search. For Cross-Task evidence, Mission selects an exact `ArtifactReadLocator` (`engine_artifact`, `task_artifact_snapshot`, or `task_artifact_resource`) from the source Task catalog and creates the receiving Task with `{source_task_id, locator}`. The receiving catalog exposes a target-owned imported Engine Artifact that preserves the source type, schema, payload, copied resources, and original consumption provenance in immutable `import_lineage`; copied request prose and foreign reads are not evidence. Empty search/default fields are valid. Missing, foreign, corrupt, stale, unreadable, or path-invalid selected evidence is an explicit error.

Typed publishers finish every independent exact read, producer/lineage check, payload parse, and resource validation before recording source selections. Their Engine Artifact and Task Artifact publications use stable Task execution plus exact Delivery Slice revision subject identity, so an identical publication reuses one canonical identity while changed bytes or semantics remain distinct.
