`opencorvus serve` starts the OpenCorvus HTTP API server. It is the substrate behind the [SDK](/docs/sdk/), the Overlay UI, the [ACP](/docs/acp/) bridge, and external integrations (GitHub Action, channel runtime, etc.).

Source: `packages/opencorvus/src/server/`.

## Launch

```bash
opencorvus serve --hostname 127.0.0.1 --port 7878
```

See [CLI](/docs/cli/) for all flags. Set `OPENCORVUS_SERVER_PASSWORD` when binding to a non-loopback hostname.

## Architecture

- `server.ts` — HTTP entrypoint, mounts route modules.
- `defaults.ts` — default port / hostname / password rules.
- `event.ts` — SSE event multiplexer.
- `mdns.ts` — optional mDNS service discovery.
- `overlay-ui.ts` — serves the static Overlay UI under `/ui/`.
- `in-process-client.ts` — embedded SDK client used by `opencorvus acp`.
- `shutdown.ts` — graceful shutdown hooks.

## Route modules

Routes are split into focused modules under `packages/opencorvus/src/server/routes/`:

| Module | Module | Module |
|---|---|---|
| `app.ts` | `attachment.ts` | `auth.ts` |
| `channel.ts` | `coding.ts` | `config.ts` |
| `control.ts` | `executor.ts` | `experimental.ts` |
| `export.ts` | `file.ts` | `gateway.ts` |
| `global.ts` | `mcp.ts` | `orchestrator.ts` |
| `panel.ts` | `permission.ts` | `project.ts` |
| `provider.ts` | `pty.ts` | `question.ts` |
| `session.ts` | `skill.ts` | `tui.ts` |

Each module owns a related slice of the API (e.g. `permission.ts` exposes `/permission/*`, `mcp.ts` exposes `/mcp/*`).

## Streaming

Long-running events stream over SSE on `/event`. The SDK exposes this as `client.event.subscribe()`. Reconnect logic with exponential backoff (max 60 s) lives client-side.

## Authentication

For non-loopback hostnames the server requires the `OPENCORVUS_SERVER_PASSWORD` env. Requests must carry it as a header (`X-OpenCorvus-Password`) or a query parameter — the SDK does this automatically.

## Embedding

```ts
import { createOpenCorvus } from "@opencorvus-ai/sdk"
const { client, server } = await createOpenCorvus({ directory: "/path/to/repo" })
```

This boots a server in-process on a random port and returns a client connected to it. Use this when you don't want a separate `opencorvus serve` process.

See [SDK](/docs/sdk/) for the full client surface.
