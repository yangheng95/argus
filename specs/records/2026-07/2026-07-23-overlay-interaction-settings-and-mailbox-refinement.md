## Causal chain

1. The Composer issues share an overlay-structure cause: one flat Select simultaneously owns intent, squad discovery, and hover descriptions, while mention completion adds a second visual state beside an already sufficient text-query state. A portaled semantic submenu and the existing category/entity grammar remove both competing overlay trees.
2. Mission is not an executor and therefore must not have any active profile, including `general`. The selection is a visibility constraint on the canonical recommendation catalog. Mission reads that catalog, chooses explicit squads for phases, and assigns one fixed `promptProfile` only to each created Task.
3. Expert Squad card contention is frontend-wide because the busy owner is scalar even though package lifecycle APIs are independent. Busy identity must therefore be `(scope, action key/package)`, not page-wide.
4. Mailbox durable state is correct; the flash is renderer identity loss after canonical refresh. Stable primitive keys preserve card/disclosure/focus geometry without inventing read state.
5. Goal alignment is not a spacing problem. The shared grid is already the correct tab-stop source; one inherited `text-align: center` on the identifier cell causes the visible drift.
6. The missing Windows popup is not a Mailbox ingestion or setting problem: the running settings enable desktop notifications and the projector reaches the send command. The direct trigger is a portable executable calling an installed-app-only plugin path; the plugin's Windows worker discards the native `show` result, causing false delivery evidence. A registered AUMID plus a result-bearing Windows Runtime submission repairs both platform identity and observability at the host boundary.
