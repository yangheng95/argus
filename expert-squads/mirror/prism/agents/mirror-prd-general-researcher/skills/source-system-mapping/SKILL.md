- Treat the supplied URL as a discovery entry, not a route-count instruction.
- Capture the entry route first, derive actual candidate identities and navigation dependencies, then fan independent candidates across the smallest reusable pool of concurrent Browser acquisition lanes that provides real parallelism. Keep only true click/navigation/state dependency chains sequential within one lane; never create one Browser Session per route, card, or candidate.
- Evaluate every discovered candidate for domain, product-section, canonical-path, template duplication, business distinctness, implementability, evidence sufficiency, system role, and authorized scope.

Group accepted routes only when material evidence proves a shared parameterized template, behavior/state contract, and implementation ownership; a route instance remains separately evidenced even when it shares a delivery surface.
- Classify reference pages as product observations and transferable capabilities as adopt/defer/reject inspiration. Leave AInvest product/design authority to the mandatory mapper. Downstream agents do not read this working path.
