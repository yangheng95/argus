# User Interface audit contract

## Required inputs

Require the canonical system-project contract, every applicable exact delivery-plan entry, complete assigned surface set, exact member route URLs,
material journeys, viewport/device boundary, observation theme/state and source evidence. If any
required input is missing, report it instead of silently choosing a replacement. Unsupported
optional detail may remain absent.

## Observation passes

1. Consume the existing route membership and evidence anchors without repeating task-wide route discovery.
2. Capture every member route and its stable regions at the required viewport.
3. Inventory product regions and reusable component families with their product role and behavior.
4. Observe hierarchy, capability grouping, content/data density, component conventions, contrast,
   motion and desktop behavior as product facts. Layout measurements and computed styles are
   observation context only, never Prism design authority.
5. Capture default, hover, focus, active, selected, disabled, loading, empty, error, success, modal,
   menu and overflow states that materially exist.
6. Exercise every material journey applicable to the surface. Record entry condition, steps,
   controls, route transitions, feedback, data/state changes, error/recovery path and outcome.
7. Check keyboard order and focus movement, dialogs/menus, validation, back/forward behavior,
   contrast, zoom/reflow clues, reduced motion and performance risks.
8. Record each observed product asset candidate with route/region, source URL or inline reference, trigger
   state, media type, reuse relationship, rights evidence and acquisition limitation. Do not
   materialize candidate product bytes or invent missing provenance.
9. Capture real Browser screenshots for the required member routes and material states. Record the
   exact returned `/attachment/...` URL in the matching evidence-index pointer so the Host can bind
   the observed bytes into immutable FrontendResearchBrief Artifact resources after the Turn.

## Report

Write one Task-wide report under `.mirror/prd/tmp/` containing every applicable exact delivery-plan entry, the complete assigned surface set, observation parameters, exact
member-route coverage, product-region map, component-pattern inventory, product-observation table, state matrix
and journey/navigation/recovery evidence, plus keyboard/focus evidence, asset-candidate ledger,
design-system consistency, accessibility findings, performance findings, screenshots/diagnostics,
confidence/limitations, and implementation-relevant facts. Each finding states observation, exact
evidence, impact and confidence. Mark all target/competitor screenshots and geometry as observation
context without visual-parity authority. Do not prescribe a replacement design or invent unobserved values.
