- 模型：几何布朗运动 (GBM)
- 参数：drift (μ)、volatility (σ)
- 更新频率：每秒一个 tick
- 涨跌停：±10%（基于昨收价）
- 盘口：5 档买卖

### 撮合引擎

- 市价单：当前最优价立即成交
- 限价单：挂入订单簿，当前价 ≤ 委托价(买)或 ≥ 委托价(卖)时成交
- 手续费：买 0.03%，卖 0.03% + 印花税 0.05%

### 风控

- 涨停不可买入，跌停不可卖出
- 资金/持仓校验
- T+1
- 委托数量必须为 100 整数倍

   - `orders.quantity` 表示“手”

   - `quotes.id` 为自增主键
   - 金额字段使用可表示小数的 SQLite REAL
3. `server/db/migrate.ts` 需要负责初始化数据库结构；鉴于白名单中没有 Drizzle 配置文件，允许在该文件内直接使用 Drizzle + SQLite 建表逻辑，只要与 `schema.ts` 保持一致且类型可用。
4. `server/db/seed.ts` 必须预置 PRD 中列出的 20 只 A 股，写入 `stocks` 表，初始字段至少要包含：
   - `code`、`name`、`sector`
   - `initial_price`、`current_price`、`prev_close`、`open_price`
   - `high`、`low` 初始化为初始价
   - `volume`、`turnover` 初始化为 0
   - `updated_at`
5. 如果种子脚本会重复执行，需保证不会制造重复主键冲突导致整个系统不可启动；应使用 upsert/insert-ignore 风格策略。

### 4. 服务端应用装配

1. `server/app.ts` 必须创建 Hono 应用并完成以下装配：
   - 基础中间件（如 JSON、错误响应、CORS，如实现需要）
   - 路由挂载：`/api/auth`、`/api/quotes`、`/api/orders`、`/api/positions`、`/api/trades`、`/api/account`
   - WebSocket 入口 `/ws/quotes`
2. `server/index.ts` 必须作为 Bun 运行入口，负责：
   - 初始化数据库/seed（若约定为启动时执行）
   - 初始化行情引擎与撮合引擎的周期任务
   - 启动 Hono/Bun 服务
3. 鉴于代码库中不存在其它基础设施文件，应用内依赖注入、数据库句柄、引擎实例共享应在 `server/app.ts` 与 `server/index.ts` 内自洽完成，避免依赖未列入白名单的新模块。

### 5. 认证与授权

1. `server/routes/auth.ts` 必须实现：
   - `POST /api/auth/register`
   - `POST /api/auth/login`
   - `GET /api/auth/me`
2. 注册要求：
   - 用户名唯一
   - 密码经 bcrypt 哈希后写入 `users.password_hash`
   - 初始资金默认为 1,000,000，并同步设置 `available_balance`
3. 登录成功返回 JWT；JWT 需由 `jose` 生成并在 `server/middleware/auth.ts` 中解析验证。
4. `server/middleware/auth.ts` 需为受保护路由注入当前用户身份，供订单、持仓、账户、成交等接口使用。
5. 认证失败、缺失 token、用户不存在等情况必须返回统一错误结构或至少一致的 HTTP 错误码，供前端 `web/src/api/client.ts` 处理。

### 6. 行情模拟引擎与行情接口

1. `server/engine/market.ts` 必须实现基于几何布朗运动（GBM）的 tick 生成逻辑，满足：
   - 每秒更新一次
   - 输入参数至少包含 `drift (μ)`、`volatility (σ)`
   - 输出价格被钳制在昨收价的 ±10% 范围内
   - 更新 `stocks.current_price/open_price/high/low/volume/turnover/updated_at`
   - 记录 `quotes` 快照
2. 行情引擎还必须生成 5 档买卖盘口数据，供：
   - `server/routes/quotes.ts`
   - `server/ws/quotes.ts`
   - `web/src/components/OrderBook.tsx`
   使用。
3. `server/routes/quotes.ts` 必须实现：
   - `GET /api/quotes/list`：返回股票列表及实时核心字段
   - `GET /api/quotes/:code`：返回单股详情、盘口、最新快照
   - `GET /api/quotes/:code/kline`：按 `1m/5m/15m/30m/60m/1d` 聚合 `quotes` 快照形成 K 线数据
4. 由于代码库中没有独立缓存或消息队列，行情内存态（例如盘口、订阅者列表、当日时间序列）需要由 `server/engine/market.ts` 与 `server/ws/quotes.ts` 在进程内维护。

### 7. 撮合引擎与风控

1. `server/engine/risk.ts` 必须封装下单前校验逻辑，至少覆盖：
   - 委托数量必须为 100 的整数倍（用户 PRD 写明 quantity 字段为“手”，但风控又要求 100 整数倍；实现规格需明确统一：对 API 入参建议按“股”接收并持久化到 `orders.quantity` 时采用“手”或统一按“股”衍生转换，否则会与测试标准冲突。执行时必须在 `shared/types.ts`、路由校验和测试中保持单一口径。）
   - 资金校验
   - 持仓校验
   - T+1：当日买入不可当日卖出
   - 涨停不可买入，跌停不可卖出
2. `server/engine/matching.ts` 必须实现：
   - 市价单：按当前最优价立即成交
   - 限价单：若当前价满足买/卖条件则即时成交，否则挂为 `pending` 并在后续 tick 到达时检查成交
   - 成交时生成 `trades` 记录、更新 `orders`、更新 `positions`、更新用户余额
3. 手续费规则必须严格体现在撮合逻辑中：
   - 买入：0.03%
   - 卖出：0.03% + 0.05% 印花税
4. 撤单规则：
   - `DELETE /api/orders/:id` 仅允许撤销未完全成交订单
   - 撤单后应释放冻结资金或冻结持仓（若采用冻结模型）
5. 由于没有白名单允许新增专门 service/repository 文件，`server/routes/orders.ts` 与 `server/engine/*.ts` 的职责边界需清楚：

   - 引擎负责业务判定与数据库写入

  - `positions`、`orders`、`trades`、`quotes` 的时间戳为整数；
  - `quotes.id` 为自增主键。
- `server/db/migrate.ts` 需负责以 better-sqlite3/Drizzle 初始化 SQLite 数据库并确保表存在；由于当前仓库没有现成 drizzle 配置文件，迁移逻辑应放在该文件内自包含完成。
- `server/db/seed.ts` 必须写入 PRD 指定的 20 只 A 股基础数据到 `stocks` 表，字段至少包括代码、名称、板块、初始价、昨收、开盘、当前价、高低价、成交量、成交额、更新时间。
- 由于允许修改文件列表中没有独立 DB client 文件，数据库连接与 schema 导出模式需在 `server/db/schema.ts` / `server/db/migrate.ts` / 使用方文件之间复用，而不能依赖新增未授权文件。

### 3. 共享类型

- `shared/types.ts` 必须定义前后端共享的核心类型，至少包括：
  - 用户认证载荷与 JWT claims；
  - 股票、盘口档位、tick、K 线、订单、持仓、成交、账户汇总、盈亏曲线点；
  - API 请求/响应体的 TypeScript 类型；
  - 订单方向、订单类型、订单状态、K 线周期等字符串联合。
- 所有后端路由返回与前端 store/API client 消费的数据形状，应以 `shared/types.ts` 为单一事实来源，减少前后端重复定义。

### 4. 认证与鉴权

- `server/routes/auth.ts` 需实现：
  - `POST /api/auth/register`：校验用户名/密码，密码以 bcrypt 哈希存储，用户创建时初始资金 `1_000_000`，可用资金与初始资金相同，冻结资金为 0；
  - `POST /api/auth/login`：校验凭据并签发 JWT；
  - `GET /api/auth/me`：基于 JWT 返回当前用户基础信息和资金字段。
- `server/middleware/auth.ts` 必须实现 Hono 中间件，负责：
  - 解析 `Authorization: Bearer <token>`；
  - 使用 `jose` 校验 JWT；
  - 将当前用户身份信息注入上下文，供 `server/routes/orders.ts`、`server/routes/positions.ts`、`server/routes/trades.ts`、`server/routes/account.ts`、`server/routes/auth.ts` 的 me 接口使用。
- JWT 密钥来源必须在当前允许文件范围内可配置；若无环境变量时需有开发态默认值，但规范中应标注这只是本地模拟用途。

### 5. 行情模拟引擎与 WebSocket

- `server/engine/market.ts` 必须封装行情模拟引擎，基于几何布朗运动（GBM）生成每秒 tick：
  - 输入至少包含 `drift (μ)`、`volatility (σ)`、当前价格、昨收；
  - 输出价格必须被限制在昨收 ±10% 范围内；
  - 更新 `stocks.current_price/open_price/high/low/volume/turnover/updated_at`；
  - 写入 `quotes` 快照，用于分时/K 线聚合。
- 引擎还必须生成 5 档买卖盘口数据，供 `GET /api/quotes/:code` 与 `WS /ws/quotes` 返回。
- `server/ws/quotes.ts` 必须实现 Hono WebSocket 行情推送端点 `/ws/quotes`，能向连接客户端广播全市场或单股行情更新。若 Hono 的 WS 集成需要在 `server/app.ts` 注册，也必须在那里完成。
- `server/routes/quotes.ts` 需实现：
  - `GET /api/quotes/list`：股票列表及最新行情；
  - `GET /api/quotes/:code`：单股详情，至少包含股票基本行情、涨跌幅、5 档盘口；
  - `GET /api/quotes/:code/kline`：按 `1m/5m/15m/30m/60m/1d` 返回 K 线数据。由于当前只有秒级 quotes 快照，K 线可由 `quotes` 表聚合生成。

### 6. 撮合引擎与风控

- `server/engine/risk.ts` 必须封装委托前校验逻辑，至少覆盖：
  - 委托数量必须为 100 整数倍；
  - 资金是否充足（买入）；
  - 可卖数量与 T+1 限制（卖出仅允许 `positions.available_quantity`）；
  - 涨停不可买、跌停不可卖。
- `server/engine/matching.ts` 必须封装订单撮合与结算逻辑，至少覆盖：
  - 市价单按当前最优价立即成交；
  - 限价单在价格满足时成交，否则保留 `pending` 状态；
  - 成交后更新 `orders.filled_quantity/filled_price/status/updated_at`；
  - 生成 `trades` 记录；
  - 结算资金与持仓：
    - 买入手续费 0.03%；
    - 卖出手续费 0.03% + 印花税 0.05%；
    - 买入更新/创建 `positions`；
    - 卖出减少 `positions.quantity` 与 `available_quantity`；
    - 买入冻结/扣减资金，撤单释放冻结资金。
- 由于只允许修改 `server/routes/orders.ts` 而没有单独服务层文件，订单路由必须调用 `server/engine/risk.ts` 与 `server/engine/matching.ts` 中的显式导出函数，保持职责分离。
- T+1 的实现需要在买入成交时将新增仓位记为当日不可卖；在现有限定文件中，推荐通过 `positions.available_quantity` 与买入时间/当日归集逻辑组合表达，并在 `server/routes/positions.ts` 返回可用数量。

### 7. 交易与账户 API

- `server/routes/orders.ts` 需实现：
  - `POST /api/orders`：下单，支持 `buy/sell`、`market/limit`；
  - `DELETE /api/orders/:id`：仅允许撤销仍未完全成交的订单，并释放相应冻结资金/冻结卖出数量；
  - `GET /api/orders`：返回当日委托；
  - `GET /api/orders/history`：返回历史委托。
- `server/routes/positions.ts` 实现 `GET /api/positions`，返回当前用户持仓、可卖数量、成本价、浮动盈亏。
- `server/routes/trades.ts` 实现 `GET /api/trades`，返回成交列表，至少支持按时间倒序。
- `server/routes/account.ts` 必须提供：
  - `GET /api/account/summary`：总资产、可用资金、冻结资金、持仓市值、累计盈亏、当日盈亏；
  - `GET /api/account/pnl`：收益分析序列，至少可供前端收益曲线图展示。
- `server/app.ts` 必须装配所有 API 路由与 WS 路由，形成单一 Hono app。
- `server/index.ts` 必须作为 Bun 启动入口，启动 DB 初始化、seed（幂等）以及 HTTP/WS 服务。

### 8. 前端架构与路由

- `web/src/main.tsx` 必须创建 React 19 应用入口，挂载路由、Ant Design 基础样式和全局状态。
- `web/src/App.tsx` 必须定义 React Router 7 路由：
  - `/login`
  - `/register`
  - `/dashboard`
  - `/market`
  - `/market/:code`
  - `/orders`
  - `/trades`
  - `/positions`

- `web/src/api/client.ts` 必须集中封装 REST 请求与 JWT header 注入，并处理 WebSocket 连接辅助函数（如实现放这里或 `web/src/stores/quotes.ts`）。

### 9. 前端状态管理

- `web/src/stores/auth.ts` 负责登录、注册、当前用户获取、token 持久化。
- `web/src/stores/quotes.ts` 负责：

- `web/src/stores/account.ts` 负责资产摘要、持仓、收益曲线。

### 10. 前端页面与组件

- `web/src/pages/Dashboard.tsx` 展示：

## Constraints

- 当前仓库探索结果显示：除 `package.json`、`tsconfig.json`、`prd-stock-trading-system.md`、`opencorvus.json` 外，没有现成 `server/`、`web/`、`shared/` 文件；因此本任务本质上是在“受限文件白名单”内从零搭建系统。
- 只能创建/修改用户列出的文件，不能补充常见辅助文件（例如 `.env`、`drizzle.config.ts`、独立 `db.ts`、额外 hooks/components/tests`）；因此实现必须将连接、配置、类型与工具集中收纳到已授权文件中。
- 用户明确指定技术栈，不能替换：
  - 后端必须是 Hono；
  - ORM 必须是 Drizzle ORM + better-sqlite3；
  - 认证必须是 JWT + jose；
  - 校验必须是 Zod；
  - 前端必须是 React 19 + Vite 6 + Zustand + Ant Design 5 + React Router 7 + Tailwind 4；
  - 图表必须使用 ECharts / echarts-for-react。
- 验收只明确要求 `bunx tsc --noEmit` 与 `bun test server/test/engine.test.ts` 通过，但规范仍要求路由、页面、类型与配置完整到可编译。
- 根级 `tsconfig.json` 当前 `moduleResolution` 为 `Bundler`，这对前后端共享是可行的，但实现必须避免 Node 专属 CommonJS 写法。
- 因项目是模拟交易系统，撮合可简化为“基于当前行情/盘口的单用户模拟成交”，不要求真实多用户订单簿竞价撮合；但接口与状态字段仍需符合 PRD。
- `better-sqlite3` 为同步驱动，后端实现应接受同步 DB 操作模式，并在 Hono route 中谨慎组织调用，避免假定异步事务 API。

6. `server/routes/positions.ts`、`server/routes/trades.ts`、`server/routes/account.ts` 返回能支撑前端持仓、成交、资产分析页面的数据，包含浮盈亏与收益曲线所需字段。

      - 更新 `orders.filled_quantity/filled_price/status/updated_at`
      - 写 `trades`
      - 买入：增加/新建 `positions.quantity`，并将新增股份先记入 `quantity`、但不增加 `available_quantity`（当日不可卖）
      - 卖出：减少 `positions.quantity` 和已冻结/可卖数量
      - 更新用户 `available_balance/frozen_balance`
      - 买手续费 0.03%，卖手续费 0.03% + 0.05% 印花税
    - `cancelOrder`：
      - 仅 `pending/partial` 可撤
      - 买单释放剩余冻结资金；卖单恢复未成交部分 `available_quantity`
      - 更新状态为 `cancelled`
    - `processPendingOrders`：由 `server/index.ts` 在每次行情 tick 后调用，遍历 `pending` 限价单，满足价格则成交。
