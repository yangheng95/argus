# v0.0.34beta Windows Native Package

## Recall

### 用户原始要求

- bump 到 0.34 分支再打包。

### 验收指标

- 从最新 `legacy-remote/v0.0.33beta` 创建 `v0.0.34beta`，保留本地已验证提交并纳入远端新增提交。
- 使用仓库版本同步工具把唯一 release family 更新为 `0.0.34-beta`，由 `bun run version:check` 正向确认所有 package、Cargo、Tauri、MSI 和 lock 投影一致。
- 在打包前把不可变源码提交推送到 `legacy-remote/v0.0.34beta`。
- 先执行 GUI（Graphical User Interface，图形用户界面）installer matrix，再执行 CLI（Command-Line Interface，命令行界面）binary matrix，不使用 `--skip-build`。
- 只声明当前 Windows x64 主机经真实 checker 接受的 row；其他平台明确 skipped。
- 独立复核产物文件名、版本、架构、大小和 SHA-256（Secure Hash Algorithm 256-bit，256 位安全散列算法）。
- 记录打包期间源码提交是否保持等于 legacy remote 远端，并把证据提交、推送。

### 硬约束

- `bun run package:gui-installer-matrix` 与 `bun run package:binary-matrix` 是唯一产物所有者；不手工拼装包。
- 不创建或运行 UI 自动化测试；产品 UI 只沿用本轮已完成的真实页面截图人工复核。
- 不使用 stash、reset、restore 或 `--no-verify`，不向 `origin` 推送。
- 精确保护当前工作区改动；生成的安装包、二进制和归档是 ignored output，不进入源码提交。
- commit subject 以 `dsw-33987` 开头。

## Plan

1. 提交当前已验证 MCP 静态凭证实现，基于 `legacy-remote/v0.0.33beta` 创建 `v0.0.34beta` 并只迁移本地独有功能提交。
2. 运行版本同步到 `0.0.34-beta`，执行版本、目标测试、类型、API、文档和差异检查。
3. 提交并推送不可变打包源到 `legacy-remote/v0.0.34beta`。
4. 设置 8 GiB Node.js heap，先运行 GUI installer matrix，再运行 CLI binary matrix，均不使用跳过构建参数。
5. 独立运行 release checker，检查版本、Portable Executable（PE，Windows 可移植可执行文件）架构、文件集合、大小与 SHA-256。
6. fetch legacy remote 证明打包期间源码是否稳定；写回验证账本，执行文档健康检查、二次 diff review、提交并推送证据。
