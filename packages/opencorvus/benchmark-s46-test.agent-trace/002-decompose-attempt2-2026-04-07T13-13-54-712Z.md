## 设计原则

- **实时优先**: 行情、委托状态、持仓盈亏必须实时响应，不允许用户依赖刷新页面确认结果。
- **交易优先**: 页面结构围绕”看盘 -> 判断 -> 下单 -> 跟踪 -> 复盘”组织，而不是围绕 CRUD 菜单组织。
- **高密度但不混乱**: 桌面端优先采用多栏布局、紧凑表格、固定数值对齐、明确分区。
- **结果可解释**: 每笔订单的状态变化、成交价格、资金变化必须能在界面上追溯。
- **风控前置**: 在输入阶段就提示可买数量、可卖数量、价格区间与错误原因，减少提交后报错。

## 行情模拟引擎

- 预置 10 只模拟股票（代码 SH600001-SH600010，中文名称）
- 服务启动时生成当日历史价格（模拟 9:30 开盘至今，每分钟一个 tick，约 240 点，以 OHLCV 格式存储于 `price_history`）
- 每 2 秒生成一次新 tick（更新当前 1 分钟 bar）：
  - 基于上一个价格 ± 随机波动（正态分布，σ = 0.5%）
  - 叠加趋势因子（每只股票有隐含趋势 -0.1% ~ +0.1%）
  - 涨跌幅限制 ±10%（基于当日开盘价）
  - 当前 bar 的 high/low 随 tick 持续更新，满 60 秒封闭当根 K 线，开启新 bar
- K 线聚合规则（kline 接口实时计算）：
  - `1m` — 原始每分钟 bar
  - `5m`、`15m` — 将 1m bar 按时间窗口合并：首根 open、末根 close、区间 high/low 极值、累计 volume
  - `1d` — 当天全部 1m bar 合并为一根日 K
  - 技术指标随 K 线响应一同返回：
    - MA5、MA10、MA20（close 的简单移动平均）
    - MACD：EMA12/EMA26 -> DIF；EMA9(DIF) -> DEA；BAR = (DIF − DEA) × 2
- 每次价格变动自动撮合挂单：
  - 买单：市价 ≤ 买入价 -> 成交
  - 卖单：市价 ≥ 卖出价 -> 成交
- 每次撮合后需要同步更新：
  - 用户余额与冻结资金
  - 持仓数量、可卖数量、成本价
  - 股票成交量
  - 成交记录与委托状态
  - SSE 推送载荷

**行情模拟引擎精确参数**

*正态分布随机波动实现*（绕过 Math.random() 精度不足的问题，使用 Box-Muller 变换）：
```typescript
function gaussianRandom(mean: number, sigma: number): number {
  const u = 1 - Math.random()  // (0, 1]
  const v = Math.random()
  const z = Math.sqrt(-2.0 * Math.log(u)) * Math.cos(2.0 * Math.PI * v)
  return mean + sigma * z
}
// 每次 tick: priceChange = gaussianRandom(0, 0.005) + trend
// trend 范围: -0.001 ~ +0.001 (每个股票固定，服务启动时确定)
```

*开盘价*（服务启动时从种子数据读取，不重新随机）：使用 `stocks` 表中 `open_price` 字段的固定值，不受每次重启的影响。

*历史价格预生成规则*：
```
t = 0         → open_price（种子表中固定值）
t = 1..239    → price(t) = price(t-1) × (1 + gaussianRandom(0, 0.005) + trend)
                限制：price(t) 不超出 open_price × [0.90, 1.10]
每分钟 bar volume → 随机整数，范围 [10000 * baseVol, 50000 * baseVol]（baseVol 见种子表）
每根 bar 的 high/low → 在 open/close 基础上添加 gaussianRandom(0, 0.002) 的上下振幅
                       high = max(open, close) + abs(gaussianRandom(0, 0.002)) × max(open,close)
                       low  = min(open, close) - abs(gaussianRandom(0, 0.002)) × min(open,close)
```

*`daily_snapshots` 写入时机*：每日服务启动时，写入一条昨日快照（`total_assets = 1,000,000`，新账户）；之后每次 SSE tick 周期（2 秒）不写入快照——快照仅在每分钟整点（`tick_count % 30 === 0`，即每 60 秒）写入一次，保留最近 30 天 × 每日 1 条（取最后一条）。

## 个股新闻生成引擎（`src/news.ts`）

### 设计目标

用情绪驱动的随机新闻让模拟系统具有"真实市场"氛围感，提升演示体验。新闻不落入数据库，仅在内存中维护（每只股票最多 50 条，全市场混排队列最多 100 条），服务重启后重新生成。

### 生成逻辑

- 服务启动时为每只股票预生成 8 条历史新闻（模拟早盘前已发布）
- 此后每只股票每 30~120 秒（独立随机间隔）追加一条新新闻
- 情绪类型按当前涨跌幅加权随机选取：
  - `涨幅 > 3%` → 利好 70% + 中性 20% + 利空 10%（噪音）
  - `跌幅 > 3%` → 利空 70% + 中性 20% + 利好 10%（噪音）
  - `波动 ±3%` → 利好 40% + 利空 40% + 中性 20%
- 每条新闻数据结构：
  - `id`: UUID
  - `stock_code`: 股票代码（全市场新闻为 `MARKET`）
  - `title`: 标题（15-40 字，从模板插值）
  - `summary`: 摘要（50-120 字）
  - `sentiment`: `positive` | `negative` | `neutral`
  - `source`: 轮换自「东方财富」「证券时报」「21 世纪经济报道」「界面新闻」「上海证券报」
  - `impact`: `high` | `medium` | `low`
  - `created_at`: Unix 时间戳

## 交易规则与风控

- 密码用 Argon2 哈希存储
- 未认证请求返回 401
- 用户只能操作自己的订单、自选股和持仓
- 交易数量必须是 100 的整数倍（1 手 = 100 股）
- 挂单价格限制：当前价 ±10%
- 买入校验：可用资金 ≥ 数量 × 价格
- 买入挂单未成交前，相应资金进入冻结态
- 卖出校验：持仓数量 ≥ 卖出数量
- 卖出挂单未成交前，相应可卖持仓进入冻结态
- 撤单成功后恢复对应冻结资金或可卖持仓
- 价格、数量、股票代码必须进行基础格式校验，返回明确错误文案
- 所有涉及资金的接口返回最新资产摘要，避免前端自行推算

  ```typescript
  // 在 <Bar dataKey="close" shape={<CandlestickBar />} /> 中使用
  // props 由 Recharts 注入：x, y, width, height, payload
  function CandlestickBar(props: any) {
    const { x, y, width, payload, yAxis } = props
    const { open, high, low, close } = payload

    // yAxis.scale 是 Recharts 注入的 y 坐标比例函数
    const yOpen  = yAxis.scale(open)
    const yClose = yAxis.scale(close)
    const yHigh  = yAxis.scale(high)
    const yLow   = yAxis.scale(low)

    const isUp    = close >= open
    const color   = isUp ? '#ff5b5b' : '#27c281'
    const strokeC = isUp ? '#cc3333' : '#1a9960'  // 边框加深 20%

    // 实体矩形
    const bodyTop    = Math.min(yOpen, yClose)
    const bodyBottom = Math.max(yOpen, yClose)
    const bodyHeight = Math.max(bodyBottom - bodyTop, 1)  // 最小高度 1px，平收不消失
    const bodyX      = x + width * 0.1
    const bodyWidth  = width * 0.8

    // 上下影线（始终居中于实体）
    const wickX = x + width / 2

    return (
      <g>
        {/* 上影线 */}
        <line x1={wickX} y1={yHigh} x2={wickX} y2={bodyTop}
              stroke={color} strokeWidth={1} />
        {/* 实体 */}
        <rect x={bodyX} y={bodyTop} width={bodyWidth} height={bodyHeight}
              fill={isUp ? color : color}
              stroke={strokeC} strokeWidth={0.5}
              fillOpacity={close === open ? 0 : 1} />
        {/* 平收：用灰色空心矩形 */}
        {close === open && (
          <rect x={bodyX} y={bodyTop - 0.5} width={bodyWidth} height={1}
                fill="#607089" />
        )}
        {/* 下影线 */}
        <line x1={wickX} y1={bodyBottom} x2={wickX} y2={yLow}
              stroke={color} strokeWidth={1} />
      </g>
    )
  }
  ```
  > **注意**：`yAxis.scale` 必须从 Recharts 注入的 props 中取，不能自行推算，否则坐标错位。如果 Recharts 不注入 yAxis.scale，需通过 `useRef` + `onMouseMove` 手动维护价格→像素映射。

### 主题方向

  - 中性信息：蓝灰色

### 排版

- 使用更有终端感的英数字体与中文无衬线搭配，避免默认系统栈的平庸观感
- 大数字区域采用更大的字重与更紧凑的字间距
- 表格数字必须启用等宽数字样式，减少跳动感
- 页面标题、股票代码、价格数字应形成三级信息层级，一眼看出重点

### 布局密度

- 桌面端采用三段式：顶部账户条 + 主内容区 + 底部状态区或表格区
- 行情页与个股页优先使用多栏布局，避免大面积留白
- 表格、卡片、图表边距统一，控制在紧凑区间，呈现交易软件的“压缩感”与效率感

### 图表样式

- 分时图：折线使用 accent 色（`#3bc9db`），面积区域为渐变填充——当日涨时用红色系渐变（`#ff5b5b` -> 透明），跌时用绿色系渐变（`#27c281` -> 透明），基准线从昨收价处展开

  **分时图实现细节**：
  - 使用单个 `ComposedChart`（无需三联图），包含：`<Area>` 折线+面积 + `<Bar>` 成交量（下方 20% 高度独立 Y 轴）
  - 基准线（昨收价）：`<ReferenceLine y={prevClose} stroke="#607089" strokeDasharray="4 2" strokeWidth={0.5} />`
  - 折线颜色跟随当前价 vs 昨收价：`currentPrice >= prevClose ? '#ff5b5b' : '#27c281'`（实时跟随 SSE 刷新）
  - `<defs>` 渐变色定义：
    ```jsx
    <linearGradient id="intraday-up" x1="0" y1="0" x2="0" y2="1">
      <stop offset="0%"   stopColor="#ff5b5b" stopOpacity={0.35} />
      <stop offset="100%" stopColor="#ff5b5b" stopOpacity={0} />
    </linearGradient>
    <linearGradient id="intraday-down" x1="0" y1="0" x2="0" y2="1">
      <stop offset="0%"   stopColor="#27c281" stopOpacity={0.35} />
      <stop offset="100%" stopColor="#27c281" stopOpacity={0} />
    </linearGradient>
    ```
  - Area fill 动态绑定：`fill={currentPrice >= prevClose ? 'url(#intraday-up)' : 'url(#intraday-down)'}`
  - X 轴：显示 9:30 / 10:00 / 10:30 / 11:00 / 11:30 / 13:00 / 13:30 / 14:00 / 14:30 / 15:00 共 10 个固定时刻刻度
  - Y 轴：左侧显示价格（2 位小数），右侧显示涨跌幅（相对昨收，`±x.xx%`）——使用 `yAxisId="price"` 和自定义 `tickFormatter`

- K 线蜡烛图：涨实体红（`#ff5b5b`）、跌实体绿（`#27c281`），影线同色，实体边框加深 20%，平收时以灰色实体表示
- MA 均线细而不抢眼，strokeWidth 1，opacity 0.85
- MACD BAR：正值红色，负值绿色；DIF 与 DEA 使用对比明显的两种线色，不与 MA 冲突
- 热力图色阶：最大涨（`#7f1d1d`）→ 涨（`#ff5b5b`）→ 平盘（`#1e293b`）→ 跌（`#27c281`）→ 最大跌（`#064e3b`）
- 图表网格线低对比（`#233044` 细线），背景透明，弱化装饰感
- 鼠标 hover 交叉线：颜色 `#607089`，0.5px 宽；信息面板固定于图表左上角，不随鼠标浮动

### 动效与反馈

- 首屏卡片、表格和图表采用轻量级分段进入动画，速度快，不拖泥带水
- 数字刷新使用瞬时变色或轻微闪动，强化“有数据流动”感
- 下单、撤单、成交反馈采用顶部 toast 或侧边消息流，不阻塞操作
- 禁止使用夸张弹簧动画或泛用玻璃拟态效果

### 响应式

- 桌面优先，1440 宽度下信息密度最佳
- 平板可用，允许部分侧栏折叠
- 移动端不是本期重点，但必须保证核心表格与交易表单可浏览，不出现布局崩坏

### 数字格式

- 价格保留 2 位小数
- 百分比保留 1 位小数
- 金额千分位分隔
- 成交量可使用 `万`、`亿` 简写，但 tooltip 中显示完整数值
- 时间统一展示为本地时区格式

```sql
CREATE TABLE users (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  username TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,
  balance REAL NOT NULL DEFAULT 1000000,
  frozen_balance REAL NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL DEFAULT (unixepoch())
);

CREATE TABLE sessions (
  token TEXT PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  created_at INTEGER NOT NULL DEFAULT (unixepoch())
);

CREATE TABLE stocks (
  code TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  open_price REAL NOT NULL,
  current_price REAL NOT NULL,
  high_price REAL NOT NULL,
  low_price REAL NOT NULL,
  prev_close REAL NOT NULL,
  volume INTEGER NOT NULL DEFAULT 0,
  trend REAL NOT NULL DEFAULT 0,
  updated_at INTEGER NOT NULL DEFAULT (unixepoch())
);

CREATE TABLE price_history (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  stock_code TEXT NOT NULL REFERENCES stocks(code),
  price REAL NOT NULL,
  volume INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL DEFAULT (unixepoch())
);

CREATE TABLE orders (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  stock_code TEXT NOT NULL REFERENCES stocks(code),
  direction TEXT NOT NULL CHECK(direction IN ('buy', 'sell')),
  quantity INTEGER NOT NULL,
  price REAL NOT NULL,
  frozen_amount REAL NOT NULL DEFAULT 0,
  status TEXT NOT NULL DEFAULT 'pending' CHECK(status IN ('pending', 'filled', 'cancelled')),
  filled_at INTEGER,
  created_at INTEGER NOT NULL DEFAULT (unixepoch())
);

CREATE TABLE positions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  stock_code TEXT NOT NULL REFERENCES stocks(code),
  quantity INTEGER NOT NULL DEFAULT 0,
  available_quantity INTEGER NOT NULL DEFAULT 0,
  cost_basis REAL NOT NULL DEFAULT 0,
  UNIQUE(user_id, stock_code)
);

CREATE TABLE watchlists (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  stock_code TEXT NOT NULL REFERENCES stocks(code),
  created_at INTEGER NOT NULL DEFAULT (unixepoch()),
  UNIQUE(user_id, stock_code)
);

CREATE TABLE daily_snapshots (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  total_assets REAL NOT NULL,
  cash REAL NOT NULL,
  market_value REAL NOT NULL,
  created_at INTEGER NOT NULL DEFAULT (unixepoch())
);
```
