`packages/channel-runtime/` 是 OpenCorvus 的多 IM 接入层。它把外部消息平台统一抽象为**三元组**：

```
platform : channel : thread
```

每条 thread 对应一个 OpenCorvus session，thread 里的所有消息共享同一任务上下文。

## 运行 channel-runtime

```bash
cd packages/channel-runtime
cp .env.example .env    # 填入你要启用的 channel 的 token
bun run dev             # 实际执行 bun run src/main.ts
```

`registerAdapters()`（`src/registry.ts:242`）会自动扫描 env，**只启动配置了必要 token 的 channel**，其他跳过——不会因为某个 channel 没配置就崩。

## 与 OpenCorvus 后端的通信

| 方向                         | 协议             | 端点                                                                                                                               |
| ---------------------------- | ---------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| channel-runtime → OpenCorvus | HTTP REST (JSON) | `/session`、`/session/{sessionID}/prompt_async`、`/tui/runtime/start`、`/tui/runtime/submit-task`、`/permission/{requestID}/reply` |
| OpenCorvus → channel-runtime | SSE              | `/event`                                                                                                                           |

SDK：`@opencorvus-ai/sdk`。

两种启动模式：

1. **Embedded**：`createOpenCorvus()` 在进程内嵌入启动后端
2. **External**：`createOpenCorvusClient({ baseUrl })` 连到已跑的 `opencorvus serve`

## 消息流（通用）

```
用户在 IM 里发消息
  ↓
<Platform>Adapter.onMessage(IncomingMessage)
  ↓
ChannelRuntime.handleMessage()      [src/core.ts:235]
  ├─ 若是音频 → STTPipeline.transcribe()
  ├─ SessionCoordinator.get(threadKey) 查已有 session
  ├─ 无 session → client.session.create() 创建新 session
  └─ client.session.promptAsync() 投递任务

OpenCorvus 后端处理中 → SSE 事件流回
  ↓
handleEvent(event)                  [src/core.ts:1132]
  ├─ task.report → safeSend() 进度/完成/失败
  ├─ message.updated → 文本累积 → safeSend()
  ├─ part.updated(image) → uploadImage()
  └─ permission.asked → 自动/手动回复
```

## 扩展新 channel 的三步

1. **注册**：在 `packages/channel-config/src/index.ts` 的 `ChannelCatalog` 里 `define({...})`，声明 id、必填字段、对应 env 名。
2. **适配器**：在 `packages/channel-runtime/src/adapters/` 下实现 `ChannelAdapter` 接口（`src/adapter.ts:9`），至少实现 `start / stop / sendMessage / onMessage`，可选 `uploadImage / startThread`。
3. **接线**：在 `packages/channel-runtime/src/registry.ts` 的 `AdapterOptions` 与 `build()` switch 里加 case；在 `main.ts` 的 `registerAdapters()` 传入工厂函数。

详见 [Slack 实现](./slack.md) 作为参考样板。
