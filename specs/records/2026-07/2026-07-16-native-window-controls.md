## Root cause

The main window disables operating-system decorations for every platform. `WindowControls.tsx` then draws three Lucide SVG buttons inside the HTML titlebar and calls Tauri minimize/maximize/quit methods. Because the visual owner is the web frontend rather than AppKit, Win32, or the Linux window manager, macOS cannot render its native traffic-light controls or native window semantics.

## Implementation

1. Enable Tauri decorations as the cross-platform source of minimize, maximize, and close chrome. Use Tauri's macOS overlay titlebar, hidden title, and traffic-light positioning so AppKit controls occupy the existing 36-pixel titlebar rather than adding a second bar.
2. Inject the build target platform through the existing Vite compile-time configuration and publish a macOS native-titlebar data attribute only in a Tauri host. The titlebar CSS uses that explicit build/host evidence to reserve AppKit's leading control area; browser and VS Code hosts do not receive the inset.
3. Delete the frontend `WindowControls` component, mount, dedicated HostTransport UI capabilities, and dedicated CSS/test fixtures. Keep generic close/minimize/maximize icons where other product surfaces use them.
4. Add one nonvisual native-close lifecycle owner. It listens to Tauri's native close request, prevents the default close, asks with the existing localized confirmation, and invokes the existing `window.quit` command so backend cleanup remains authoritative.
5. Update source, browser, configuration, and lifecycle tests; verify the production bundle and Rust configuration/runtime tests. Capture and personally inspect a task-scoped isolated browser screenshot of the titlebar content geometry without touching the user's running native Overlay.

## Outcome

- Tauri now owns decorated window chrome. The main window uses native decorations on every desktop platform and the supported macOS overlay-titlebar fields (`hiddenTitle`, `titleBarStyle`, and `trafficLightPosition`) for AppKit traffic lights inside the existing compact titlebar.
- The Solid `WindowControls` component, its mount, two HostTransport UI capability flags, dedicated Button/titlebar CSS, four retired locale labels, and simulated browser fixtures were deleted. No frontend fallback remains.
- Native close requests synchronously prevent the operating system's default close, reuse the localized confirmation, and then call the existing `window.quit` command, which stops the backend before exiting.
- Passed 16 focused source tests, Overlay TypeScript, Vite production build, Rust tests, historical-document links, document health after staging, and `git diff --check`.
- A Node-served production build was opened in the in-app browser without touching the user's running Overlay. The task-scoped titlebar screenshot at `.scratch/native-window-controls-titlebar.png` was personally inspected: the row remains 36 pixels tall, navigation and File/Edit/View/Help remain aligned, and the rendered DOM contains zero simulated window controls. Tauri/AppKit chrome cannot be composited into a browser screenshot; its configuration was instead validated by the focused configuration regression and Rust/Tauri compilation.
- The broader existing titlebar browser file still has unrelated failures for a concurrently changed theme color expectation and retired global/right-toolbar DOM fixtures. Its responsive titlebar/locale subtest passed; these failures do not intersect the native window-control paths and were not hidden or rewritten as acceptance evidence.
