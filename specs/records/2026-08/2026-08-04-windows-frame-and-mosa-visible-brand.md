## Causal chain

1. The new Windows package visibly lost the boundary between the transparent frameless client and the desktop.
2. Commit `e9815258b7` added `shadow: false` at the same time the window became transparent; non-macOS startup still removes decorations before reveal.
3. That combination disables the native shadow/outline owner while leaving no legitimate replacement. The root repair is to remove the shadow suppression and let Tauri/Win32 restore the system-owned boundary, not to add a CSS border inside the WebView.
4. Visible branding is currently scattered across two rendered components, startup/native chrome, native tray/menu/error copy, and two locale catalogs. The rebrand is a display contract only; changing persistent/runtime/protocol identity would create an unrelated migration and break package/tool contracts.
