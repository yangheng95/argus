## Overview

AInvest Nova is a professional-grade financial data and trading platform. The visual language is **data-dense, precise, and trustworthy** — built for investors who need rapid information scanning and decisive action. The interface layers clean typography over a systematic color grammar where every hue carries semantic meaning: price direction, status, hierarchy. The platform supports both light and dark modes, each with its own full token set. The design intent is Bloomberg-meets-modern-SaaS: serious but not cold, dense but not cluttered.

***

## Colors

### Brand
- **Primary (#165DFF light / #3371FF dark):** The signature brand blue. Reserved for primary CTAs, selected states, and the logo. Should feel energetic but controlled.
- **Brand black variant:** HSL dark mode adaptation for the brand primary in inverted contexts.

### Price signals (the most semantically critical palette)
- **Up (#009B67 / #00A36D):** Positive price movement, gains, success states. Use with confidence.
- **Down (#FF381A / #FF4A2E):** Negative price movement, errors, destructive actions. High urgency.
- **Even (#000 / #FFF):** Flat/unchanged price. The only neutral in the price grammar.
- **Crypto Up (#2DD0D0) / Crypto Down (#E9528F):** Dedicated crypto market colors — distinct from equities to prevent cognitive cross-contamination.
- **Reversed mode:** `stock-color-mode=reverse` inverts up/down for certain market conventions.

### Text hierarchy (light mode primary)
- **Primary (#000):** Body copy, headlines, any high-emphasis text.
- **Secondary (60% opacity):** Subheadings, metadata, labels that support primary content.
- **Tertiary (40%):** Timestamps, secondary metadata, decorative text.
- **Quaternary (20%):** Disabled states, placeholder content, dividers-as-text.
- **Inverse (#FFF):** Text rendered over dark/colored backgrounds.
- **Link (#165DFF):** Inline hyperlinks. Consistent with brand primary.

### Background layers (elevational system)
- **Layer 1 (#F2F2F2):** Root page background. The base canvas.
- **Layer 2 (#F2F2F2):** Slightly elevated surface — cards, sidebars.
- **Layer 3 (#FFF):** Cards, modals, interactive surface elements.
- **Layer 4/5 (#FFF):** Nested containers, widget backgrounds.
- **Mask levels 1–3:** Overlay scrims at 80%, 60%, 20% black for modal backdrops.
- **Nav (#FFF / #171717):** Navigation bar. Distinct from content background.

### Dividers
- **Level 1 (20% opacity):** Primary structural dividers between sections.
- **Level 2 (10%):** Intra-component separators, table borders, list dividers.
- **Level 3 (5%):** Subtle hairline separators, decorative borders.

### Greyscale
- A full grey ramp from `#F7F7F7` (97) to `#000` (0). Used for illustration, placeholder states, disabled backgrounds, and any neutral tone that doesn't carry emotional weight.

### Accent palette (charts and data visualization)
The full spectrum: blue, green, red, orange, yellow, cyan, acid blue, indigo, purple, gold. Each has a matching `transparent-*` variant at 10–20% opacity for backgrounds behind charts and badges.

### Interactive states
- **Hover (5% black / 20% white in dark):** Subtle background fill on interactive row/card hover.
- **Click (10% / 25%):** Pressed/active state fill.
- **Inverse variants:** Used on dark backgrounds where normal hover would be invisible.

## Elevation & Depth

### Shadows
- **Small:** `0 0 8px 0 rgba(0,0,0,0.12)` — card hover, floating elements.
- **Medium:** `0 4px 12px 0 rgba(0,0,0,0.12)` — modals, dropdowns.
- **Large:** `0 0 20px 0 rgba(0,0,0,0.12)` — prominent overlays.
- Shadows are light-mode-only in practice; dark mode relies on grey-layer elevation instead.

## Shapes

### Border radius
The atom radius system (`--atom-radius-*`) spans from 0 to 20px, with Tailwind-extended `sm`/`md`/`lg`/`xl` referencing the CSS variable `--radius` (0.5rem / 8px). The dominant shape language is **rounded** (4–8px) for interactive surfaces, **fully rounded** (`9999px`) for buttons and badges, and **sharp** (0–2px) for dividers and data table cells.

***

## Components

### Buttons
Six variants — `primary` (brand fill), `default` (black fill), `secondary` (grey fill), `text` (no background), `link` (brand text), `outline` (border only). Four sizes from `xs` (24px) to `lg` (44px). All buttons use `border-radius: 50%` (pill shape). Hover states reduce opacity or shift fill color; disabled states reduce opacity and desaturate.

### Cards
Default card uses `layer3` background with 8px radius and 24px padding. No shadow by default; use `card-elevated` for floating cards needing depth.

### Badges
`badge-up` / `badge-down` use transparent tinted backgrounds with matching status color text — the canonical way to display price change in data tables and news items.

### Inputs
Border-based inputs use `border-bt` color and `medium` radius. Focus states use the browser default ring (configured in globals.css via Tailwind's `ring-*` utilities).

### Segmented controls
Used for view-mode switches (e.g., chart timeframes). Pill-shaped container with `segmented-controls-bg` background; active segment shows `segmented-controls-fg` fill.

### Tooltips / Toast
Background `#383838`, white text, `medium` radius. Used for keyboard shortcuts, hover explanations, and notification toasts.

### Dividers
Use `divider-level2` as the default intra-component rule. `level1` for section breaks. `level3` for subtle decorative hairlines.

### Scrollbars
Custom webkit scrollbars: 5px width, `divider-level2` thumb color, transparent track. The `custom-scrollbar` class widens to 12px with rounded thumb for scrollable panels.

### Navigation
`background-nav` with `navbar: 54px` height. Sidebar layout triggers at `662px` minimum width.

## Do's and Don'ts

- **Do** use atom color CSS variables (`--atom-color-*`) via Tailwind utilities (`bg-brand-primary`, `text-text-secondary`, `border-divider-level1`) in all new components.
- **Do** use semantic price signal colors (`price-up`, `price-down`) whenever displaying price movement — not generic green/red.
- **Do** apply the `badge-up` / `badge-down` component pattern for inline price changes in tables and news feeds.
- **Do** support both light and dark modes. The dual-mode token set in `variables-v1.css` covers every color; always use token references, never hardcoded hex.
- **Don't** introduce new colors without extending the atom token system first. Every new color needs a `--atom-color-*` CSS variable in `variables-v1.css` and a corresponding Tailwind mapping in `tailwind.config.ts`.
- **Don't** use `border-radius: 0` on interactive elements — the platform's shape language is rounded. Reserve sharp corners for data tables and dividers.
- **Don't** nest button variants. `button-primary-hover` is a sibling entry, not `button-primary.hover`.
- **Don't** apply shadows in dark mode — use the grey background layers (layer3, layer4) to create elevation contrast instead.
- **Don't** mix the news font (NewYork/PTSerif) with UI elements — it is exclusively for editorial/article headline typography.
