当前 engine schema 位于 `packages/opencorvus/src/engine/engine.sql.ts`。运行时读取走 `packages/opencorvus/src/engine/store.ts`，其中多种逻辑 row 从 append-only artifact 重建。

## 概念关系

```
EngineTask (kind: "workflow" | "build")
 ├─ EngineSpecSnapshot / EngineRequirement
 ├─ EnginePlanVersion
 │   ├─ EngineGoal[]
 │   └─ EnginePlanNode[]
 ├─ RunRow                  从 engine_artifact kind="run" 重建
 ├─ GoalRunRow[]            从 engine_artifact kind="goal_run_attempt" 重建
 ├─ AcceptanceRow[]         从 engine_artifact kind="acceptance" 重建
 └─ EvaluationRow[]         从 engine_artifact kind="verification-evidence" 重建
```

`engine_artifact` 是 run、goal attempt、acceptance、evaluation、integrity attempt、report、diff、image 等证据的持久化表面。

## EngineTask

`EngineTaskTable` 存储用户请求与任务级元数据：

| 字段 | 说明 |
|---|---|
| `kind` | `"workflow"` 走 pipeline workflow；`"build"` 走 direct build |
| `executor` | `opencorvus`、`codex` 或 `claude-code` |
| `request` / `title` | 用户可见的任务契约 |
| `attachments` | 用户契约附件 |
| `system_artifacts` | 系统生成材料，如截图和 rendered evidence |
| `criteria_results` | Overlay quality panel 使用的汇总 |
| `time_started` / `time_completed` / `error` | 派生 task status 的来源字段 |

`deriveTaskStatus` 从时间戳、错误、取消 metadata 和 run 状态派生任务状态。

## Requirements 和 Specs

`EngineSpecSnapshotTable`、`EngineSpecItemTable` 与 `EngineRequirementTable` 存储由 `requirements` workflow tool / agent 写入的 requirements 阶段产物。

## PlanVersion、Goal、PlanNode

Architect agent 写入：

| 实体 | 说明 |
|---|---|
| `EnginePlanVersionTable` | active 或 superseded 的计划版本 |
| `EngineGoalTable` | Goal contract 字段：objective、acceptance specs、dependencies、ownership、priority、kind |
| `EnginePlanNodeTable` | 把 goals 连接到 active plan 的计划图行 |

UI 和 prompt 中的 goal 状态都从 goal-run attempt 链派生。

## RunRow

`RunRow` 从 `engine_artifact.kind="run"` 的 artifact 重建。状态集合：

```
queued | accepted | running | blocked | completed | failed | aborted
```

workflow 进度从 artifacts 与 workflow tool side effects 投影。

## GoalRunRow

`GoalRunRow` 从 `engine_artifact.kind="goal_run_attempt"` 的 artifact 重建。

| 字段 | 说明 |
|---|---|
| `goal_id` | 正在实现的 goal |
| `status` | `queued / accepted / planning / running / evaluating / blocked / completed / failed / aborted` |
| `workspace_dir` / `workspace_branch` | 隔离 goal workspace |
| `workspace_base_ref` / `merge_ref` | replay / merge 使用的 snapshot/git 引用 |
| `supersede_of` | 连接 retry/rework attempt，并保留之前的证据 |
| `owner` | 进程 owner，用于重启后识别 orphaned live attempt |

最新且未被 supersede 的 attempt 是 goal 进度的权威来源。

## Acceptance 和 Evaluation

`AcceptanceRow` 从 `engine_artifact.kind="acceptance"` 重建，记录 candidate / publishing / delivered / failed 的 acceptance statuses。

`EvaluationRow` 从 `engine_artifact.kind="verification-evidence"` 重建，记录 task-level 或 goal-run 证据：

| 字段 | 说明 |
|---|---|
| `scope` | `goal_run` 或 `acceptance` |
| `status` | `pending / passed / failed / inconclusive` |
| `verdict` | `accepted / rejected / inconclusive` |
| `checks[]` | 检查摘要、证据指针和 scorer metadata |

## 状态持久化

所有任务领域状态存 SQLite，位置由 OpenCorvus 数据目录配置决定。Server 重启后，UI 从 engine tables 与 artifacts 恢复任务上下文；orchestrator 只在真实 wake/message 到来后继续下一次决策。
