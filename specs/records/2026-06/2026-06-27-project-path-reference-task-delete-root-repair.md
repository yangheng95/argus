## Independent Review Follow-Up

Independent review found four gaps:

- `deleteSession(...deleteTasks:true)` still skipped `deleteTask`'s settlement waits. Fixed by adding `awaitPipelineSettled()` and `awaitTaskLoopIdleForDelete()` before breadcrumbs and row deletion, with `delete-session-delete-tasks-settle.test.ts`.
- Path alias coverage only proved symlink/junction realpath equality. Fixed by adding `Project.sameFilesystemLocation()` with realpath plus `dev:ino` identity comparison, and by stopping `Filesystem.resolve()` from canonicalizing selected directories before project identity resolution.
- `source_reference_artifact` schema accepted `webpage-evidence/reference.png` even though submit validation only accepts `web-clone-source`. Fixed by allowing only `web-clone-source/reference*.png` or paths ending in `/web-clone-source/reference*.png`, with schema and tool-entry tests.
- `realpath()` failures were previously collapsed to "not equal". Fixed so only missing paths (`ENOENT` / `ENOTDIR`) compare as absent; permission, mount, and other filesystem failures throw.
- `deleteSession(...deleteTasks:true)` had only a positive settlement test. Fixed by adding a failure-path test proving task/session rows and delete breadcrumbs remain untouched when task-loop idle settlement fails.
- `Instance.provide` preserved aliases but still keyed active instances by exact Windows casing. Fixed by folding only the cache lookup key on Windows while preserving the visible selected directory in the active context.
- Local sidecar crash review found the remaining process-exit class was not DB deletion itself. `SessionPromptState` read/cancel/finish helpers still needed to address existing prompt owners by `sessionID` / abort signal after the active Instance context disappeared, and prompt-settlement waiting could not subscribe to instance-scoped `Bus` from a server-route delete path. Fixed with owner lookup before ambient-directory lookup, Bus-free inactivity settlement, and a delete-task regression that cancels a child prompt from an HTTP/no-Instance path, then lets an asynchronous no-directory finish callback settle without process errors.

## Acceptance

- Opening `/project/current?directory=<visible-alias>` creates/returns a project using the selected visible root, not the physical target path.
- Opening the same Windows project path through casing variants reuses one active instance without realpath-canonicalizing the visible path.
- Opening a repo through a visible path alias records `project.worktree` as the selected visible root when the selected directory and Git top-level identify the same filesystem location.
- Opening a real linked git worktree still records the primary repo root as `project.worktree` and the linked worktree as sandbox.
- Existing same-project rows using a filesystem-equivalent physical path are rewritten to the selected visible path instead of throwing `ProjectWorktreeIdentityConflictError`.
- `cancelTask` remains non-destructive.
- `deleteTask` and `deleteSession(...deleteTasks:true)` wait for task-owned execution to settle, then leave task-runtime breadcrumbs naming the delete origin before deleting rows.
- Deleting an active task from a server route with no active `Instance` must not crash the sidecar when the cancelled prompt loop finishes later without an explicit directory.
- Frontend-design reports distinguish rendered skeleton previews from source reference screenshots, and source reference artifacts must come from the `web-clone-source/reference*.png` artifact path.
