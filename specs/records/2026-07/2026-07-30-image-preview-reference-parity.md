## Causal analysis

| Layer                                | Evidence                                                                                                                                                                                                                                                                                                                            |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Observable symptom                   | The current preview still reads as a bounded utility window with a filename chip and a dense top toolbar, while the reference is a full-shell media viewer whose image and minimal floating controls dominate. Copy also consumes permanent toolbar space even though the requested interaction is contextual to the image.         |
| Direct trigger                       | `ImagePreviewHost` renders zoom, fit-width, fit-image, 1:1, and copy controls inside `Dialog.headerActions`; `messages.css` limits the form to 1180 × 820, keeps a visible title, and positions the full toolbar at the top.                                                                                                        |
| Deeper cause                         | The earlier visual repair detached the old titlebar but preserved its application-window information architecture. The preview’s canonical behaviors are correct, yet its visible chrome still models every capability as an always-visible command instead of matching a focused media-inspection surface.                         |
| Why prior work did not finish parity | The July 28 repair targeted outer radius and toolbar crowding while explicitly retaining all visible controls. The new reference and user instruction now establish a tighter composition and move Copy to contextual interaction, so the single host must be re-composed rather than patched with more CSS around the old toolbar. |

## Implementation plan

1. Recompose `ImagePreviewHost` into a full-shell dialog with no visible filename title, a top-right download/close action group, and a bottom-center zoom capsule.
2. Wrap the canonical visible image with the shared Kobalte `ContextMenu`; its Copy image item invokes the existing single-source PNG clipboard path and reflects in-flight state.
3. Keep fit-width, fit-image, and 1:1 functions as internal behavior owners for initial sizing and existing interaction semantics, while removing their obsolete always-visible toolbar buttons.
4. Replace only image-preview CSS so the form fills the legal overlay shell, the backdrop matches the reference dimming, floating actions use shared tokens, the image remains the real context-menu target, and long images remain scrollable/pannable.
5. Build and typecheck without running or modifying UI tests. Start an isolated real Overlay page, open a real preview, inspect the closed/open/right-click states, capture goal-bound screenshots, and correct visual defects.
6. Run documentation health checks required by the new record, inspect the scoped diff twice, commit task-owned paths with the `dsw-33987` prefix, and push the current branch to `legacy-remote`.
