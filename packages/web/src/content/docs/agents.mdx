OpenCorvus's orchestration is built around **agents**. A single task can spawn multiple agents — primary planners, executors, and one-shot sub-agents dispatched for parallel goals.

Source: `packages/opencorvus/src/agent/`, `packages/opencorvus/src/orchestrator/`.

## Primary agents

OpenCorvus ships with several primary agents:

| Agent | Role |
|---|---|
| `task` | Top-level coordinator that drives spec → goals → plan → run → eval |
| `requirements` | Extracts a testable spec with acceptance criteria from the user request |
| `planner` | Breaks the spec into independent goals |
| `executor` | Implements a goal in code (the workhorse) |
| `evaluator` | Runs build/test/lint/startup/artifact checks on the result |

Models for each agent are configurable via `assistant.<name>.model` (see [config](/docs/config/)) — typically you plan with a slow/strong model and execute with a fast/cheaper one.

## Sub-agents

When a task has multiple parallel goals, the planner dispatches sub-agents for each goal via the **`dispatch_goal`** tool. Each sub-agent runs in its own Goal worktree (a checked-out git workspace), executes independently, and the orchestrator merges the result back via fast-forward only.

If the evaluator rejects a goal, the orchestrator can call **`retry_goal`** to start a fresh attempt with the prior failure context attached — same goal, new session.

Single-session-per-sub-agent: each sub-agent owns one session; the orchestrator does not wrap a "next session" around an existing sub-agent's session.

## Defining a custom agent

You can define agents inline in your config or in markdown under `~/.config/opencorvus/agents/` or `.opencorvus/agents/`:

```jsonc
{
  "agent": {
    "code-reviewer": {
      "description": "Reviews code for best practices and potential issues",
      "model": "anthropic/claude-sonnet-4-6",
      "prompt": "You are a code reviewer. Focus on security, performance, maintainability.",
      "tools": { "write": false, "edit": false }
    }
  }
}
```

Custom agents inherit OpenCorvus's tool set, permissions, and channel reach.

## Default agent

Set `default_agent` to pick the agent used when none is specified explicitly. Must be a primary agent.

## Limits

Agent runs honor budget settings in `assistant.<name>`:
- `max_steps` — turn budget per run
- `max_runs` — orchestrator-level retries
- `max_goal_retries` — retries per dispatched sub-goal

These are hard ceilings to prevent runaway loops. See [config](/docs/config/).
