## Causal chain

1. **Observable:** the permanent native scrollbar spans the complete
   message-panel content plane and remains visible beside the bottom Composer.
2. **Direct trigger:** `.conversation-scroll-shell` is a full-height flex
   column, `#chatScroll` takes all of it, and `#solidChatComposer` is an
   absolutely positioned sibling sharing the transcript's bottom edge.
3. **Deep cause:** the fixed-Composer repair modeled the Composer as a paint
   layer over a full-height scrollport. Its measured height became transcript
   `padding-bottom`, which protects content but does not reduce the scrollport
   or native scrollbar track.
4. **Why the latest path exposed rather than fixed it:** commit `c698301674`
   changed conditional scrollbar visibility to permanent `overflow-y: scroll`
   and permanent paint. Existing browser tests explicitly accepted the
   full-height track and shared bottom edge, so the previously quiet geometry
   became continuously visible while still passing.
