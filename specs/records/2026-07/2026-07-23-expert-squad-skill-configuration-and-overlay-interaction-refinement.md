## Causal Chain

1. Chat and Expert Squad Composer modes currently share one unconditional mention catalog, so the Listbox cannot communicate that Squad routing is unavailable in Chat. The exact-category parser also replaces the category list with entity rows inside the same surface, so it cannot produce the explicitly requested persistent first popup plus independent second popup.
2. The existing Agent Skill matrix is mature and already supports drag/drop, but it is mounted under the now-obsolete Installed Skills tab and its backend matrix is hard-bound to the runtime-active profile. Merely moving the markup would configure the wrong squad whenever Configuration displays an inactive package.
3. Mission status derivation currently collapses queued work into active and does not preserve terminal cancellation. The shared status surface was also recently changed from dots to Lucide icons, contrary to the new explicit request.
4. The user-message footer intentionally added a timestamp in an earlier refinement; the new request supersedes that presentation decision.
5. Agent access rows render label, Agent ID, and base role as three separate lines while badges and disclosure indicators use unrelated layout axes.
6. Environment visibility is intentionally operator-only in the current architecture. Its category body adds a child indent, and the first implementation pass added a synthetic Runtime parent around the existing Environment facts. The user clarified that these facts belong directly to Environment Information while Task, Requirements, Architecture, Workspace, and Tools are peer-level classifications.
7. Mission children are kept mounted but switch between `display: none` and `display: flex`; that discrete layout jump cannot animate.
8. Agent Rail already has Codex-derived proximity motion for its tick marks, but its Tooltip content inherits the global large shadow and has no surface-specific enter/exit transform, so marker motion and detail presentation feel disconnected.
