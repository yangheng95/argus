## Root cause

`TaskDirBar.runtimeToolShortcuts` maps the derived Right Dock environment catalog
without consulting the information sources that make those panels meaningful.
That turns tool capability into unconditional visibility, so an empty Browser
target, empty diff, missing project scope, and empty screenshot projection still
produce rows. Separately, the shared ghost Button hover rule and a local
shortcut hover/focus rule both assign a background wash; the Changes row has no
surface-specific hover override. The repair belongs in the environment
projection and its local visual contract, not in the Right Dock catalog or
individual panel bodies.

## Implementation plan

1. Add a popover-scoped Browser Preview resource keyed by selected task, active directory, and board refresh identity; treat only a non-empty returned URL as Browser information.
2. Promote File Explorer's existing scoped directory-list request into `file-workbench`, delete the component-local duplicate, and query the project root while the popover is open.
3. Filter the existing environment catalog using the established Browser, Review, Files, and Screenshots sources without adding a parallel catalog or state owner.
4. Make Changes and the four environment resource rows visually invariant under pointer hover while preserving click and keyboard focus behavior.
5. Update focused source tests and the existing Node-launched browser scenario for populated/empty visibility, transparent computed hover, navigation, and screenshots.
6. Run focused tests, Overlay typecheck/i18n/build, document health, real browser visual acceptance, inspect screenshots, perform a second diff review, selectively commit, and push.
