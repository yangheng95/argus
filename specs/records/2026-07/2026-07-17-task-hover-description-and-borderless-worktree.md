## Causal chain

1. The Task hover lacks description because `engine_task.request` stops at the task domain and is omitted by both Mission Task and Work Ledger response schemas; the Overlay therefore cannot render the real value.
2. Fetching Task detail on hover would create a second asynchronous source and visible timing race. Projecting the existing persisted request through the canonical list response repairs the missing data flow at its owner.
3. The Worktree list looks like stacked colored cards because `.project-worktree-row` explicitly adds a one-pixel border, inset fill, radius, and hover/focus replacement fill. The child button is already transparent.
4. The current leading icon is a private `FolderGit2` worktree alias, while the requested `dev` reference is already represented by the registered Lucide `GitBranch` icon in the branch information row. Reusing that registry entry is the direct replacement.

## Implementation plan

1. Add failing route/projection/source/browser assertions for the Task description response and hover block, then add failing source/browser assertions for a borderless transparent worktree row and Lucide Git-branch icon.
2. Project `engine_task.request` through Mission Task and Work Ledger schemas/mappers, mirror the Overlay type, and render the exact Task-only description inside the existing tooltip.
3. Replace the worktree icon with `git-branch`, remove the now-unused private worktree icon alias, and flatten only the worktree row border/background rules without changing actions or layout ownership.
4. Regenerate OpenAPI/SDK/API docs, run focused backend/Overlay/source tests, typecheck, internationalization, route/docs health, and Node-launched browser tests.
5. Inspect the current-task desktop screenshots at original resolution, correct any clipping/density/feedback problem, perform an exact diff review, and update this record with evidence. Keep the result local because the user explicitly prohibited push.
