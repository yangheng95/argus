## 一、产品定义

### 1.1 愿景

让金融从业者用自然语言发起"数据查询 + 代码编写"的复合任务，在同一个对话流中得到可执行的结果，无需在任何外部工具之间切换。

### 1.2 北极星指标（HTCR）

**混合任务闭环率**：用户发出包含金融数据意图的编程请求，工具在不追问、不切换工具的情况下，一次性完成数据获取 + 代码生成 + 结果呈现的比率。

测量方法：
- 测试集：S01-S05 各 20 条标注指令（共 100 条），不公开给研发
- 判定规则：≤3 轮完成 + 工具调用参数正确 + 输出含结构化内容 + 无占位符
- 数据源超时不计入分母

目标：M2 ≥ 55% → M3 ≥ 70%

辅助指标：工具调用成功率 ≥ 95%、代码复制率 ≥ 60%、会话均轮次 ≤ 3、7 日留存 ≥ 40%、意图识别准确率 ≥ 90%

### 1.3 用户角色

| 角色 | 特征 | 核心痛点 | 对应场景 |
|---|---|---|---|
| **A：量化研究员** | 每天写 Python，熟悉 pandas/numpy/backtrader，理解 IC/因子暴露/Sharpe | 数据获取与代码编写分离，缺乏领域专用错误提示 | S02 S03 S04 |
| **B：基本面分析师** | 财务建模为核心，Python 能力参差不齐 | 拉数据、清洗、建模三件事重复耗时 | S01 S05 |
| **C：风控工程师** | VaR、压力测试、风险归因，需快速引用历史行情 | 风控代码可复用性差，历史情景数据拉取繁琐 | S03 S04 |

**非目标用户**：纯软件工程师（非金融）、个人散户、通用 ML/AI 数据科学家。

### 1.4 核心场景

| 场景 | 用户输入 | 期望行为 |
|---|---|---|
| **S01** 财报可视化 | "帮我画一下茅台过去三年ROE趋势" | 调用财报工具 → ROE 折线图 + 数据表 + Python 代码 + 文字解读 |
| **S02** 因子调试 | 粘贴动量因子代码 + "我的IC跑出来很低" | 识别 look-ahead bias / 存活偏差 → 修改建议 + 修正代码 |
| **S03** 数据封装 | "最近30个交易日沪深300成分股平均换手率，封装成函数" | 调用行情工具 → 换手率柱状图 + 数据表 + 参数化封装函数 |
| **S04** 压力测试 | "用2015年股灾数据跑当前组合最大回撤" + 持仓表 | K 线图 + 回撤曲线 + 压测代码 + 风险数字 |
| **S05** 多标的对比 | "比较宁德时代、比亚迪、亿纬锂能的营收增速、毛利率和PE" | 并行查询 3 家财报 → 多指标对比图 + 对比表格 + 一句话评价 |

### 1.5 能力边界（不做什么）

以下 6 条红线适用于全部里程碑：

1. **不提供投资建议**：不出现"建议买入/卖出/持有"。市场分析类输出必须附 disclaimer。
2. **不执行交易指令**：不接入交易所或经纪商 API，无委托下单功能。
3. **不自主修改生产代码**：所有代码修改由用户手动执行或复制。
4. **不存储用户金融数据**：数据仅在会话生命周期内流转，不持久化到产品数据库。
5. **不支持非金融领域通用编程**：Web 开发、通用 ML、DevOps 不在服务范围。
6. **不做实时交易监控**：不提供 tick 级推送、实时 PnL 监控（M3 阶段前）。

### 1.6 设计原则

| 编号 | 原则 | 正例 | 反例 |
|---|---|---|---|
| P1 | **意图优先于模式切换** | 用户说"画茅台ROE趋势"，自动完成数据+代码+渲染 | 用户必须先点"数据模式"查数据，再切"代码模式" |
| P2 | **工具调用透明化** | 财报数据旁显示"来源：Tushare · 截至2024Q3" | 数据直接出现，不知来源 |
| P3 | **输出即可用** | 代码已内联实际数据，直接复制能跑 | 代码中大量 `YOUR_TICKER`、`TODO` |
| P4 | **金融错误优于代码错误** | KeyError → "可能是列名大小写不一致" | 仅输出 "KeyError at line 12" |
| P5 | **最小必要上下文** | "最新一期"自动对应最近财报期，不追问 | 先问"哪个财报期？"再问"股票代码？" |

## 二、系统架构

```
┌──────────────────────────────────────────────────────────────────────┐
│                      浏览器 / Tauri Desktop Shell                     │
│                                                                      │
│   React SPA (Vite 5 + TypeScript 5 + Zustand 4)                    │
│   ├── 设计系统 (深色主题 CSS Variables + Tailwind 3)               │
│   ├── 三栏布局: Sidebar + Chat + Canvas                            │
│   └── 实时通信: SSE streaming + REST (ky)                         │
└──────────────────────────────┬───────────────────────────────────────┘
                               │ HTTP / SSE
┌──────────────────────────────▼───────────────────────────────────────┐
│                   AimeCode API Server (Bun + Hono)                   │
│                                                                      │
│   POST /api/chat         LLM streaming proxy (SSE)                  │
│   GET  /api/sessions     会话 CRUD                                   │
│   POST /api/sessions/:id/messages                                    │
│   POST /api/execute      代码执行服务                                │
│   GET  /api/data/...     金融数据缓存层                              │
└───────┬──────────────────────┬──────────────────┬────────────────────┘
        │                      │                  │
   Anthropic API           Tushare Pro API      SQLite / PostgreSQL
   (Claude, SSE流)         (金融数据)           (会话持久化 · Drizzle)
        │                      │
   Tool Call编排           缓存层(财报24h·行情4h)
        │
   代码执行沙箱
   M0/M1: Pyodide (WASM)
   M3+:   Docker (Python 3.11)
```

**各层职责**：
- **前端**：纯 UI，通过 SSE 消费事件流，不直接调用 LLM 或金融 API
- **API Server**：LLM 代理 + Tool Call 编排 + 缓存 + 沙箱
- **数据层**：Tushare Pro 为主数据源，AkShare 作为降级选项（配置切换，非 fallback）

## 四、PRD 编写规范

每个里程碑 PRD 必须满足以下规范，否则 AI 实现时会产出低质量结果：

### 4.1 自包含原则

- **不跨文件引用**：每个 PRD 不得写"参见 M0-1"或"同上节"，所有内容就地内联。
- **技术栈版本内联**：不写"最新版"，写 "Hono 4.x"、"Bun 1.x"。
- **完整代码内联**：关键文件（接口、核心组件、Store、类型）给出完整 TypeScript/TSX 代码，不写伪代码或省略号。

### 4.2 Mock 数据质量标准

- **场景 events 全内联**：Mock LLM 场景的 events 数组必须完整内联，包含真实的 Plotly chartSpec JSON、真实数值的 table_data、可独立运行的 code_block。
- **图表有金融语义**：折线图含均值参考线和峰值标注，K 线图含成交量子图，对比图有颜色区分。
- **数值真实可信**：使用真实历史数据区间的数值，不使用 `[0.1, 0.2, 0.3]` 这种显然是 placeholder 的序列。

### 4.3 验收标准格式

每条验收标准必须是 **操作 + 可判断的期望结果**，不允许写 "页面正常显示" 这种无法判断的标准。

正确示例：
> V3 · 工具调用时间线 | 在 S01 场景流式过程中观察 | 可见进度条动画；done 后显示 "15条 · Tushare · 2024Q3"，颜色变为绿色

错误示例：
> V3 · 工具调用正常工作

### 4.4 集成陷阱显式标注

已知的第三方库版本冲突、CSS 优先级问题、TypeScript 类型不兼容、SSE 跨域问题等，必须在 PRD 末尾"集成陷阱"章节显式列出，附解决方案。

### 4.5 禁止项

- **禁止 fallback 逻辑**：不写"如果X失败就用Y"的降级分支，修根源。
- **禁止关键词匹配规则**：任何形式的意图关键词过滤都不可接受。
- **禁止硬编码 orchestration**：工具调用顺序由 LLM 推理决定，不写 state machine。
- **禁止占位符代码**：`YOUR_TICKER`、`TODO`、`# fill in here` 不允许出现在产出代码中。

2. 完整的文件创建顺序（带目录结构）
3. 每个关键文件的完整代码（内联，非引用）

## 六、词汇表

| 术语 | 定义 |
|---|---|
| 会话（Session） | 用户打开对话到关闭的生命周期，独立上下文 |
| 轮次（Turn） | 一条用户消息 + 一条完整回复 |
| 意图（Intent） | 代码意图 / 数据意图 / 混合意图 |
| 工具调用（Tool Call） | 向外部数据源发起的查询请求 |
| Tool Call 编排 | 服务端拦截 LLM tool_use → 调用真实 API → 回传 tool_result 的循环 |
| 代码执行（Code Execution） | 在沙箱中运行代码并返回结果 |
| 混合意图（Hybrid Intent） | 单条输入同时包含数据查询和代码编写需求 |
| Canvas | 右侧输出面板，显示图表/表格/代码等富媒体内容 |
| StreamEvent | 从后端 SSE 推送到前端的事件单元（discriminated union） |
| ContentBlock | 消息持久化后的结构化内容块 |
| HTCR | Hybrid Task Completion Rate，混合任务闭环率，北极星指标 |
| Pyodide | WebAssembly 版 Python 运行时，用于 M0/M1 代码执行 |
