```sql
CREATE TABLE users (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  username TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,
  balance REAL NOT NULL DEFAULT 1000000,
  created_at INTEGER NOT NULL DEFAULT (unixepoch())
);

CREATE TABLE sessions (
  token TEXT PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  created_at INTEGER NOT NULL DEFAULT (unixepoch())
);

CREATE TABLE stocks (
  code TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  open_price REAL NOT NULL,
  current_price REAL NOT NULL,
  high_price REAL NOT NULL,
  low_price REAL NOT NULL,
  volume INTEGER NOT NULL DEFAULT 0,
  trend REAL NOT NULL DEFAULT 0,
  updated_at INTEGER NOT NULL DEFAULT (unixepoch())
);

CREATE TABLE price_history (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  stock_code TEXT NOT NULL REFERENCES stocks(code),
  price REAL NOT NULL,
  volume INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL DEFAULT (unixepoch())
);

CREATE TABLE orders (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  stock_code TEXT NOT NULL REFERENCES stocks(code),
  direction TEXT NOT NULL CHECK(direction IN ('buy', 'sell')),
  quantity INTEGER NOT NULL,
  price REAL NOT NULL,
  status TEXT NOT NULL DEFAULT 'pending' CHECK(status IN ('pending', 'filled', 'cancelled')),
  filled_at INTEGER,
  created_at INTEGER NOT NULL DEFAULT (unixepoch())
);

CREATE TABLE positions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  stock_code TEXT NOT NULL REFERENCES stocks(code),
  quantity INTEGER NOT NULL DEFAULT 0,
  cost_basis REAL NOT NULL DEFAULT 0,
  UNIQUE(user_id, stock_code)
);

CREATE TABLE daily_snapshots (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  total_assets REAL NOT NULL,
  created_at INTEGER NOT NULL DEFAULT (unixepoch())
);
```

### 5. Trading Module (src/trading.ts)

**Validation Rules:**

- Buy: user.balance >= quantity * price
- Sell: position.quantity >= quantity (if exists)
- Price limit: current_price * 0.9 <= price <= current_price * 1.1

**Routes:**
- `POST /api/trading/buy`: Body `{ stock_code: string, quantity: number, price: number }`
  - Validate all rules
  - Deduct balance: UPDATE users SET balance = balance - (quantity * price)
  - Create order: INSERT INTO orders (user_id, stock_code, direction, quantity, price, status)
  - Return order object
  
- `POST /api/trading/sell`: Body `{ stock_code: string, quantity: number, price: number }`
  - Validate position exists and has sufficient quantity
  - Create order (no balance change yet - happens on fill)
  - Return order object
  
- `POST /api/trading/cancel/:id`:
  - Verify order belongs to user and status is 'pending'
  - If buy order: refund balance
  - UPDATE orders SET status = 'cancelled'
  - Return updated order
  
- `GET /api/trading/orders`: Query params `?status=pending|filled|cancelled`
  - Return orders for current user, optionally filtered by status

```typescript
const generateNextPrice = (currentPrice: number, trend: number, openPrice: number): number => {
  // Random walk with normal distribution (σ = 0.5%)
  const randomChange = (Math.random() - 0.5) * 0.01; // ±0.5%
  
  // Apply trend factor
  const trendChange = trend;
  
  // Calculate new price
  let newPrice = currentPrice * (1 + randomChange + trendChange);
  
  // Apply ±10% limit from open price
  const maxPrice = openPrice * 1.1;
  const minPrice = openPrice * 0.9;
  newPrice = Math.max(minPrice, Math.min(maxPrice, newPrice));
  
  return Math.round(newPrice * 100) / 100; // 2 decimal places
};
```

<risks>
- **Risk: SSE Connection Management** - Multiple concurrent SSE connections may cause memory leaks if not properly closed. Mitigation: Ensure abort signal handling in SSE endpoint closes intervals and streams.
- **Risk: Database Race Conditions** - Simultaneous order matching and trading operations could cause balance/position inconsistencies. Mitigation: Use SQLite transactions for all order-related updates (BEGIN/COMMIT).
- **Risk: Price Simulation Accuracy** - Random price generation with ±10% limits needs careful bounds checking. Mitigation: Clamp prices after applying random changes, ensure high/low tracking is accurate.
- **Risk: Frontend State Synchronization** - SSE updates may conflict with user actions. Mitigation: Implement optimistic updates with rollback on API error, refresh data after mutations.
- **Risk: Tailwind v4 Compatibility** - Tailwind v4 uses different configuration syntax. Mitigation: Use CSS-based configuration with `@theme` directive instead of JS config.
- **Risk: React Router v7 API Changes** - v7 has different import paths. Mitigation: Use `react-router` package (not react-router-dom), import from `react-router`.
- **Risk: Bun SQLite WAL Mode** - WAL mode may leave -shm and -wal files. Mitigation: Already in .gitignore, ensure proper cleanup on shutdown.
</risks>
