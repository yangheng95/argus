title: Integrity Review
description: OpenCorvus 如何记录验证证据，并从最终 integrity attempt 完成任务。
---

per-goal build attempt 会发布持久证据，任务最终复核面是 `integrity` workflow tool。当前 completion contract 是 artifact-backed：orchestrator 只能基于最新 post-build `integrity_attempt` 完成任务。

## 当前复核流程

1. **Build evidence**：direct build 与 per-goal build 写入 `run`、`goal_run_attempt`、changed-file、report、diff 与可选 verification artifacts。
2. **Verification evidence**：browser preview target、browser preview capture、runtime check、截图与视觉证据存为 `engine_artifact` 行，例如 `verification-evidence`、`browser_preview_target`、`browser_preview_evidence`。
3. **Visual QA**：任务存在前端可见交付面时，`visual_qa` 复核可见产品证据；它不完成任务。
4. **Integrity review**：`integrity` 读取用户请求、requirements、architect contract graph、goal outputs、diffs、runtime/visual evidence 与历史 attempts。
5. **Completion decision**：`manage_task action=complete_task` 要求当前 post-build `integrity_attempt` id。non-pass 证据会路由回 `dispatch_agent target=build`、`manage_task action=modify_goal`、`dispatch_agent target=architect`、用户问题或 `manage_task action=fail_task`。

## 证据表面

| 表面                            | 当前源码                                                    |
| ------------------------------- | ----------------------------------------------------------- |
| Verification evidence artifacts | `packages/opencorvus/src/engine/store.ts`                   |

| Visual QA semantics             | `packages/opencorvus/src/visual-qa/acceptance-semantics.ts` |
| Integrity team review           | `packages/opencorvus/src/integrity/team-agent.ts`           |
| Integrity schemas               | `packages/opencorvus/src/integrity/team-schema.ts`          |
| Completion guard                | `packages/opencorvus/src/orchestrator/tools.ts`             |

## Artifact Records

复核路径从当前 `engine_artifact` kind 重建，重点包括：

```typescript
"run"
"goal_run_attempt"
"verification-evidence"
"browser_preview_target"
"browser_preview_evidence"
"integrity_attempt"
```

checks 是给 operator 和后续 review 使用的审计证据，不能替代最终 `integrity_attempt` completion contract。

## Integrity Verdict 语义

| Integrity outcome               | Orchestrator 含义                                                                                    |
| ------------------------------- | ---------------------------------------------------------------------------------------------------- |
| pass                            | 集成系统满足本任务；orchestrator 可以用最新 post-build `integrity_attempt` id 调用 `manage_task action=complete_task`。 |
| non-pass 且有 blocking findings | orchestrator 必须基于证据把修复路由到 `dispatch_agent target=build`、`manage_task action=modify_goal`、`dispatch_agent target=architect` 或用户问题。 |
| thrown / artifact missing       | orchestrator 会收到可见失败证据并决定恢复；UI 不应静默显示空卡片。                                   |
