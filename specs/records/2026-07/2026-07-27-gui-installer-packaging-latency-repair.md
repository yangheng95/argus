## Causal chain

1. The release script builds Vite before building the embedded backend.
2. Its Tauri invocation deep-merges only `bundle.resources`, leaving the configured `beforeBuildCommand` active, so Tauri builds Vite again. The local Tauri schema confirms `build.beforeBuildCommand` accepts `null`, which is the precise scripted-build override.
3. The embedded backend clean build deletes its prior payload and recopies runtime package trees. The safe Windows repair from July 6 replaced broken Bun recursive copy with explicit traversal, but the implementation awaits every stat, directory, and file copy serially across about 15,000 files.
4. The payload producer then hashes every byte and Rust validates and archives it. Those integrity passes are expected work; the duplicated frontend build and serialized copy inflate the avoidable portion before them.
5. Because the scripts do not print stage duration boundaries, the long copy/hash/archive interval looks like a hang and the failed run does not identify its last completed stage.

## Repair

| Surface               | Change                                                                                                                                                                                                                                                         |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Overlay release build | Keep direct Tauri builds self-contained, but pass `build.beforeBuildCommand: null` from the release script after its explicit Vite build so the release path has one owner.                                                                                    |
| Runtime module copy   | Retain explicit file-copy behavior and nested `node_modules` exclusion. Traverse directory batches and copy file batches with worker count derived from `os.availableParallelism()`, avoiding Bun recursive copy and unbounded promises.                       |
| Payload hash          | Preserve the exact SHA-256 byte contract while prefetching a bounded host-derived window of file reads. Hash updates remain in canonical file order, so Rust validation is unchanged.                                                                          |
| Installer compression | Override the scripted Windows NSIS build from its slow default LZMA compressor to Tauri's documented ZLIB compressor. The embedded payload is already gzip-compressed, so LZMA recompression adds CPU cost without an integrity benefit.                       |
| Windows release copy  | Split the official Tauri CLI flow into `build --no-bundle`, a task-local `target/release/package-input` executable snapshot, and `bundle --bundles`. The development `dist` executable can be the live application and must never be overwritten by packaging. |
| Observability         | Time SDK build, Overlay frontend, embedded backend, Tauri bundle, staging, and validation stages with start/completion/failure messages.                                                                                                                       |
| Regression tests      | Assert the null Tauri override, single release-script Vite owner, bounded explicit copy implementation, nested-module exclusion, and successful representative runtime copying.                                                                                |

- Focused timing, release-contract, matrix, and build-artifact tests pass.
- Whole-repository typecheck passed before the remote merge.
- The merge added Virtua 0.49.3 `bufferSize` consumers while the local installation still projected 0.42.3. The company registry closed connections, so the project-pinned Bun 1.3.13 executable was acquired from the public npm package and used with the public registry.
- Bun 1.3.13 exposed one manifest/lock mismatch from the merged branch: `@slack/bolt` belonged to `packages/channel-runtime` but remained recorded under `packages/opencorvus`. Regenerating with the pinned Bun moved that single existing resolution without changing its version, and Overlay then resolved Virtua 0.49.3 with the expected `bufferSize` type.
- First clean matrix evidence: SDK 34.66s; Vite 194.08s; embedded backend 653.73s; Tauri 777.74s. Both MSI and NSIS were created, but the final Bun file copy returned `EBUSY`, so staging did not run.
- Payload timestamps divide the 653.73s backend stage into roughly 87s executable compile, 98s runtime assembly, and 469s producer SHA-256. Tauri spent about 434s building the Rust executable and another 344s producing both installers. A live-process sample proved NSIS was CPU-active rather than ownerless.
- The first repair removed the duplicate Vite invocation but did not meet the elapsed-time acceptance. The second repair therefore targets the measured producer hash, NSIS LZMA recompression, Windows copy failure, and missing inner-stage timing.
- Isolated second-repair benchmark on the actual 15,054-file, 461.9 MiB payload completed the unchanged ordered SHA-256 contract in 3.06s, down from the first run's approximately 469s timestamp interval.
- Second clean matrix evidence: SDK 12.12s; Vite 76.80s; embedded backend 181.24s (22.83s executable, 18.42s runtime payload, 124.60s SHA-256 under concurrent machine load); Tauri 217.67s.
