# Mirror Prism selection

## Expert Contract

Select package `mirror/prism` with active profile `prism` when one or more authorized reference products must converge into one coherent original AInvest desktop subsystem spanning Product Requirements, rendered design, production implementation, and independent MirrorTest acceptance. A supplied URL is a product-observation and subsystem-discovery entry point, never the output identity or a single-page delivery boundary. Derive the complete subsystem closure from acquired evidence rather than a numeric quota: preserve every qualified route inside the authorized reference boundary plus every associated subpage required to complete an evidenced business capability or material user journey; add none without source support, and omit none merely to satisfy a cap. The closure must identify its entry, member surfaces/routes, shared shell/data/state capabilities, navigation graph, end-to-end journeys, and evidence-backed reason each member is required. Insufficient material is a visible evidence gap, not permission to invent scope or present an isolated entry page as a complete subsystem.

A single route is a valid Prism closure only when the acquired evidence proves that the route itself owns the complete requested business capability with no required associated subpage, shared-state continuation, or cross-route journey. Otherwise Prism owns the entire connected closure in the same Task. Page files may be internal parallel work units, but they are never separately accepted deliverables.

Never select Prism for clone, replica, port, migration-parity, screenshot-parity, pixel-parity, source-to-render comparison, or high-fidelity restoration. Those requests belong to the dedicated `frontend-replica` Expert Squad. Prism has one design mode, `greenfield_original`: reference pages supply product structure, capability, data, interaction, state, accessibility, and adopt/defer/reject evidence, while the package-owned AInvest authority supplies the output product identity, design system, semantic tokens, components, assets, market colors, compliance, and light/dark behavior. Reference layout geometry, styling, regions, screenshots, brand assets, and protected content never become Prism visual authority.

Every Prism delivery uses the Mission-provisioned canonical AInvest child repository, bound through `panel.create_task.directory`, as its repository authority. The first delivery Task has no predecessor Artifact import or copied repository packet. Preserve existing files and concurrent changes; never implement the product in the OpenCorvus control repository or escape the Task directory.

Bind the sole workflow `mirror-prism-ainvest` before the first dispatch. The output identity is always AInvest even when every reference product is non-financial. If the authorized reference boundary is absent, obtain it before dispatch. Prism's source observation is internal to this full delivery and is not independently selectable. Do not select this package for a bounded observation-only or test-only request. A Product Requirements Document-only, design-only, or code-only request is not a complete Mirror Prism delivery and must not be silently widened to this workflow.

This package is fixed for the delivery Task lifetime. Reused implementations are materialized inside this package, and every runtime reference resolves to this package or a platform `default` resource; the scheduler never reads another installed or inactive Expert Squad package. Canonical AInvest directory provisioning is completed by the owning Mission before this Task starts. The scheduler executes the package workflow under the immutable Task package revision binding; a different Squad requires a separate Task.

After selection, use the platform Task Artifact catalog for every declared evidence dependency; the workflow graph does not define a parallel transport. Task completion requires joint evidence for the exact closure-member set and all material journeys, not a representative page or count-only claim.
