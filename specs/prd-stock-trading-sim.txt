股票交易 Web 应用 PRD v2.0 （需要 architect 分解 > 30 goals 才可完成）
============================

交付一个接近成熟券商终端体验的商业级可运行 MVP，全栈实现行情、下单、持仓、资产、记录与风控闭环。
UI 全面采用 Apple 设计语言（参照 macOS/iOS Stocks App + Apple HIG），在专业交易场景中实现
「简洁、克制、层次分明、信息密度高但不拥挤」的质感。

## 一、产品定位

### 1.1 产品目标

构建一个模拟 A 股交易 Web 终端，支持用户完成注册、登录、看盘、下单、撤单、持仓管理、
收益分析和交易复盘。产品在功能层面覆盖一个真实券商 App 的核心交易链路，在体验层面
达到 Apple 原生应用的设计水准。

### 1.2 产品基调

- **不是**: 通用 SaaS 仪表盘、管理后台、学习 demo、默认 Vite 页面
- **是**: 一个让用户打开后第一反应是「这是一个真正的交易软件」的专业级 Web 应用
- **设计参照**: macOS Stocks App、iOS Stocks App、Apple 官网产品页的排版节奏感、
  Apple HIG 的组件规范与动效原则

### 1.3 目标用户

| 用户角色 | 核心需求 | 使用场景 | 关键体验指标 |
|---------|---------|---------|------------|
| 新手投资者 | 熟悉股票交易流程与术语 | 首次接触股票，通过模拟账户零风险学习 | 5 分钟内完成首次买入 |
| 轻度交易者 | 模拟练习与策略试错 | 尝试不同买卖策略，观察盈亏变化 | 交易链路无歧义，数据实时可信 |
| 产品/面试演示 | 展示完整交易闭环与实时 UI 能力 | 技术展示、产品路演、面试作品 | 视觉专业度、交互流畅度 |

### 1.4 成功标准

1. 用户可在 5 分钟内完成注册到第一次买入
2. 行情刷新具有实时感（SSE 驱动，2 秒刷新），连接状态明确可感知
3. 核心交易链路无歧义：可买、可卖、可撤、可查、可回看
4. UI 具有 Apple 原生应用质感，不出现任何"默认 Vite 页面"或"普通管理后台"观感
5. 所有页面在 1440px 桌面端呈现最佳信息密度
6. 首屏加载 < 2s，交互响应 < 100ms（感知层面）

## 二、技术栈（固定）

### 2.1 后端

- **运行时**: Bun
- **语言**: TypeScript (strict mode)
- **框架**: Hono
- **数据库**: SQLite via `bun:sqlite`，数据文件 `data/trading.db`
- **实时推送**: Server-Sent Events (SSE) — 行情推送
- **密码哈希**: `Bun.password.hash()` / `Bun.password.verify()`
- **入口**: `index.ts`，同时服务 API 和前端静态资源

### 2.2 前端

- **框架**: React 19 + TypeScript
- **脚手架**: Vite (react-ts 模板结构)
- **路由**: React Router v7
- **样式**: Tailwind CSS v4
- **图表**: Recharts（K 线蜡烛图 + 均线叠加 + MACD 子图、分时图、成交量、资产曲线、市场热力图 Treemap）
- **HTTP**: 原生 fetch + SSE EventSource
- **前端目录**: `web/`，构建产物 `web/dist/`

## 四、Apple 设计系统

本项目 UI 全面模拟 Apple 设计语言。以下是完整的设计系统定义，所有组件、页面、交互
必须严格遵循。

### 4.1 设计原则（来自 Apple HIG）

1. **清晰 (Clarity)**: 文字清晰可读，图标精确易懂，功能显而易见。去除一切装饰性噪音。
2. **遵从 (Deference)**: 内容是主角，UI 框架退居幕后。流畅的动效帮助用户理解空间关系，
   但绝不抢夺注意力。
3. **深度 (Depth)**: 通过层级、模糊、动效建立空间感。层与层之间的关系通过视觉深度自然表达。

### 4.2 颜色系统

采用 Apple 深色模式色板，在交易场景中保持专业感的同时具备 Apple 特有的柔和质感。
与传统交易终端的「纯黑+高饱和强调色」不同，Apple 风格的深色模式使用带色倾向的深灰，
强调色饱和度适中，整体氛围温润而非冰冷。

#### 4.2.1 基础色板

```css
:root {
  /* ── 背景层级（Apple 深色模式的多层灰，带微蓝色倾向） ── */
  --color-bg-primary:       #000000;       /* 最底层，纯黑，用于页面背景 */
  --color-bg-secondary:     #1c1c1e;       /* 二级面板/侧边栏背景 */

  --color-bg-elevated:      #3a3a3c;       /* 弹窗/浮层/下拉菜单背景 */
```

#### 4.2.2 颜色使用规则

1. **永远不要在深色背景上使用纯白文字的 100% opacity**：主文字用 `#ffffff`，次要文字
   必须降低 opacity，形成层级。
2. **涨跌色只用于有语义的数值**：股票代码、名称不染色，只有价格、涨跌额、涨跌幅、
   盈亏数字才使用涨跌色。
3. **分隔线使用半透明色**，不要用实线颜色，这是 Apple 深色模式的关键特征。
4. **背景层级严格递进**：页面 → 面板 → 卡片 → 弹窗，每一层比上一层亮一个级别。

### 4.3 排版系统

模拟 Apple SF Pro 字体族的排版节奏。Web 环境下使用 Inter 作为英数等宽替代，
中文使用 -apple-system 回退链。

#### 4.3.1 字体栈

```css
:root {
  /* 主字体（界面文字） */
  --font-sans: "Inter", -apple-system, BlinkMacSystemFont, "SF Pro Text",
               "Helvetica Neue", "PingFang SC", "Hiragino Sans GB",
               "Microsoft YaHei", sans-serif;

  /* 等宽数字字体（价格、金额、数量） */
  --font-mono: "SF Mono", "JetBrains Mono", "Fira Code", "Cascadia Code",
               "Consolas", monospace;

  /* 数字专用样式 */
  --font-tabular: "Inter";  /* Inter 支持 font-variant-numeric: tabular-nums */
}
```

#### 4.3.2 字号体系（Apple HIG 标准 Dynamic Type 映射）

| Token | 用途 | 大小 | 行高 | 字重 | 字间距 |
|-------|------|------|------|------|--------|
| `--text-large-title` | 页面主标题 | 34px | 41px | 700 (Bold) | 0.37px |
| `--text-title-1` | 区块标题 | 28px | 34px | 700 (Bold) | 0.36px |
| `--text-title-2` | 卡片标题 | 22px | 28px | 700 (Bold) | 0.35px |

| `--text-headline` | 列表标题行 | 17px | 22px | 600 (Semibold) | -0.41px |
| `--text-body` | 正文 | 17px | 22px | 400 (Regular) | -0.41px |
| `--text-callout` | 标注文字 | 16px | 21px | 400 (Regular) | -0.32px |
| `--text-subheadline` | 次要标题 | 15px | 20px | 400 (Regular) | -0.24px |

#### 4.3.3 数字排版规则

- 所有价格、金额、数量字段必须启用 `font-variant-numeric: tabular-nums`
- 价格大数字（如个股详情页的最新价）使用 `--text-large-title` + `font-weight: 700`
- 表格中的数值使用 `--font-mono`，确保列对齐不跳动
- 千分位分隔符使用半角逗号（如 `1,000,000.00`）
- 盈亏百分比带正负号（如 `+3.2%` / `-1.5%`）

### 4.4 间距系统（8pt 网格）

Apple HIG 使用 8pt 基准网格。所有间距必须是 4 的倍数（最小 4px），常用值为 8 的倍数。

```css
:root {
  --space-0:    0px;
  --space-1:    4px;     /* 最小间距：图标与文字、行内元素间 */
  --space-2:    8px;     /* 紧凑间距：列表项内部、标签间 */
  --space-3:    12px;    /* 常规间距：卡片内元素间 */
  --space-4:    16px;    /* 标准间距：卡片内边距、列表项间 */
  --space-5:    20px;    /* 区块间距 */
  --space-6:    24px;    /* 面板内边距 */
  --space-7:    32px;    /* 大区块间距 */
  --space-8:    40px;    /* 页面边距 */
  --space-9:    48px;    /* 章节间距 */
  --space-10:   64px;    /* 最大间距 */
}
```

#### 间距应用规则

- 页面左右边距：桌面端 `--space-8`（40px），平板 `--space-6`（24px）
- 卡片内边距：`--space-4`（16px），大卡片 `--space-6`（24px）
- 表格行高：最小 44px（Apple 推荐的最小可点击区域）
- 表格单元格内边距：水平 `--space-3`（12px），垂直 `--space-2`（8px）
- 相邻卡片间距：`--space-3`（12px）
- 区块标题与内容间距：`--space-3`（12px）
- 导航栏高度：52px

### 4.5 圆角系统

Apple 使用「连续圆角（Squircle / Superellipse）」而非标准 CSS `border-radius` 的
几何圆弧。Web 环境中无法原生实现 Squircle，使用略大的 `border-radius` 值近似模拟。

```css
:root {
  --radius-xs:    4px;     /* 小型元素：徽章、标签 */
  --radius-sm:    8px;     /* 中型元素：按钮、输入框 */
  --radius-md:    12px;    /* 卡片、面板 */
  --radius-lg:    16px;    /* 大卡片、弹窗 */
  --radius-xl:    20px;    /* 浮层、底部弹窗 */
  --radius-full:  9999px;  /* 药丸形：Segmented Control 内选中态、标签 */
}
```

### 4.6 阴影与层级

Apple 深色模式中，阴影效果较浅色模式更为克制。层级主要通过背景色递进 + 边框 + 微弱
阴影共同实现。

```css
:root {
  /* Apple 深色模式阴影（极其克制） */
  --shadow-sm:   0 1px 3px rgba(0, 0, 0, 0.3);
  --shadow-md:   0 4px 12px rgba(0, 0, 0, 0.4);
  --shadow-lg:   0 8px 32px rgba(0, 0, 0, 0.5);
  --shadow-xl:   0 16px 48px rgba(0, 0, 0, 0.6);

  /* 弹窗阴影 */
  --shadow-popover: 0 4px 16px rgba(0, 0, 0, 0.5),
                    0 0 0 0.5px rgba(255, 255, 255, 0.1);

  /* 卡片内发光边框（Apple 深色模式的标志性效果） */
  --border-card:  0.5px solid rgba(255, 255, 255, 0.08);
}
```

### 4.7 毛玻璃与材质 (Vibrancy)

Apple 深色模式的标志性特征：半透明 + 高斯模糊背景，让层与层之间产生深度感。

```css
/* 侧边栏 / 导航栏的毛玻璃效果 */
.material-thin {
  background: rgba(28, 28, 30, 0.72);
  backdrop-filter: saturate(180%) blur(20px);

/* 弹窗 / 浮层的毛玻璃效果 */
.material-thick {

  -webkit-backdrop-filter: saturate(180%) blur(40px);

/* 顶部导航栏 */
.material-navbar {
  background: rgba(0, 0, 0, 0.65);
  backdrop-filter: saturate(180%) blur(20px);
  -webkit-backdrop-filter: saturate(180%) blur(20px);
```

### 4.8 图标规范

- 使用 Lucide React 图标库（风格最接近 Apple SF Symbols 的开源方案）
- 图标大小：导航栏 24px，列表项 20px，按钮内 16px，徽章内 12px
- 图标 stroke-width: 1.5（Apple SF Symbols 的标准粗细）
- 图标颜色跟随文字层级，不额外上色（除非有语义需求）

### 4.9 动效系统

Apple 动效三原则：自然（弹性曲线）、即时（不拖泥带水）、有意义（反映状态变化）。

#### 4.9.1 缓动曲线

```css
:root {
  /* Apple 标准缓动 */
  --ease-default:    cubic-bezier(0.25, 0.1, 0.25, 1.0);    /* 通用 */
  --ease-in:         cubic-bezier(0.42, 0, 1, 1);            /* 元素退出 */
  --ease-out:        cubic-bezier(0, 0, 0.58, 1);            /* 元素进入 */
  --ease-in-out:     cubic-bezier(0.42, 0, 0.58, 1);         /* 状态切换 */
  --ease-spring:     cubic-bezier(0.34, 1.56, 0.64, 1);      /* 弹性（慎用） */
}
```

#### 4.9.2 时长标准

| 场景 | 时长 | 说明 |
|------|------|------|
| 微交互（hover、press） | 100ms | 即时反馈 |
| 状态切换（tab 切换、toggle） | 200ms | 快速过渡 |
| 面板展开/折叠 | 250ms | 清晰可见但不拖沓 |
| 页面转场 | 300ms | 标准转场 |
| 复杂动画（首屏入场） | 400-600ms | 分段入场 |
| 价格闪烁 | 300ms | 涨跌色背景淡出 |
| 数字滚动 | 400ms | 滚轮动画 |

#### 4.9.3 必须实现的动效

1. **价格闪烁**: SSE 推送后，价格发生变化的单元格触发背景色闪烁：
   - 涨：`var(--color-up-bg)` → 透明，300ms ease-out
   - 跌：`var(--color-down-bg)` → 透明，300ms ease-out
   - 平：无动画
   - 实现方式：CSS `@keyframes flash-up / flash-down`，通过 className 触发

2. **数字滚动 (Odometer)**: 核心金额数字（总资产、可用资金、盈亏）变化时，
   数字从旧值到新值做垂直滚轮动画：
   - 每位数字独立滚动，高位先到位
   - 使用 `requestAnimationFrame` + CSS `translateY` + `clip-path` 实现
   - 时长 400ms，缓动 `--ease-out`
   - 不引入第三方库

3. **首屏分段入场**: 页面元素按视觉层级分段淡入 + 微上移：
   - 第一段（导航栏）：0ms 延迟
   - 第二段（顶部摘要卡片）：100ms 延迟
   - 第三段（主内容区）：200ms 延迟
   - 第四段（底部表格/图表）：300ms 延迟
   - 每段：opacity 0→1 + translateY(8px→0)，时长 400ms

4. **Tab / Segmented Control 切换**: 选中指示器（背景色块）在选项间平滑滑动，
   200ms ease-in-out

5. **Toast 通知**: 从顶部滑入（translateY(-100%→0)），300ms ease-out；
   3 秒后自动滑出

6. **按钮 press**: 按下时 scale(0.97)，释放回弹 scale(1)，100ms

7. **卡片 hover**: 微弱亮度提升（background-color 过渡到 `--color-bg-tertiary`），
   200ms

## 五、设计原则（交易场景特化）

1. **实时优先**: 行情、委托状态、持仓盈亏必须实时响应，不允许用户依赖刷新页面确认结果。
2. **交易优先**: 页面结构围绕「看盘 → 判断 → 下单 → 跟踪 → 复盘」组织，
   而不是围绕 CRUD 菜单组织。
3. **Apple 式高密度**: 信息密度高，但通过层级、留白、分组保持清晰。
   与传统交易终端的「像素级压缩」不同，Apple 风格允许适度留白，
   通过排版层级而非颜色堆砌来传达信息优先级。
4. **结果可解释**: 每笔订单的状态变化、成交价格、资金变化必须能在界面上追溯。
5. **风控前置**: 在输入阶段就提示可买数量、可卖数量、价格区间与错误原因，
   减少提交后报错。

## 八、通用组件规格

### 8.1 AnimatedNumber（数字滚动组件）

- Props: `value: number`, `prefix?: string`（如 `¥`）, `decimals?: number`
- 行为：每次 value 变化时播放从旧值到新值的垂直滚轮动画
- 实现要点：
  - 将数字拆分为每位数字（含小数点、逗号）
  - 每位数字独立滚动，使用 `translateY` 实现
  - 高位先到位，低位稍有延迟（stagger 20ms）
  - 使用 `requestAnimationFrame` 驱动
  - CSS `overflow: hidden` + `clip-path` 裁剪
  - 总时长 400ms，缓动 `--ease-out`
- 不引入第三方动画库

### 8.2 PriceFlash（价格闪烁组件）

- Props: `value: number`, `prevValue: number`
- 行为：当 value !== prevValue 时，触发背景色闪烁
- CSS keyframes:
  ```css
  @keyframes flash-up {
    from { background-color: var(--color-up-bg); }
    to { background-color: transparent; }
  }
  @keyframes flash-down {
    from { background-color: var(--color-down-bg); }
    to { background-color: transparent; }
  }
  ```
- 动画时长 300ms，ease-out

### 8.3 SegmentedControl（分段控制器）

- Props: `options: string[]`, `value: string`, `onChange: (v: string) => void`
- Apple 标准样式（见 4.9.3 中 Tab/Segmented Control 描述）

### 10.1 种子数据

预置 10 只模拟股票：

| 代码 | 名称 | 开盘价 | 趋势因子 |
|------|------|--------|---------|
| SH600001 | 浦发银行 | 8.50 | +0.02% |
| SH600002 | 齐鲁石化 | 12.30 | -0.01% |
| SH600003 | 东北高速 | 15.80 | +0.05% |
| SH600004 | 白云机场 | 22.40 | +0.03% |
| SH600005 | 武钢股份 | 5.60 | -0.03% |
| SH600006 | 东风汽车 | 9.20 | +0.01% |
| SH600007 | 中国国贸 | 18.90 | +0.04% |
| SH600008 | 首创环保 | 3.80 | -0.02% |
| SH600009 | 上海机场 | 45.60 | +0.06% |
| SH600010 | 包钢股份 | 2.10 | -0.04% |

### 10.2 历史数据生成

- 服务启动时生成当日历史价格
- 模拟 9:30 开盘至当前时刻，每分钟一个 tick（约 240 点）
- 以 OHLCV 格式存储于 `price_history` 表
- 每根 1 分钟 bar 包含：open、high、low、close、volume
- volume 为随机值（基础量 ± 50% 波动）

### 10.3 实时 Tick 生成

- 每 2 秒生成一次新 tick：
  1. 基于上一个价格 ± 随机波动（正态分布，σ = 0.5%）
  2. 叠加趋势因子（每只股票有隐含趋势 -0.1% ~ +0.1%）
  3. 涨跌幅限制 ±10%（基于当日开盘价）
  4. 当前 bar 的 high/low 随 tick 持续更新
  5. 满 60 秒封闭当根 K 线，开启新 bar

### 10.4 K 线聚合规则

kline 接口实时计算：
- `1m` — 原始每分钟 bar
- `5m` — 将 1m bar 按 5 分钟窗口合并：首根 open、末根 close、区间 high/low 极值、累计 volume
- `15m` — 同理，15 分钟窗口
- `1d` — 当天全部 1m bar 合并为一根日 K

### 10.5 技术指标计算

随 K 线响应一同返回：
- **MA5、MA10、MA20**: close 的简单移动平均
- **MACD**:
  - EMA12 = 12 周期指数移动平均
  - EMA26 = 26 周期指数移动平均
  - DIF = EMA12 − EMA26
  - DEA = EMA9(DIF)（9 周期指数移动平均）
  - BAR = (DIF − DEA) × 2

### 10.6 撮合引擎

每次价格变动自动撮合挂单：
- 买单：当前市价 ≤ 买入委托价 → 成交
- 卖单：当前市价 ≥ 卖出委托价 → 成交

撮合后同步更新：
1. 用户余额与冻结资金
2. 持仓数量、可卖数量、成本价（加权平均）
3. 股票成交量
4. 成交记录与委托状态（`pending` → `filled`）
5. SSE 推送载荷

## 十一、个股新闻生成引擎

### 11.1 设计目标

用情绪驱动的随机新闻让模拟系统具有「真实市场」氛围感，提升演示体验。
新闻不落入数据库，仅在内存中维护（每只股票最多 50 条，全市场混排队列最多 100 条），
服务重启后重新生成。

### 11.2 生成逻辑

1. 服务启动时为每只股票预生成 8 条历史新闻（模拟早盘前已发布）
2. 此后每只股票每 30~120 秒（独立随机间隔）追加一条新新闻
3. 情绪类型按当前涨跌幅加权随机选取：
   - `涨幅 > 3%` → 利好 70% + 中性 20% + 利空 10%（噪音）
   - `跌幅 > 3%` → 利空 70% + 中性 20% + 利好 10%（噪音）
   - `波动 ±3%` → 利好 40% + 利空 40% + 中性 20%

### 11.3 新闻数据结构

```typescript
interface NewsItem {
  id: string;            // UUID
  stock_code: string;    // 股票代码（全市场新闻为 "MARKET"）
  title: string;         // 标题（15-40 字，从模板插值）
  summary: string;       // 摘要（50-120 字）
  sentiment: "positive" | "negative" | "neutral";
  source: string;        // 轮换自 5 个来源
  impact: "high" | "medium" | "low";
  created_at: number;    // Unix 时间戳
}
```

### 11.4 新闻来源池

轮换自：「东方财富」「证券时报」「21 世纪经济报道」「界面新闻」「上海证券报」

## 十二、交易规则与风控

### 12.1 认证与权限

- 密码用 Argon2 哈希存储（`Bun.password.hash()` / `Bun.password.verify()`）
- 未认证请求返回 401
- 用户只能操作自己的订单、自选股和持仓
- 所有修改操作必须验证 Bearer token

### 12.2 交易规则

- 交易数量必须是 100 的整数倍（1 手 = 100 股）
- 挂单价格限制：当前价 ±10%
- 买入校验：可用资金 ≥ 数量 × 价格
- 买入挂单未成交前，相应资金进入冻结态（`frozen_balance += quantity × price`）
- 卖出校验：持仓可卖数量 ≥ 卖出数量
- 卖出挂单未成交前，相应可卖持仓进入冻结态（`available_quantity -= quantity`）
- 撤单成功后恢复对应冻结资金或可卖持仓

### 12.3 输入校验

- 股票代码必须在 SH600001-SH600010 范围内
- 价格必须为正数，保留 2 位小数
- 数量必须为正整数，且是 100 的整数倍
- 所有校验失败返回明确中文错误文案（见 API 错误响应示例）

### 12.4 资金同步

- 所有涉及资金的接口返回最新资产摘要（`account` 字段），避免前端自行推算
- 成本价计算：加权平均法
  - `新成本 = (原成本 × 原数量 + 成交价 × 成交数量) / (原数量 + 成交数量)`

## 十三、数据模型

```sql
CREATE TABLE users (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  username TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,
  balance REAL NOT NULL DEFAULT 1000000,
  frozen_balance REAL NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL DEFAULT (unixepoch())
);

CREATE TABLE sessions (
  token TEXT PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  created_at INTEGER NOT NULL DEFAULT (unixepoch())
);

CREATE TABLE stocks (
  code TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  open_price REAL NOT NULL,
  current_price REAL NOT NULL,
  high_price REAL NOT NULL,
  low_price REAL NOT NULL,
  prev_close REAL NOT NULL,
  volume INTEGER NOT NULL DEFAULT 0,
  trend REAL NOT NULL DEFAULT 0,
  updated_at INTEGER NOT NULL DEFAULT (unixepoch())
);

CREATE TABLE price_history (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  stock_code TEXT NOT NULL REFERENCES stocks(code),
  open REAL NOT NULL,
  high REAL NOT NULL,
  low REAL NOT NULL,
  close REAL NOT NULL,
  volume INTEGER NOT NULL DEFAULT 0,
  timestamp INTEGER NOT NULL,
  UNIQUE(stock_code, timestamp)
);

CREATE TABLE orders (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  stock_code TEXT NOT NULL REFERENCES stocks(code),
  direction TEXT NOT NULL CHECK(direction IN ('buy', 'sell')),
  quantity INTEGER NOT NULL,
  price REAL NOT NULL,
  frozen_amount REAL NOT NULL DEFAULT 0,
  status TEXT NOT NULL DEFAULT 'pending' CHECK(status IN ('pending', 'filled', 'cancelled')),
  filled_at INTEGER,
  created_at INTEGER NOT NULL DEFAULT (unixepoch())
);

CREATE TABLE positions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  stock_code TEXT NOT NULL REFERENCES stocks(code),
  quantity INTEGER NOT NULL DEFAULT 0,
  available_quantity INTEGER NOT NULL DEFAULT 0,
  cost_basis REAL NOT NULL DEFAULT 0,
  UNIQUE(user_id, stock_code)
);

CREATE TABLE watchlists (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  stock_code TEXT NOT NULL REFERENCES stocks(code),
  created_at INTEGER NOT NULL DEFAULT (unixepoch()),
  UNIQUE(user_id, stock_code)
);

CREATE TABLE daily_snapshots (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  total_assets REAL NOT NULL,
  cash REAL NOT NULL,
  market_value REAL NOT NULL,
  created_at INTEGER NOT NULL DEFAULT (unixepoch())
);

-- 索引
CREATE INDEX idx_price_history_code_time ON price_history(stock_code, timestamp);
CREATE INDEX idx_orders_user_status ON orders(user_id, status);
CREATE INDEX idx_orders_stock_status ON orders(stock_code, status);
CREATE INDEX idx_positions_user ON positions(user_id);
CREATE INDEX idx_daily_snapshots_user ON daily_snapshots(user_id, created_at);
```

## 十八、错误处理规范

### 18.1 HTTP 错误码

| 状态码 | 场景 |
|--------|------|
| 200 | 成功（查询、更新） |
| 201 | 成功（创建） |
| 400 | 参数校验失败、业务规则违反 |
| 401 | 未认证或 token 过期 |
| 403 | 无权操作（如操作他人订单） |
| 404 | 资源不存在 |
| 500 | 服务端内部错误 |

### 18.2 错误响应格式

```json
{
  "error": "具体中文错误描述"
}
```

### 18.3 前端错误处理

- 401 → 自动跳转登录页
- 400 → 在对应表单字段下方显示错误信息
- 500 → Toast 提示「服务器繁忙，请稍后重试」
- 网络错误 → Toast 提示「网络连接异常」
