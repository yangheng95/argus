## Root cause

Prism's package migration preserved the generic frontend-design and Visual Quality Assurance
adapters but did not preserve one package-owned design-authority decision. Target screenshots,
competitor evidence, Product Requirements, and AInvest product/design authority all became generic
`source evidence`. The scheduler therefore had enough ambiguity to select `reference_parity`, after
which the shared adapter correctly required reference-comparison evidence and the Prism reviewer had
all formal region-comparison tools available.

The shared template is not the causal owner: it already supports original design and forbids
reference comparison in greenfield mode. The defect is responsibility inversion in the Prism
package. The package failed to declare that its current product algorithm is original synthesis and
allowed a runtime-template mode to choose the domain meaning.

The earlier “Prism Algorithm Stability Audit” corrected target-question coverage, provenance,
validation order, and idempotency. It did not calibrate the Product Requirements-to-design
authority transition. The later Planner refactor removed Requirements, Architect, Goal, and
Delivery Slice production but left stale Delivery Slice and architecture prose, proving that the
behavioral cutover was incomplete.

## Design

### Single Prism design authority

Prism always dispatches its page designer through `frontend_design` with
`mode=greenfield_original`. The accepted Prism Product Requirements, selected original design
direction, target team's approved design system, and optional AInvest mapper Artifact are the sole
design authority.

The evidence roles are:

- target evidence: product structure, route relationships, data shapes, interactions, states, and
  accessibility observations;
- competitor evidence: adopt/defer/reject product-pattern inspiration only;
- product/design authority: approved target-team or AInvest semantic tokens, component contracts,
  asset contracts, compliance, and brand boundary;
- rendered evidence: current Prism-authored screenshots used to review the original design itself.

None of these roles authorizes source-to-render visual parity inside Prism.

### Removed capability

Delete Prism projection and prompt use of:

- `prepare-visual-reference`;
- `browser_preview_compare_reference_regions`;
- `browser_preview_compare_scroll_slices`;
- `browser_preview_layout_geometry`;
- formal reference-region bindings and external screenshot parity claims.

Keep ordinary live Browser navigation, interaction, diagnostics, and screenshot tools because
original design still requires rendered visual review.

The source-capability contract keeps the original source inventory auditable, but records the
source designer's conditional high-fidelity restoration section under `unavailable` with an explicit
disposition: the capability is intentionally owned by Frontend Replica and is not implemented by
Prism.

### Downstream review

- Design review compares the rendered original design with its Product Requirements, selected
  original direction, design system, interactions, states, accessibility, and current screenshots.
- Code visual review compares implementation with the approved Prism-authored design.
- MirrorTest reviews the final product's visible behavior and quality.

No downstream reviewer may reconstruct an external parity obligation from target URLs, competitor
URLs, screenshots, filenames, region inventories, or source labels.
