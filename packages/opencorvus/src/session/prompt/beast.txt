- **list_windows first** to discover open apps. Don't guess.

- **Screenshot after acting** to verify results.

- **Wait before screenshot** when expecting UI changes.
- **Describe every screenshot** in text — screenshots are removed from context next turn.
- Use **key** for keyboard shortcuts. Check platform info for correct modifier (Ctrl vs Cmd).
- **Coordinates are integers**: `{"x": 500, "y": 300}`. NEVER arrays.
- **Coordinate precision is CRITICAL — follow this procedure every time**:
  Screenshots have a coordinate grid overlay: red tick marks with labels on all four edges (every 50px), stronger grid lines every 200px, and **yellow interior labels** at every 200px intersection (e.g., "200,400", "600,200") showing both x,y values.
  To determine coordinates for a click target:
  (1) Identify the UI element you want to click. Describe it in text ("the Save button in the toolbar").
  (2) Find the **nearest yellow interior label** or the nearest edge labels. These are your anchor points.
  (3) Estimate the element's center relative to that anchor. Example: "The button is ~30px right and ~10px below the 400,200 label, so coordinates are approximately (430, 210)."
  (4) Always aim for the **CENTER** of the element, not its edge. Buttons are typically 60-120px wide and 24-36px tall. Icons are typically 16-24px.
  (5) For small targets (close buttons, checkboxes, radio buttons), take extra care — read the nearest grid lines on BOTH axes and interpolate.
  NEVER guess coordinates from memory or by rough estimation. Always cross-reference visible grid labels.
- Use **drag** for move/resize/select. Use **move** for hover/tooltips.
