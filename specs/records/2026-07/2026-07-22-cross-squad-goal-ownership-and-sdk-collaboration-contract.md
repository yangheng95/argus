## Ownership model

| Entity                       | Sole responsibility                                                                                                                                                                    |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Task                         | The user's final outcome, authorization boundary, and one visible root session.                                                                                                        |
| Goal                         | One independently accepted delivery surface with durable dependencies and evidence. Cluster stages are Goals, not labels inferred from agent names.                                    |
| Expert Squad                 | A self-contained capability package that owns only its current Goal and local collaboration. It cannot encode or select another squad.                                                 |
| Agent                        | A role inside one active squad. Requirements and architect roles are planning owners, not implicit lifecycle stages or cross-squad Goals.                                              |
| Cluster Skill                | User-invoked coordination authority that establishes the task-wide Goal graph, passes visible evidence, and selects the next squad. It contains no domain implementation logic.        |
| SDK collaboration definition | Static authoring contract binding stage IDs to exact squad/workflow IDs, dependencies, evidence inputs/outputs, and repair owners. It validates package composition but never runs it. |

Domain squads consume the exact ready Goal and its prerequisite evidence through goal-scoped collaboration workflows. They do not replace the task spec or decompose the complete cluster request again.

## Follow-up protocol correction

1. `PromptProfileResolver` renders one generic invariant beside every active package graph: the scheduler visibly chooses the exact matching workflow before dispatch; every declared node must have terminal-success evidence; a dependent node cannot dispatch before all declared predecessors; only dependency-independent nodes may run concurrently; unavailable evidence causes visible refusal rather than skipping or reordering. This remains prompt-level semantic enforcement and creates no host gate or persisted workflow selection.
2. Conditional paths must be separate declared workflows. Mirror PRD has distinct standard and AInvest delivery graphs. MirrorTest has distinct non-visual and visual delivery graphs; the Mirror Prism acceptance graph is explicitly visual.
3. MirrorTest owns post-delivery test requirements, test architecture, test artifacts, execution, visual/integrity audit, release judgment, and test-owned repair. It may classify a failure as a product defect only far enough to provide reproducible evidence and route ownership. It must not investigate product root cause, edit product source, or present itself as a product debugger.
