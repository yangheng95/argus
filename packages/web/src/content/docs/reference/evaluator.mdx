---
title: Integrity Review
description: How OpenCorvus records verification evidence and completes tasks from final integrity attempts.
---

Per-goal build attempts publish durable evidence, and the task's final review is the `integrity` workflow tool. The current completion contract is artifact-backed: the orchestrator may complete a task only from the latest post-build `integrity_attempt`.

## Current Review Flow

1. **Build evidence** — direct and per-goal build work writes `run`, `goal_run_attempt`, changed-file, report, diff, and optional verification artifacts.
2. **Verification evidence** — browser preview targets, browser preview captures, runtime checks, screenshots, and visual evidence are stored as `engine_artifact` rows such as `verification-evidence`, `browser_preview_target`, and `browser_preview_evidence`.
3. **Visual QA** — `visual_qa` reviews visible product evidence when the task has a frontend-visible surface; it does not complete the task.
4. **Integrity review** — `integrity` reads the user request, requirements, architect contract graph, goal outputs, diffs, runtime/visual evidence, and previous attempts.
5. **Completion decision** — `manage_task action=complete_task` requires the current post-build `integrity_attempt` id. Non-pass evidence routes back to `dispatch_agent target=build`, `manage_task action=modify_goal`, `dispatch_agent target=architect`, a user question, or `manage_task action=fail_task`.

## Evidence Surfaces

| Surface                         | Current source                                              |
| ------------------------------- | ----------------------------------------------------------- |
| Verification evidence artifacts | `packages/opencorvus/src/engine/store.ts`                   |
| Browser preview target/evidence | `packages/opencorvus/src/tool/browser-preview.ts`           |
| Visual QA semantics             | `packages/opencorvus/src/visual-qa/acceptance-semantics.ts` |
| Integrity team review           | `packages/opencorvus/src/integrity/team-agent.ts`           |
| Integrity schemas               | `packages/opencorvus/src/integrity/team-schema.ts`          |
| Completion guard                | `packages/opencorvus/src/orchestrator/tools.ts`             |

## Artifact Records

The review path is reconstructed from current `engine_artifact` kinds, especially:

```typescript
"run"
"goal_run_attempt"
"verification-evidence"
"browser_preview_target"
"browser_preview_evidence"
"integrity_attempt"
```

Checks are audit evidence for operators and downstream review. They are not a replacement for the final `integrity_attempt` completion contract.

## Integrity Verdict Semantics

| Integrity outcome               | Orchestrator meaning                                                                                                                            |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| pass                            | The integrated system is acceptable for this task; the orchestrator may call `manage_task action=complete_task` with the latest post-build `integrity_attempt` id. |
| non-pass with blocking findings | The orchestrator must route repairs to `dispatch_agent target=build`, `manage_task action=modify_goal`, `dispatch_agent target=architect`, or a user question based on evidence. |
| thrown / artifact missing       | The orchestrator receives visible failure evidence and decides recovery; the UI should not silently show an empty card.                         |
