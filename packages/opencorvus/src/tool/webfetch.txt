DEPRECATED for visual / clone / layout work — use `webpage_extract` and the
rest of the `webpage_*` mirror pipeline whenever you want to render a URL,
analyze its layout, extract design tokens, or reproduce it as HTML. `webfetch`
returns flat text/markdown/html and throws away every structural signal the
mirror pipeline needs (DOM tree, per-element computed styles, reference
screenshot, asset manifest).

Use `webfetch` only for pure-text content where no visual or structural
analysis is needed: API documentation, README files, plain JSON / XML
endpoints, or text scraping. If you find yourself about to `webfetch` a URL
you then intend to clone, render, or style-match, stop and call
`webpage_extract` instead.

Usage notes:
  - If `webpage_extract` is available and the URL is a real webpage you want
    to inspect visually, prefer it over `webfetch`. Always.
  - Check the "Mirror Cache" section of your prompt before either tool — if
    the URL has already been captured this task, read the existing
    `extracted-page.json` / `page-ir.xml` / `scaffold.json` instead of
    re-fetching.
  - The URL must be a fully-formed valid URL (http/https).
  - Format options: "markdown" (default), "text", or "html".
  - This tool is read-only and does not modify any files.
  - Results may be summarized if the content is very large.
