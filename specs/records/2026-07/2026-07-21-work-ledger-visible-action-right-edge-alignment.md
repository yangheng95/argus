## Causal Chain

1. The visible Project and Task action rails appear on hover and already share the same trailing button centerline.
2. Project action glyphs inherit Icon's 14px standard tier, while every Work Ledger Task/Mission/Chat action glyph explicitly requests the 12px compact tier.
3. Equal centers with different SVG widths prevent one common visual scale. After the first correction unified the SVG boxes, screenshot pixel review exposed the deeper optical mismatch: Lucide Plus paints through x=19 while Archive paints through x=21 in their shared 24-unit viewBox.
4. The earlier regression measured button centers, and the first strengthened regression still measured only SVG rectangles, so both could pass while the user-visible painted paths remained misaligned.
5. The root repair is to use the existing standard Icon tier for all sibling Work Ledger action glyphs, apply the exact 2/24-viewBox optical delta only to the three trailing archive glyphs in the one Work Ledger style owner, and make the real-browser regression calculate painted path bounds with `getBBox()`.

## Codex Review Feedback

The first implementation draft correctly unified Project and Work Ledger action SVG size tiers, but its browser assertion compared only `getBoundingClientRect()` rectangles. Original-resolution screenshot review and direct pixel inspection showed Project Plus ending at x=248 while Task Archive still ended at x=250. That evidence disproved the assumption that equal SVG boxes imply equal painted edges. The plan was revised to account for the Lucide path-bound difference, the browser test now computes painted bounds with `getBBox()`, and the corrected screenshot reports both trailing painted edges at x=248.
