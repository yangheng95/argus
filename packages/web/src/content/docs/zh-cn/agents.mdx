OpenCorvus 的编排围绕 **agent** 构建。代理注册表（名称、模式、默认 prompt、工具白名单、权限规则集）位于 `packages/opencorvus/src/agent/agent.ts` 的 `Agent.state()`。

## 内置代理

当前注册表内置以下代理。`mode` 表示调用方式：`primary` 作为会话顶层 agent 运行；`subagent` 由其他 agent 通过 `task` 工具派发。`hidden` 表示路由槽——不会出现在选择器里，但模型 / prompt 仍可在 config 中覆盖。

| Agent          | 模式              | 角色                                                                                                                                                                                                         |
| -------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `coding`       | primary           | 普通本地会话的交互式 coding agent。                                                                                                                                                                          |
| `build`        | primary（hidden） | 实现 agent。由 orchestrator 或 direct workflow 派发后执行 read / edit / bash 类实现工具。                                                                                                                    |
| `visual-qa`    | primary（hidden） | 视觉 QA 阶段 agent，使用固定视觉证据工具面。                                                                                                                                                                 |
| `general`      | subagent          | 通用多步研究 / 并行工作 agent，由 `task` 工具派发。                                                                                                                                                          |
| `explore`      | subagent          | 代码库探索——快速文件 / 代码搜索，默认只读。                                                                                                                                                                  |
| `orchestrator` | primary（hidden） | 编排 agent。拥有任务生命周期决策权，并调用 `frontend_design`、`frontend_research`、`analyze_intent`、`requirements`、`architect`、`build`、`integrity`、`modify_goal`、`propose_task` 等显式 workflow 工具。 |
| `requirements` | primary（hidden） | 需求阶段。抽取用户需求和基础技术决策。                                                                                                                                                                       |

其他注册的代理（`architect`、`frontend-design`、`frontend-research`、`intent-analysis`、`integrity`、`fact-check`、`deep-research`、`goal-workload-analyst`、`summary`、`title`、`compaction`、`mission`、`control`）是由 orchestrator、mission runtime 或 session loop 内部调用的 stage / 工具槽。它们在 config 中可见（可覆盖 model、prompt），但除非有专门 runtime 暴露，否则不可用户选择。

权威定义见 `packages/opencorvus/src/agent/agent.ts`。

## 子代理派发

普通 session 通过 **`task`** 工具派发子代理；orchestrator 使用 `requirements`、`architect`、`build`、`integrity`、`frontend_design`、`frontend_research` 等专用工具。每次派发都会创建独立 worker session。

orchestrator 跑 `pipeline` 工作流时，Architect 创建 goals，每个 blocking goal 在独立 worktree 中由 `build` 实现，最终任务级复核由 `integrity` 完成。

## 按 agent 配置模型

每个 agent 的模型在 `agent.<name>.model` 下设置——见 `packages/opencorvus/src/config/config.ts`（`agent` 是 `z.object({...}).catchall(Agent)`）。相关 `assistant.<name>` 块在同一 config schema 中声明。

```jsonc
{
  "agent": {
    "build": { "model": "anthropic/claude-sonnet-4-6" },
    "frontend-design": { "model": "anthropic/claude-sonnet-4-6" },
  },
}
```

带连字符的 agent 名（`frontend-design`、`intent-analysis`）必须加引号。

## 自定义 Agent

可在 config 内联，或写成 markdown 放进 `~/.config/opencorvus/agents/`、`.opencorvus/agents/`：

```jsonc
{
  "agent": {
    "code-reviewer": {
      "description": "审查代码最佳实践与潜在问题",
      "model": "anthropic/claude-sonnet-4-6",
      "prompt": "你是代码评审者。关注安全、性能、可维护性。",
      "tools": { "write": false, "edit": false },
    },
  },
}
```

自定义 agent 继承默认权限规则集（在 `agent.ts` 的 `defaults` 块构建）。

## 默认 Agent

`default_agent` 指定无显式选择时使用的 agent，必须是 primary 且非 hidden——`Agent.defaultAgent()`（`agent.ts`）会拒绝 subagent / hidden 选项。

## Agent 预算

各 agent 的 step 预算 / skill 路径在 `assistant.<name>` 下（config.ts）：

```jsonc
{
  "assistant": {
    "requirements": { "max_steps": 20 },
    "architect": { "max_steps": 40 },
    "frontend_design": { "max_steps": 30 },
    "intent_analysis": { "max_steps": 10 },
    "build": { "max_steps": 80 },
    "integrity": { "max_steps": 160 },
  },
}
```

orchestrator 顶层预算直接挂在 `assistant` 下（config.ts）：

- `assistant.max_runs` — 任务总 run 上限
- `assistant.max_fix_runs` — 失败后修复 run 上限
- `assistant.max_executor_groups` — 并行 executor group 上限

这些是硬上限，防止失控循环。详见 [config](/docs/zh-cn/config/)。
