## 是什么

编码代理（coding agent）擅长写代码，但单次输出**不可靠**：没有规格、没有验收、没有重试、没有状态。

OpenCorvus 把「一次性的代码生成」包装成**可重复、可验收、可自愈的研发工作流**。你给一个任务，orchestrator 会在 direct build 与 pipeline workflow 之间选择：按需做 research/design、intent analysis、requirements、architecture、per-goal build 与 integrity review。

## 核心能力

| 能力             | 说明                                                                                           |
| ---------------- | ---------------------------------------------------------------------------------------------- |
| **需求抽取**     | Requirements agent 把模糊请求转成可测试的需求与基础决策                                        |
| **架构分解**     | Architect agent 把需求转成可独立实现的 goals、acceptance specs 与依赖契约                      |
| **多执行器调度** | 内置 OpenCorvus，可自动发现并调度 Codex / Claude Code                                          |
| **完整性复核**   | build evidence、specialist checks、visual/runtime evidence 与 LLM review 由 integrity 阶段汇总 |
| **多通道接入**   | HTTP API、Overlay 桌面端、14 个 IM channel                                                     |
| **状态持久化**   | 任务、需求、计划、goal、run、artifact、交互、acceptance 与 evaluation 全部落 SQLite            |
| **人工参与**     | 权限 ask/allow/deny、follow-up 消息、手动反馈，均可在无人值守流程中无缝嵌入                    |

## 三层架构

```
┌─ Channel 层 ─────────────────────────────────────────────┐
│  Overlay UI / HTTP API / 14 个 IM channel                │
├─ Orchestrator 层 ────────────────────────────────────────┤
│  Orchestrator → workflow tools → per-goal build → review │
│  （SQLite 持久化 + permission + 预算 + artifacts）       │
├─ Executor 层 ────────────────────────────────────────────┤
│  OpenCorvus 内核 / Codex / Claude Code                   │
└──────────────────────────────────────────────────────────┘
```

## 快速上手

```bash
curl -fsSL https://github.com/yangheng95/argus/releases/latest/download/install.sh | bash
cd /path/to/your/repo
opencorvus serve
# 打开 http://127.0.0.1:7878/ui/
```
