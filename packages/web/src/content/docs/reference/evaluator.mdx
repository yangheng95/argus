---
title: Integrity and Evaluation
description: How OpenCorvus records verification evidence and performs final integrity review.
---

Per-goal build attempts produce verification evidence, and the pipeline's final review is the `integrity` workflow tool.

## Current Review Flow

1. **Build evidence** — every direct build or per-goal build writes run and goal-run artifacts, changed files, reports, and optional verification evidence.
2. **Acceptance/evaluation artifacts** — `engine_artifact` rows with `kind="acceptance"` and `kind="verification-evidence"` preserve acceptance and check evidence for replay.
3. **Integrity review** — the integrity agent reads the user request, requirements, architect contract graph, goal outputs, diffs, runtime/visual evidence, previous attempts, and acceptance evidence.
4. **Orchestrator decision** — integrity returns pass or non-pass evidence. The orchestrator decides whether to complete, modify goals, re-run build, re-enter architect, ask the user, or fail the task.

## Evaluation Row Shape

`EvaluationRow` is reconstructed from `engine_artifact.kind="verification-evidence"`:

```typescript
type EvaluationRow = {
  scope: "goal_run" | "acceptance"
  status: "pending" | "passed" | "failed" | "inconclusive"
  verdict: "accepted" | "rejected" | "inconclusive"
  checks: EngineEvaluationCheck[] | null
}
```

Checks are audit evidence for operators and downstream review.

## Integrity Verdict Semantics

| Integrity outcome | Orchestrator meaning |
|---|---|
| pass | The integrated system is acceptable for this task; the orchestrator may complete the task. |
| non-pass with blocking findings | The orchestrator must route repairs to build, `modify_goal`, `architect`, or a user question based on evidence. |
| thrown / artifact missing | The orchestrator receives visible failure evidence and decides recovery; the UI should not silently show an empty card. |

## Configuration Notes

Agent models and step budgets are configured under `agent.integrity.*` and `assistant.integrity.*`. Visual acceptance thresholds live under `assistant.acceptance_visual` in the engine config.
