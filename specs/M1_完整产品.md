### 3.2 SandboxService 实现

```typescript
// src/services/executor/sandbox.ts

export class SandboxService implements IExecutorService {
  private baseUrl: string
  private abortController: AbortController | null = null

  constructor(sandboxUrl: string) {
    this.baseUrl = sandboxUrl  // 默认 'http://localhost:8001'
  }

  async execute(params: {
    code: string; language: 'python' | 'sql' | 'r'; sessionId: string
  }): Promise<ExecutionResult> {
    // 1. 取消上一次未完成的请求
    this.abortController?.abort()
    this.abortController = new AbortController()

    const startTime = Date.now()
    try {
      // 2. POST 到沙箱服务
      const resp = await fetch(`${this.baseUrl}/execute`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          code: params.code,
          language: params.language,
          session_id: params.sessionId,
          timeout_seconds: 30,
        }),
        signal: this.abortController.signal,
      })
      const data = await resp.json()
      const durationMs = Date.now() - startTime

      // 3. 解析图表
      const charts = (data.figures ?? []).map((fig: any, i: number) => ({
        id: `chart-${i}`,
        spec: fig.plotly_json ? JSON.parse(fig.plotly_json) : {},
        imageDataUrl: fig.png_base64 ? `data:image/png;base64,${fig.png_base64}` : undefined,
      }))

      // 4. 错误格式化
      if (data.status === 'error') {
        return {
          status: 'error',
          stdout: data.stdout ?? '',
          stderr: this.formatError(data.stderr ?? data.error ?? ''),
          charts: [],
          durationMs,
        }
      }

      return {
        status: data.status === 'timeout' ? 'timeout' : 'ok',
        stdout: data.stdout ?? '',
        stderr: data.stderr ?? '',
        charts,
        durationMs,
      }
    } catch (err) {
      const durationMs = Date.now() - startTime
      if (err instanceof DOMException && err.name === 'AbortError') {
        return { status: 'error', stdout: '', stderr: '执行已取消', charts: [], durationMs }
      }
      return { status: 'error', stdout: '', stderr: '无法连接沙箱服务，代码已复制到剪贴板', charts: [], durationMs }
    }
  }

  private formatError(raw: string): string {
    if (raw.includes('KeyError'))   return `变量未定义：${raw.match(/KeyError: '?(.+?)'?$/m)?.[1] ?? '未知'}，请检查数据字段名`
    if (raw.includes('NameError'))  return `名称未定义：${raw.match(/NameError: name '(.+?)'/)?.[1] ?? '未知'}`
    if (raw.includes('ImportError'))return `模块未安装：请使用预装库（pandas/numpy/plotly）`
    if (raw.includes('TimeoutError') || raw.includes('timed out')) return '执行超时（>30s），代码中可能存在无限循环'
    return raw  // 其他错误保留原文
  }

  abort(): void {
    this.abortController?.abort()
  }
}
```

**formatError 规则**：

| Python 错误类型 | 用户提示 |
|---|---|
| KeyError | "变量 'xxx' 未定义，请检查数据字段名" |
| NameError | "变量 'xxx' 未定义，请检查拼写或是否已导入" |
| ImportError / ModuleNotFoundError | "模块 'xxx' 未安装，请使用预装库" |
| 其他 | 原始 traceback |

所有错误提示后附加原始 stderr，供调试使用。

**SandboxRawResponse 类型**：

```typescript
interface SandboxRawResponse {
  status: 'ok' | 'error' | 'timeout'
  stdout?: string
  stderr?: string
  error_type?: string        // Python 异常类名
  figures?: Array<{
    plotly_json?: string     // Plotly Figure JSON string
    png_base64?: string      // Matplotlib PNG base64
  }>
}
```

### 3.3 沙箱 HTTP API 规格

**端点**：`POST /execute`

**请求体**：

```json
{
  "code": "import pandas as pd\nprint('hello')",
  "language": "python",
  "session_id": "sess_abc123",
  "timeout_seconds": 30
}
```

**响应体**：

```json
{
  "status": "ok",
  "stdout": "hello\n",
  "stderr": "",
  "figures": [
    {
      "plotly_json": "{\"data\":[...],\"layout\":{...}}",
      "png_base64": null
    }
  ]
}
```

**图表捕获机制**：

沙箱内部的 Python 执行环境通过以下方式捕获图表对象：

1. 劫持 `plotly.io.show` 和 `matplotlib.pyplot.show`，不打开浏览器窗口，而是将 Figure 序列化
2. Plotly Figure → `fig.to_json()` → 存入 `figures[].plotly_json`
3. Matplotlib Figure → `savefig(BytesIO, format='png')` → base64 编码 → 存入 `figures[].png_base64`
4. 执行结束后收集所有捕获的 Figure 对象，放入响应的 `figures` 数组

**状态码**：

| HTTP 状态码 | 含义 |
|---|---|
| 200 | 执行完成（不管是 ok / error / timeout，都返回 200，通过 body.status 区分）|
| 400 | 请求体格式错误（缺少 code 字段等）|
| 503 | 沙箱服务过载（所有 worker 都在忙）|

#### 3.4.2 沙箱服务器（sandbox_server.py）

核心逻辑：

1. **HTTP Handler**：监听 8001 端口，处理 `POST /execute` 请求
2. **子进程隔离**：使用 `multiprocessing.Process` 执行用户代码，通过 `Manager().dict()` 传递结果
3. **超时控制**：`proc.join(timeout=N)` 等待，超时后 `terminate()` → `kill()` 两段式清理
4. **stdout/stderr 捕获**：重定向 `sys.stdout/stderr` 到 `StringIO`，执行后收集
5. **Figure 捕获**：执行前调用 `install_figure_hooks()`，执行后调用 `collect_figures()`

配置常量：

| 常量 | 值 | 说明 |
|---|---|---|
| `MAX_TIMEOUT` | 30s | 最大允许超时 |
| `MAX_CODE_LENGTH` | 50000 字符 | 最大代码长度 |
| `MAX_STDOUT` | 100000 字符 | stdout 最大捕获长度 |
| `LISTEN_PORT` | 8001 | 监听端口 |

#### 3.4.3 Figure 捕获模块（figure_capture.py）

提供三个函数：

- `install_figure_hooks()`：在代码执行前调用，劫持 `plotly.io.show` 和 `matplotlib.pyplot.show`
- `collect_figures()`：执行结束后调用，返回所有捕获的 Figure

捕获逻辑：

- **Plotly**：劫持 `pio.show` 和 `go.Figure.show`，调用 `fig.to_json()` 序列化 → 存入 `plotly_json`
- **Matplotlib**：劫持 `plt.show`，遍历所有 Figure，`savefig(BytesIO, format='png', dpi=150)` → base64 编码 → 存入 `png_base64`，最后 `plt.close('all')`

## 5. M08：上下文记忆引擎

### 5.1 模块定位

在多轮对话中追踪用户当前讨论的标的、时间窗口、查询类型等上下文变量，使用户无需每轮重复说明。通过 system prompt 注入的方式实现指代消解，不依赖独立的 NLP 管道。

**核心交付**：
- `context.store`（Zustand store）
- `updateFromToolCall`：工具调用后自动更新上下文
- `updateFromMessage`：用户消息前提取实体更新上下文
- `buildSystemPromptAppendix`：将上下文拼入 system prompt
- 上下文切换规则（新标的替换、新时间段更新、新建会话清空）

**不在 M1 范围**：
- 会话摘要（长会话压缩）→ 推迟到 M1.5 或阶段 2
- `context.history`（上下文快照与撤销）→ 接口保留，实现推迟

### 5.2 context.store 完整实现

```typescript
// src/stores/context.store.ts

import { create } from 'zustand'

// ── 类型定义 ──────────────────────────────────────────────────────

export interface AnalysisContext {
  /** 当前讨论的股票代码列表（最多 5 个） */
  tickers: string[]
  /** 当前时间范围 */
  dateRange?: { start: string; end: string }
  /** 最近使用的财报期，如 '2024-Q3' */
  reportPeriod?: string
  /** 上次查询类型 */
  lastQueryType?: 'financial' | 'market'
  /** 上次查询的字段列表 */
  lastFields?: string[]
}

/**
 * 从用户消息中解析出的实体。
 * 由 useEntityParser hook 提供。
 */
export interface ParsedEntities {
  /** 解析出的股票代码 */
  tickers?: string[]
  /** 解析出的时间范围 */
  dateRange?: { start: string; end: string }
  /** 解析出的财报期 */
  reportPeriod?: string
  /** 是否为并列提及（"还有"、"以及"、"和"等） */
  isAdditive?: boolean
  /** 是否明确要求切换标的（"换一只"、"看别的"等） */
  isClearTickers?: boolean
}

interface ContextState {
  /** 当前分析上下文 */
  current: AnalysisContext

  /** 上下文快照历史（最近 10 次，M1 保留接口，实现推迟） */
  history: AnalysisContext[]

  /** 工具调用完成后更新上下文 */
  updateFromToolCall: (toolName: string, params: Record<string, unknown>) => void

  /** 用户消息发送前，根据实体解析结果更新上下文 */
  updateFromMessage: (parsed: ParsedEntities) => void

  /** 将当前上下文构建为 system prompt 追加文本 */
  buildSystemPromptAppendix: () => string

  /** 清空上下文（新建会话时调用） */
  reset: () => void
}

// ── 初始状态 ──────────────────────────────────────────────────────

const EMPTY_CONTEXT: AnalysisContext = {
  tickers: [],
  dateRange: undefined,
  reportPeriod: undefined,
  lastQueryType: undefined,
  lastFields: undefined,
}

// ── 股票代码 → 中文名映射（在 M02 实体解析中维护，此处引用） ────
// 用于 buildSystemPromptAppendix 中显示中文名。
// 实际实现从 M02 的 tickerNameMap 中读取。
import { getTickerName } from '../services/intent/entity-parser'

// ── Store 实现 ───────────────────────────────────────────────────

export const useContextStore = create<ContextState>((set, get) => ({
  current: { ...EMPTY_CONTEXT },
  history: [],

  updateFromToolCall: (toolName: string, params: Record<string, unknown>) => {
    set(state => {
      const next = { ...state.current }

      switch (toolName) {
        case 'get_financial_report': {
          // 更新 tickers
          const tickers = params.tickers
          if (Array.isArray(tickers) && tickers.length > 0) {
            next.tickers = tickers.slice(0, 5) as string[]
          }
          // 更新 dateRange
          if (typeof params.startDate === 'string' && typeof params.endDate === 'string') {
            next.dateRange = { start: params.startDate, end: params.endDate }
          }
          // 更新 lastFields
          if (Array.isArray(params.fields)) {
            next.lastFields = params.fields as string[]
          }
          // 更新查询类型
          next.lastQueryType = 'financial'
          // 更新财报期（从返回数据中提取最新期）
          if (typeof params.period === 'string') {
            next.reportPeriod = params.period
          }
          break
        }

        case 'get_market_data':
        case 'get_ohlcv': {
          // 更新 tickers
          const ticker = params.ticker
          if (typeof ticker === 'string') {
            next.tickers = [ticker]
          }
          // 更新 dateRange
          if (typeof params.startDate === 'string' && typeof params.endDate === 'string') {
            next.dateRange = { start: params.startDate, end: params.endDate }
          }
          // 更新查询类型
          next.lastQueryType = 'market'
          break
        }

        case 'get_index_components': {
          // 指数成分股查询不更新 tickers（查的是指数，不是个股）
          break
        }

        default:
          // 未知工具不更新上下文
          break
      }

      return {
        current: next,
        // history: 快照推迟实现
        // history: [...state.history, state.current].slice(-10),
      }
    })
  },

  updateFromMessage: (parsed: ParsedEntities) => {
    set(state => {
      const next = { ...state.current }

      // ── 标的更新逻辑 ──────────────────────────────────────

      // 用户明确说"换一只"、"看别的"
      if (parsed.isClearTickers) {
        next.tickers = []
      }
      // 用户提及新标的
      else if (parsed.tickers && parsed.tickers.length > 0) {
        if (parsed.isAdditive) {
          // 并列词（"还有"、"以及"）：追加到已有列表
          const merged = [...next.tickers, ...parsed.tickers]
          // 去重，保留最多 5 个
          next.tickers = [...new Set(merged)].slice(0, 5)
        } else {
          // 非并列：替换为新标的
          next.tickers = parsed.tickers.slice(0, 5)
        }
      }

      // ── 时间范围更新 ──────────────────────────────────────
      if (parsed.dateRange) {
        next.dateRange = parsed.dateRange
      }

      // ── 财报期更新 ────────────────────────────────────────
      if (parsed.reportPeriod) {
        next.reportPeriod = parsed.reportPeriod
      }

      return { current: next }
    })
  },

  buildSystemPromptAppendix: () => {
    const ctx = get().current

    // 如果上下文完全为空，不追加任何内容
    if (ctx.tickers.length === 0 && !ctx.dateRange && !ctx.lastQueryType) {
      return ''
    }

    const lines: string[] = ['', '当前分析上下文：']

    // ── 当前标的 ────────────────────────────────────────────
    if (ctx.tickers.length > 0) {
      const tickerDescs = ctx.tickers.map(t => {
        const name = getTickerName(t)
        return name ? `${name}（${t}）` : t
      })
      lines.push(`- 当前标的：${tickerDescs.join('、')}`)
    }

    // ── 时间范围 ────────────────────────────────────────────
    if (ctx.dateRange) {
      lines.push(`- 时间范围：${ctx.dateRange.start} ~ ${ctx.dateRange.end}`)
    }

    // ── 财报期 ──────────────────────────────────────────────
    if (ctx.reportPeriod) {
      lines.push(`- 最近财报期：${ctx.reportPeriod}`)
    }

    // ── 上次查询类型 ────────────────────────────────────────
    if (ctx.lastQueryType) {
      const typeLabel = ctx.lastQueryType === 'financial' ? '财务数据' : '行情数据'
      lines.push(`- 上次查询类型：${typeLabel}`)
    }

    // ── 上次查询字段 ────────────────────────────────────────
    if (ctx.lastFields && ctx.lastFields.length > 0) {
      lines.push(`- 上次查询字段：${ctx.lastFields.join(', ')}`)
    }

    lines.push('')
    lines.push('用户后续提问中如果出现"它"、"这只股票"、"该公司"等指代词，请根据上述上下文推断指代对象，无需追问。')
    lines.push('如果用户没有指定时间范围，使用上述时间范围作为默认值。')

    return lines.join('\n')
  },

  reset: () => {
    set({
      current: { ...EMPTY_CONTEXT },
      history: [],
    })
  },
}))
```

### 5.3 LLM 调用集成

上下文注入发生在三个时点：

**5.3.1 用户消息发送前**（`src/hooks/useChat.ts` 的 `sendMessage`）：

1. `parseEntities(userMessage)` → 提取实体
2. `useContextStore.getState().updateFromMessage(parsed)` → 更新上下文
3. `useContextStore.getState().buildSystemPromptAppendix()` → 构建追加文本
4. `BASE_SYSTEM_PROMPT + contextAppendix` → 拼入 system prompt
5. 调用 LLM

**5.3.2 工具调用完成后**（`src/hooks/useToolExecution.ts` 的 `handleToolCall`）：

1. 执行工具调用
2. `useContextStore.getState().updateFromToolCall(toolCall.name, toolCall.parameters)` → 更新上下文
3. 将结果传回 LLM

**5.3.3 新建会话时**（`src/stores/session.store.ts` 的 `createSession`）：

调用 `useContextStore.getState().reset()` 清空上下文。

### 5.4 实体解析规则

`parseEntities` 函数负责从用户自然语言消息中提取实体。此函数在 M02（意图路由）中已有基础实现，M1 阶段扩展以下能力：

```typescript
// src/services/intent/entity-parser.ts（M1 扩展部分）

export interface ParsedEntities {
  tickers?: string[]
  dateRange?: { start: string; end: string }
  reportPeriod?: string
  isAdditive?: boolean        // "还有"、"以及"等并列词
  isClearTickers?: boolean    // "换一只"、"看别的"等
}

export function parseEntities(message: string): ParsedEntities
export function getTickerName(code: string): string | undefined
```

**标的解析逻辑**：

1. 检查 CLEAR_PATTERNS（`/换一只|看别的|换个|切换到|不看.*了/`）→ `isClearTickers = true`
2. 检查 ADDITIVE_PATTERNS（`/还有|以及|再加上|另外|和|跟|同时/`）→ `isAdditive = true`
3. 在 TICKER_MAP 中匹配公司名（茅台→600519.SH、宁德时代→300750.SZ 等，初始覆盖 M05 的 5 只 + 常见蓝筹）
4. 正则匹配直接的股票代码（`/(\d{6})(?:\.(SH|SZ))?/g`，6 开头默认 .SH，其余默认 .SZ）

**时间范围解析逻辑**（按优先级匹配，首个匹配即停止）：

| 模式 | 示例 | 转换 |
|---|---|---|
| `最近 N 个交易日/天/月/年` | "最近30个交易日" | 交易日按 ×1.5 粗略估算自然日 |
| `过去/近 N 年`（支持中文数字） | "过去三年" | `start = now - N years` |
| `YYYY年`（单个） | "用2023年的数据" | `2023-01-01 ~ 2023-12-31` |
| `YYYY年`（两个） | "2021年到2024年" | `sorted[0]-01-01 ~ sorted[-1]-12-31` |
| `YYYY.MM–YYYY.MM` | "2015.06–2015.09" | 解析为对应月份范围 |

**财报期解析**：匹配 `YYYY年N季报` 或 `YYYYQN` → `YYYY-QN`。"最新一期"不设值，让工具自动使用最新。

| 场景 | 用户输入示例 | 上下文变更 |

### 6.2 规则注入机制

```typescript
// src/constants/quant-knowledge.ts

/**
 * 量化因子常见陷阱规则集。
 * 
 * 注入时机：当 M02 意图路由识别到"代码调试"或"因子分析"意图时，
 * 将规则集追加到 system prompt 中。
 * 
 * 注入方式：纯文本追加到 BASE_SYSTEM_PROMPT 末尾。
 * 不是独立服务，不走 RAG。
 */
export const QUANT_KNOWLEDGE_RULES = buildQuantKnowledgePrompt()

function buildQuantKnowledgePrompt(): string {
  return `
你是一位资深的量化研究审查专家。当用户提交代码让你审查时，请根据以下规则检查常见问题。
每条规则包含：规则编号、问题类别、具体描述、检测方法、修复建议。

如果发现问题，请：
1. 指出具体代码行
2. 说明属于哪条规则
3. 给出修复后的代码

──────────────────────────────────────────────────────────────────

${RULES.map(r => formatRule(r)).join('\n\n')}

──────────────────────────────────────────────────────────────────
`
}

interface QuantRule {
  id: string
  category: string
  title: string
  description: string
  detection: string
  fix: string
}

function formatRule(r: QuantRule): string {
  return `【${r.id}】${r.category} — ${r.title}
  问题：${r.description}
  检测：${r.detection}
  修复：${r.fix}`
}

const RULES: QuantRule[] = [
```

## 8. 验证检查点

### 8.1 场景级检查点

#### CP-01：S02 因子调试场景用真实 LLM 走通，能识别 look-ahead bias

**输入**：
```python
# 用户提交的代码
import pandas as pd
df = pd.DataFrame({
    'date': pd.date_range('2023-01-01', periods=250, freq='B'),
    'close': [100 + i * 0.1 + (i % 7) * 0.5 for i in range(250)]
})
df['signal'] = df['close'].pct_change()  # 当天收益率作为当天信号
df['position'] = (df['signal'] > 0).astype(int)
df['strategy_return'] = df['position'] * df['close'].pct_change()
print(f"年化收益率: {df['strategy_return'].mean() * 252:.2%}")
```

**期望输出**：LLM 识别出 QR-01（前视偏差），指出 `df['signal'] = df['close'].pct_change()` 在 t 日使用了 t 日的收盘价变动作为信号，而实际上 t 日信号只能在 t+1 日执行。建议修改为 `df['signal'] = df['close'].pct_change().shift(1)`。

**判定标准**：LLM 回复中明确提到"前视偏差"或"look-ahead bias"，并给出 shift(1) 的修复方案。

#### CP-02：S03 封装查询场景返回真实行情数据

**输入**："给我看一下最近 30 个交易日沪深 300 成分股的平均换手率。"

**期望输出**：
1. 工具调用 `getOHLCV(ticker='000300.SH', ...)` 返回真实数据
2. 数据时间范围覆盖最近 30 个交易日
3. 返回的 OHLCVBar 中 `turnover` 字段有值
4. 生成的封装函数参数化了时间窗口和指数代码

**判定标准**：`getOHLCV` 返回的数据日期连续、价格合理（沪深 300 在 3000–5000 点范围内）。

#### CP-03：S04 压力测试场景代码在沙箱中真实执行并返回结果

**输入**："用 2015 年 6 月到 9 月的数据，计算一下等权持有茅台和招行的最大回撤。"

**期望输出**：
1. 工具调用 `getOHLCV` 获取 600519.SH 和 600036.SH 的 2015-06 至 2015-09 行情
2. 生成最大回撤计算代码
3. 用户点击运行后，代码在沙箱中执行
4. 返回 stdout 包含最大回撤数值
5. 返回图表（回撤曲线）

**判定标准**：
- 代码执行 status 为 ok
- 最大回撤数值在合理范围内（2015 年股灾期间，茅台+招行组合回撤约 30%–50%）
- 图表在 `ChartRenderer` 中正确渲染

#### CP-04：多轮对话上下文保持

## 附录 C：术语定义

继承骨架 PRD 第七章词汇表，M1 新增以下术语：

| 术语 | 定义 |
|---|---|
| **沙箱服务（Sandbox Service）** | 运行在 Docker 容器中的 Python 代码执行服务，通过 HTTP API 接收代码并返回执行结果 |
| **Figure 捕获（Figure Capture）** | 劫持 plotly/matplotlib 的 show() 函数，将图表对象序列化而非打开浏览器窗口 |
| **分析上下文（Analysis Context）** | 当前会话中追踪的变量集合（标的、时间范围、查询类型等），用于指代消解 |
| **指代消解（Coreference Resolution）** | 将"它"、"该公司"等代词解析为具体实体的过程 |
| **因子陷阱（Factor Pitfall）** | 量化因子开发中的常见错误，如前视偏差、存活偏差等 |
| **前复权（Forward Adjusted）** | 以最新价格为基准，将历史价格按除权因子向前调整，确保价格序列连续 |
| **ICIR（Information Coefficient Information Ratio）** | IC 均值除以 IC 标准差，衡量因子选股能力的稳定性 |
