Diagnose by symptom. Each entry gives a **check path**, not "try restarting".

## Startup

### `opencorvus serve` fails to start

| Check | Detail |
|---|---|
| `opencorvus doctor` | Run the full diagnostic first |
| Port in use | Default 7878; `netstat -ano \| findstr 7878` on Windows |
| `OPENCORVUS_SERVER_PASSWORD` | Required when exposing beyond localhost; otherwise startup rejects with `refuses to expose without password` |
| `ENOSPC` | `~/.opencorvus` disk is full |

### Overlay launches but can't reach the backend

1. Tray → Restart (restarts backend + reloads frontend)
2. Inspect `~/.opencorvus/overlay.log`
3. Probe manually: `GET http://127.0.0.1:<port>/global/health`
4. Set `OPENCORVUS_OVERLAY_SINGLETON_MODE=kill-old-start-new` to clear stale backends

## Provider / model

### Executor returns empty responses

Root cause almost always: **missing provider API key**. Because `Env.state()` snapshots on instance creation:

1. `.env` not loaded → inject explicitly: `DASHSCOPE_API_KEY=sk-... opencorvus serve`
2. Wrong provider key — `alibaba-cn` uses `DASHSCOPE_API_KEY`; `anthropic` uses `ANTHROPIC_API_KEY`
3. Gateway picks wrong model — Gateway does **not** read `OPENCORVUS_BENCHMARK_MODEL`; set `cfg.model` in [config](/docs/config/)

### Alibaba API hangs for 20+ minutes

`alibaba-coding-plan-cn` is known to hang during peak hours. **Do not** mask by raising stall timeouts:

- Use `--tool-timeout-ms=30000` to fail fast
- Or switch [providers](/docs/providers/)

## Orchestrator

### Stuck before build or review

| Symptom | Check |
|---|---|
| No events at all | LLM provider connectivity |
| Reasoning tokens but no tool-call | Reasoning models must use `toolChoice: "auto"` |
| Worker session quiet for long | Inspect the latest orchestrator event and the active workflow tool (`requirements`, `architect`, `build`, or `integrity`). Tune the decision inactivity timeout only after provider connectivity is confirmed. |

### Task repeats repair cycles

Usually the latest integrity or review evidence does not identify a concrete repair. Check:

1. Requirements or acceptance specs lack concrete criteria
2. Architect goals lack runnable, evidence-backed acceptance checks
3. `max_runs` too large — default 3; larger values just burn budget

### Permission ask never resolves

| Check | Detail |
|---|---|
| Does config explicitly set `ask` | Built-in agent permissions default to `allow`; only explicit `ask` rules wait for an operator reply. |
| `OPENCORVUS_PERMISSION_TIMEOUT_MS` | Reject timeout for unanswered asks, default `300000` ms (`src/permission/next.ts`). Minimum honored value is `1000` ms. |

See [Permissions](/docs/permissions/).

## Evaluation

### Benchmark shows "accepted" but the artifact doesn't run

Classic symptom: review evidence was incomplete or local verification was skipped. Check:

1. Merge log for `EEXIST` / conflict
2. Integrity evidence includes runtime readiness, build, and startup checks where relevant
3. The benchmark report includes `localVerify.exitCode` and required check pass-rate evidence

### TypeScript errors undetected

Ensure integrity or local verification includes lint/typecheck evidence for TypeScript projects.

## Channels

### Slack message processed twice

Both `opencorvus slack` and `channel-runtime` are subscribing. **Run only one.**

### Webhook validation fails (Feishu / DingTalk / WeCom / LINE)

Signature algorithms differ per vendor. Double-check env matches the platform literally, including **newlines** (especially in Google Chat's service account JSON).

### Reply lands in the wrong thread

`SessionCoordinator` thread key = `platform:channel:thread_ts`. Wrong routing usually means an adapter dropped `thread_id`. Check the adapter's `onMessage` to ensure it propagates `thread_id` onto `IncomingMessage`.

## Tool issues

### git commands misbehave

:::tip
Per the project rules: **fix the tool first, then continue the task**.
:::

- `git worktree` errors: `git worktree prune`
- On Windows, use Git for Windows' bash; avoid MSYS2's.

### `rg` / Grep unavailable

Reinstall ripgrep; on Windows, Bun may fail to discover `rg` via PATH — use an absolute path.
