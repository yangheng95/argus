## Root cause and decision

The current manifests allow most reviewer identities to use `disjoint_goals`. That capability permits multiple sessions of the same projected reviewer to review disjoint Goals concurrently. The global `assistant.max_executor_groups` default is not the right control: lowering it would serialize researchers, implementers, and every other projected agent as collateral behavior.

The direct correction is therefore declarative and package-owned: reviewer identities use `goal_concurrency: "single"`. The existing resolver and execution-lease path already consumes this field, so no host-side scheduling rule is needed. Multiple reviewer specializations may still exist in a squad, but each reviewer identity has at most one active Goal session; this preserves visual-versus-integrity responsibility boundaries without creating multiple copies of one reviewer.
