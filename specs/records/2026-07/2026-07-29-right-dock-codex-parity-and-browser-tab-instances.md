## Causal chain

1. `RightDock.openBlankBrowserTabFromStrip` already receives exact-background
   double-clicks, so the missing behavior is not an absent DOM listener.
2. The handler calls `props.onOpen("browser")`. `main.tsx` stores open panels as
   a unique `CenterWorkbenchPanel[]`, removes any existing equal value, and
   appends the same `"browser"` identity.
3. `BrowserPreviewPanel` also hard-codes the native lease ID
   `"right-dock-browser"`. A second Browser trigger would therefore still share
   the same UI identity and native surface identity.
4. The visible symptom is consequently caused by a single-instance panel model
   being used for a multi-instance browser concept. Widening the click target or
   adding another boolean cannot fix it.
5. The root repair is one ordered workbench-tab collection whose entries carry
   stable instance IDs and panel kinds. Fixed tools use their kind as their one
   instance ID; blank Browsers receive new IDs. Selection remains the last
   entry, and the same ID is passed through Kobalte and the native WebView lease.
